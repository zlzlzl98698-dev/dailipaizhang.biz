# 联盟推广与商业合作披露（Disclosure）

> **核心结论（Answer-First）**：**代理排障（dailipaizhang.biz）** 包含部分服务商的联盟推广（Affiliate）合作链接，这是维持网站长期更新与独立排障文档建设的收入来源之一。为确保读者知情权与内容可信度，本站实行三项硬性透明制度：**所有推广注册链接统一由中心数据层输出并强制标注 `rel="nofollow sponsored noopener noreferrer"`**；**绝不将带有 `aff` 追踪参数的推广跳转地址冒充为品牌主站官网**；**商业展示优先级与技术排障、数据证据分级严格隔离**。

## 一、所有 `aff` 注册链接的来源与管理机制

1. **统一来源与禁止正文中随意硬编码**：
   - 站内涉及的品牌推广注册链接全部来源于整理收录的品牌合作/渠道资料，并集中存放在站内结构化数据与统一链接出口模块（`data/brands.json` 与 `data/links.ts`）中，通过 `<AffiliateCta />` 组件统一渲染。
   - 任何 Markdown 正文与排障文章不得绕过统一组件私自夹带未披露或来源不明的跳转链接。
2. **明确区分“推广链接”与“品牌官网”**：
   - 带有 `aff` 域名特征或 `#/?code=...` 邀请参数的地址仅代表**渠道注册入口**，而非品牌独立主站网址。
   - 在尚未对服务商主站域名完成独立核验前，本站对应品牌的官网字段统一标记为 **`待核实`**，并在 [官网与入口核验专题](/brands/official-sites/) 中公开记录发现的链接格式异常或版本冲突（例如部分记录中缺少 `#` 或邀请码在不同资料表格里不一致的情况）。

## 二、`nofollow sponsored` 策略与链接属性规范

遵循搜索引擎规范与透明运营原则，本站所有包含推广或商业合作属性的外部链接，在 HTML 渲染层固定输出以下属性与可见提示：

- **链接属性**：`target="_blank"` 搭配 `rel="nofollow sponsored noopener noreferrer"`。
- **可见文字披露**：在每个商业出口卡片附近明确提示“推广合作链接”及适用限制（例如某优惠码仅限指定周期、存在双优惠码冲突记录或不支持退款条款），避免读者误把广告点击当成客观中立导航。

## 三、合作展示位（如优先展示品牌）与客观排序的边界

1. **合作优先展示位不等于“客观第一名”**：
   - 本站在品牌库和部分推荐入口中会对主要合作推广品牌（例如作为主推合作方的光速云等展示位）给予显著展示位置，这属于**商业合作展示安排**。
   - **但商业优先级绝不改变真实证据字段**：例如即使针对重点展示品牌，本站依然如实列出资料冲突（如轻量版流量 59GB vs 69GB 的文档口径差异）、测速批次中的 0B 节点记录、AI 节点视具体落地而定、以及特殊商品不支持退款等客观限制，绝不因合作关系而隐藏负面或待核实字段。
2. **为什么本站不发布“主观速度前十排行榜”**：
   - 不同品牌在现有资料包中的测试时间、测试前端工具（MAI-TEST-BOT vs 喵速等）、后端带宽及协议（Shadowsocks vs VLESS）并不统一，不满足严格横向对比条件，因此不存在一个客观通用的“第一名速度榜”。详情见 [证据分级与测速方法论](/methodology)。

## 四、技术排障内容的完全独立性

1. **故障排查不绑定单一服务商**：所有 `/troubleshooting/`、`/clients/` 与 `/guides/` 页面以解决实际网络报错、客户端崩溃、DNS 污染与规则分流为核心目标，不为了引导消费而把“本地时间偏差 / 系统代理失效 / 端口冲突”甩锅给用户并诱导重买套餐。
2. **风险警示优先于转化**：对于“年付折算均价营销”、“仅专属客户端无法导出通用订阅”、“无免费试用”或“历史记录待核实”等容易引发用户踩坑的问题，本站一律在对应专题页和品牌详情页前置警示。

## 五、常见问题

### 点击本站品牌页里的注册链接，本站会获得什么？会影响用户价格吗？
当通过带推广属性的链接完成注册或消费时，服务商可能会向本站支付一定比例的联盟佣金。这通常不会抬高用户的购买标价，如有可用优惠码均会连同适用条件一并列出。

### 为什么本站明确区分“合作展示位（如优先展示光速云）”与“客观证据排序”？
因为商业合作决定的是展示排序权，而非事实判断权。把合作关系混同为“全网最强测速冠军”会破坏排障知识库的客观基础。

### 技术排障文档（如 Clash、TUN、DNS 教程）是否受品牌商业合作影响？
完全不受影响。所有排障方法均立足客户端原理与通用网络协议，无论读者使用的是否为合作列表中的服务商，排障步骤均同等适用。
