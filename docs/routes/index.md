faq:
  - q: 直连、公网中转和 IEPL/IPLC 专线在物理架构上到底差在哪一段？
    a: 核心差异在于从国内入口到境外落地机房这中间的一跳。直连由本地家庭宽带直接通过公网国际出口连接境外服务器，晚高峰极易遭遇主干网拥塞与端口阻断；公网隧道中转在国内增设一台云服务器做流量接力，优化了本地跨网路由，但跨境段依旧走公网国际出口；IEPL 与 IPLC 专线则将跨境段迁入基础运营商的私有内网电路，绕开公网国际出口拥堵，从而在晚高峰维持稳定的低往返延迟。
  - q: 为什么品牌资料里从 5.6 元/月到 680 元/月都写着 IEPL 专线，实际晚高峰体验却天差地别？
    a: 标注 IEPL 仅说明跨境传输段包含以太网专线环节，完全不代表带宽独享或国内入口永不拥堵。决定最终体感的核心变量还有三个：国内 BGP 入口服务器的抗攻击能力与公网接入带宽余量、服务商实际采购的专线物理带宽被多少名在线用户同时复用（超售比），以及境外落地机房出口带宽与 IP 质量。
  - q: 客户端测速显示香港节点延迟只有 20ms，为什么打开海外网页或对话 AI 依然一直转圈？
    a: 客户端列表常见的 20ms 往往只是本地设备到国内深圳或广州中转入口机的 TCP 或 TLS 握手延迟（TLS RTT），甚至由国内入口机直接代答了握手请求，并未包含跨境专线传输、境外落地服务器向目标网站发起 DNS 解析以及等待目标服务器首字节响应的完整耗时。只有观察完整 HTTP 204 请求的 HTTPS Ping 并核查落地 IP 是否被目标站点风控，才能定位转圈根因。
  - q: 香港节点延迟最低、吞吐最高，为什么反而不建议作为 ChatGPT 和 Gemini 的主力节点？
    a: 香港具备距华南物理距离最近的天然优势，实测吞吐经常突破 400MB/s，但 OpenAI、Anthropic 与 Google 均未将中国香港列入原生开放服务区。除非服务商在香港落地上额外配置了往新加坡或美国的 DNS/分流二次解锁，否则原生香港 IP 访问网页版 ChatGPT 极易被拦截，在光速云 2026-08-19 归档实测中也表现为香港专线 OpenAI 仅限移动端 APP 且 Gemini 多数失败。
  - q: 日本节点的 IIJ、软银（SoftBank）和 NTT 落地在实际使用中有什么区别？
    a: 这三家是日本最常见的上游骨干与落地运营商。IIJ 对东亚互联延迟控制较好，适合网页浏览与 AI 交互，但部分机房晚高峰带宽池较紧；软银（SoftBank）大带宽吞吐强且对中国联通路由友好，适合 4K 流媒体与大文件拉取；NTT 作为大型国际骨干网覆盖广，但在公网直连或普通回程下晚高峰更容易出现跨网抖动与绕行。
  - q: 测速图里的 MB/s 和品牌表格里的 Mbps 怎么换算，为什么跑出 500MB/s 我自己下载只有 30MB/s？
    a: 1 Byte 等于 8 bits，因此 100 MB/s 等于 800 Mbps。第三方测速图（如 MAI-TEST-BOT 与 Miaoko）普遍使用珠海联通 5Gbps 或 9Gbps 机房专线作为测试后端，并开启 32 线程并发拉取测速块，测出的是服务端节点池的理论并发上限；而普通家庭宽带多为 300Mbps 至 1000Mbps（理论下载上限约 37.5MB/s 至 115MB/s），且浏览器或单线程应用无法吃满 32 线程并发。
  - q: 测速报告里出现 0B/s 或几 KB/s 的节点意味着这家机场不能用吗？
    a: 不能直接等价为全盘不可用，但直接暴露出该品牌在测试时刻存在离线死节点或限速残障节点。例如光速云 2026-08-11 图中的香港 02 为 0B、微风网络 2026-07-19 图中的台湾 02 为 0.00B 且日本 05 为 8.00KB/s、宇宙云 2026-08-11 图中的香港 01 为 0.00B。如果单张测速图中失效节点占比低于 5% 且主力节点正常，通常属于局部维护；若大面积出现 0B，则需警惕上游断流或欠费停机。
  - q: 为什么有些品牌文字介绍写着 VLESS 或 Trojan 协议，但 2026-08-11 测速截图却显示 Shadowsocks？
    a: 这种协议口径差异在站内 31 家品牌档案中非常普遍（如星岛梦、二猫云、唯兔云、光年梯、SOGO云、可信云、速界等）。常见原因包括：服务商为兼容旧版测速后端单独维护了一套 Shadowsocks 订阅分组、不同套餐层级下发了不同协议、或品牌宣传文案更新滞后于实际节点部署。选型时应以实际导入客户端后查看到的节点协议字段为准。
  - q: 什么是节点倍率（0.5x / 1x / 2x / 5x），为什么我的 100GB 月流量三天就用光了？
    a: 节点倍率是服务商按线路采购成本设定的流量扣减乘数。实际扣除流量等于你真实产生的上下行流量乘以该节点倍率。如果客户端开启了 URLTest 自动选择，且未将 2x、5x 甚至 10x 的高倍率 IPLC 或原生家宽节点排除在自动测速组之外，后台刷 20GB 的 4K 视频在 5x 节点下会直接扣掉 100GB 账面额度。
  - q: 什么是原生 IP、广播 IP 和 YouTube 送中（CN），它们和线路快慢有关系吗？
    a: 原生 IP 指 IP 的注册归属地与物理机房所在地一致；广播 IP 则是将其他国家注册的 IP 段通过 BGP 宣告在当前机房使用。YouTube 送中（CN）是指由于使用某出口 IP 的中国大陆用户过多且伴随携带大陆位置信息，导致 Google 将该境外 IP 的地理位置库强制修正为中国（CN），进而关闭后台播放与 Premium 权益。这纯粹是落地 IP 信誉与位置库问题，与跨境专线快不快毫无关系。
  - q: 为什么 2026-10-19 的非晚高峰汇总表格不能用来给各家机场排速度名次？
    a: 因为原始品牌资料中的 2026-10-19 表格不仅缺少测试截图、未披露测速工具名称、后端带宽与并发线程数，而且 15 家不同品牌的各地区延迟与带宽数值高度趋同（例如香港全部集中在 21–27ms 与 477–548Mbps 之间），无法排除模板化填表或非严格控制变量的可能，因此本站仅将其列为品牌资料（vendor）参考，绝不据此生成速度排行榜。

# 线路与节点：直连、公网中转、BGP 与 IEPL/IPLC 分层原理

**决定一条代理节点快不快、稳不稳、能不能打开特定 AI 与流媒体，从来不是节点名称里的“香港 01”或“日本高速”这几个字，而是数据包从你的网卡发出后依次穿过的四段物理接力：`本地终端与宽带接入段 → 国内中转入口与 BGP 调度段 → 跨境传输骨干段 → 境外落地机房与目标网站段`。** 只有把“跨境传输走什么电路”和“境外落地用什么 IP”彻底剥离开来，你才能看懂为什么同样标称 **「IEPL 专线」** 的服务会在月付 `5.6 元` 到 `680 元` 之间拉开百倍价差，为什么客户端显示 `20ms` 极低延迟却依然网页转圈，以及如何从 `MAI-TEST-BOT` 与 `Miaoko` 的原始测速截图中一眼揪出 `0B` 死节点、高倍率刺客与 `送中(CN)` 隐患。

## 一、节点与线路基本概念：四段式全链路物理模型

在日常排障中，很多用户习惯把节点当成一个“黑盒”：连得上就是好节点，连不上就归结为“节点挂了”。但在现代代理网络架构中，除了早期单台海外 VPS 直连模式外，绝大多数商业机场早已演进为 **「入口与落地分离（Entry-Exit Separation）」** 的多跳接力结构。

当你点击客户端里的某条节点并发起访问（例如打开 `chatgpt.com` 或播放 YouTube 4K 视频）时，数据包在物理网络上必须依次完成以下四段行程：

1. **第一段：本地终端与家庭宽带接入段（Last Mile & Local ISP）**
   数据包先经本地代理客户端（通过系统代理端口或 TUN 虚拟网卡封装为 Shadowsocks、VLESS、Trojan 或 Hysteria 2 协议流），穿过自家路由器、光猫（ONT）与本地电信/联通/移动城域网，发往节点配置指定的 **「连接地址（Server Address）」**。该段受 Wi-Fi 干扰、光猫会话数、系统校时及运营商晚高峰 UDP 限速策略影响。
2. **第二段：国内中转入口与 BGP 多线调度段（Domestic Ingress & BGP Relay）**
   在中转或专线架构下，客户端看到的节点连接地址并非位于香港或东京，而是部署在深圳、广州、东莞、上海或江苏等国内机房的 **「入口接驳服务器（Ingress Node）」**。优质架构采购 **BGP 多线高防机房**，使电信、联通、移动宽带均能在省内或邻近骨干点就近进入入口机，避免国内跨网互联拥堵。
3. **第三段：跨境传输骨干段（Cross-Border Backbone）**
   数据包进入国内入口机后，如何跨越出境边界到达香港、东京、新加坡等对端机房，是决定 **「晚高峰稳不稳定、丢不丢包」** 的核心分水岭。它既可能是暴露在公共国际出口上的 **公网加密隧道（Public Transit）**，也可能是租用基础运营商底层电路、不过公共国际出口拥堵点的 **IEPL / IPLC 内网专线**。
4. **第四段：境外落地机房与目标网站交互段（Overseas Egress & Target Peering）**
   数据包抵达境外对端后，由 **「落地服务器（Egress Node）」** 解密并以自身公网 IP 向目标网站（如 OpenAI、Netflix、GitHub）发起请求。**目标网站看不见你的本地宽带 IP 与国内入口 IP，只能看见境外落地服务器的出口 IP 及其自治系统号（ASN）。** 因此，速度与延迟主要由前三次接力决定，而 **「能否解锁 AI 和流媒体、是否报 403」** 则几乎 100% 由第四段落地出口 IP 属性决定。

> ⚠️ **概念示意声明**：下方交互拓扑组件与文本架构图仅为网络工程分层概念模型演示，用于直观解释直连、公网中转与 IEPL/IPLC 专线在传输路径、DNS 解析及流量接管上的原理差异，**非任何具体品牌的实际物理机房或运营商拓扑**。

## 二、IEPL 专线原理与商业宣传核实边界

在站内 [31 家机场品牌数据库](/brands/) 中，**「IEPL 专线」** 是出现频率最高的技术标签。从主力档 [光速云](/brands/guangsuyun/)、[微风网络](/brands/weifeng/)、[星岛梦](/brands/xingdaomeng/)、[二猫云](/brands/ermao/)，到 [极连云](/brands/jilian/)、[光年梯](/brands/guangnian/)、[一翻云](/brands/yifan/)、[SOGO云](/brands/sogo/)、[可信云](/brands/kexin/)、[速界](/brands/sujie/)、[梯子云](/brands/tiziyun/)、[神行加速](/brands/shenxing/)，乃至年付折算仅 `5.6 元/月` 的同质化集群（[闪电鼠](/brands/shandianshu/)、[大佬云](/brands/dalaoyun/)、[云界线](/brands/yunjiexian/)、[榴莲云](/brands/liulianyun/)、[环球梯](/brands/huanqiuti/)），其品牌资料（`vendor`）均宣称采用 IEPL 专线。

### 1. 什么是真正的 IEPL（国际以太网专线）？

**IEPL（International Ethernet Private Line，国际以太网专线）** 是基础运营商基于底层 **MPLS**、**EVPL** 或 **OTN** 架构向政企客户交付的端到端 **OSI 第二层（以太网帧级）** 跨境私有通道（典型如深圳/广州直通香港将军澳/葵涌机房）。相比普通公网路由，IEPL 具备三项特征：
- **二层透明桥接**：交付标准以太网接口（VLAN），两端服务器在逻辑上处于同一跨海局域网内，不参与公共 BGP 路由收敛。
- **绕过公网出口拥塞**：普通公网出境须挤过三大运营商公共国际出口，晚间 `20:00–23:30` 易排队丢包；IEPL 走政企商业通道，物理带宽配额独立。
- **点对多点汇聚（EVPL）**：支持一端国内入口对接多端境外机房 VLAN，便于按需分配端口速率。

### 2. 为什么从 5.6 元/月到 680 元/月都宣称 IEPL？如何核实宣传边界？

正规深港/广港 IEPL 政企批发成本每百兆每月动辄数千元，为何 `5.6 元/月`（年付 `67.2 元`）和 `680 元/月` 的套餐都写着“IEPL 专线”？必须核实四个工程边界（详见二级专题 [IEPL 专线原理与辨别方法](/routes/iepl/)）：

1. **复用比（超售比）相差数十倍**：一条 `500Mbps` 深港 IEPL 若分给 200 名商务用户，晚高峰人人可跑百兆；若塞进 10,000 名低价年付用户争抢，晚高峰人均可用带宽将跌破 `1Mbps`。
2. **真假混编包装**：部分中低价服务商仅在主力香港节点挂载小带宽 IEPL，而在台、日、美或低倍率节点混用公网中转甚至直连，却统称“全线 IEPL”。
3. **仅过境段走 IEPL，后段二次中转公网**：IEPL 通常只解决“广东 → 香港”这一跳。到香港出局后，发往日、新、美、欧仍需通过香港机房购买国际公网带宽（Cogent、HE、NTT 等）二次转发（Relay）。若香港上游拥堵，去往美日照样在晚高峰丢包。
4. **“5.6 元同质化模板盘”缺乏实测证据**：[闪电鼠](/brands/shandianshu/)、[大佬云](/brands/dalaoyun/)、[云界线](/brands/yunjiexian/)、[榴莲云](/brands/liulianyun/)、[环球梯](/brands/huanqiuti/) 五家品牌不仅价格一致（年付约 `5.6 元/月 60GB`，季付起 7 折），文案也高度雷同，且均无节点地区明细与实测截图。对此类仅停留在 `vendor` 声明的超低价专线须保持审慎。

::: tip 核验 IEPL 宣传真伪的 3 项用户侧低风险观测法
1. **看晚高峰与平峰的 RTT 抖动差**：真 IEPL 在晚间 `21:00` 与下午 `14:00` 的握手延迟几乎持平（波动低于 `5ms`）；若晚高峰延迟从 `25ms` 暴涨至 `120ms+`，说明存在严重排队或混入公网中转。
2. **看跨运营商入口一致性**：如[光速云](/brands/guangsuyun/)在 `2026-08-19` 归档批次中留存了广西移动、长沙电信、河北联通三网 `2Gbps` 后端 Miaoko 实测图，三网连接同一批 62 个节点均保持稳定连接率与 `20–53MB/s` 吞吐，体现了多线 BGP 接驳的一致性。
3. **看单节点异常率**：即便接入 IEPL，若运维不到位照样会出现单节点断流（如光速云 `2026-08-11` 图中 `HK 02` 为 `0B/0B`、`HK 20` RTT 达 `201ms`），必须在客户端实测具体节点。
:::

## 三、IPLC 专线原理与“专线不等于永不波动”澄清

与 IEPL 并列的另一大高频词是 **「IPLC 专线」**。在站内品牌档案中，[唯兔云](/brands/weitu/)、[Firefly](/brands/firefly/)、[U1S1](/brands/u1s1/)、[闪跃](/brands/shanyue/)、[全球云](/brands/quanqiu/)、[隐形人](/brands/yinxingren/)、[边缘节点 EdgeNova](/brands/edgenova/) 以及[光速云](/brands/guangsuyun/)的部分文案均提及采用了 IPLC 或 IPLC/IEPL 专线架构。

### 1. IPLC（国际私有租赁电路）的底层特征

**IPLC（International Private Leased Circuit，国际私有租赁电路）** 传统上指基于 **SDH**、**MSTP** 或 **OTN 波分复用** 技术构建的点对点（Point-to-Point）专用通信电路（如深港 IPLC、沪日 IPLC）。如果把 IEPL 比作带 VLAN 标签的以太网虚拟专用车道，经典 IPLC 则更接近两端机房之间时隙固定绑定的封闭式点对点轨道：
- **时延高度恒定**：点对点路径完全固定，深港 IPLC 跨境段的纯物理传输往返时延通常在 `2–5ms` 以内；加上省际接入延迟，全国多数地区访问香港 IPLC 节点的端到端 RTT 均可控制在 `15–45ms`。
- **协议与端口无关性**：跨境内网传输段不受公共国际出口对特定端口或 TLS 指纹的随机干扰。在实际商业部署中，多数机场采购的是云厂商切割后的 IPLC/IEPL 虚拟专线端口，两者体感差距极小，真正决定上限的是采购带宽余量与运维冗余。

### 2. 深度澄清：为什么“上了 IPLC / IEPL 专线”不等于“永不波动、永不掉线”？

不少新手看到品牌宣传“企业级 IPLC 纯专线、晚高峰 0 丢包、1 小时修复”（如[一翻云](/brands/yifan/)、[隐形人](/brands/yinxingren/)、[U1S1](/brands/u1s1/) 等品牌的 `vendor` 宣传语），就误以为买了专线机场就永不断网。事实上，**跨境专线只能免疫“第三段（跨境国际出口）”的公网拥堵，却无法消灭其余三个环节的工程故障**（详见二级专题 [IPLC 跨境专线与误区澄清](/routes/iplc/)）：

| 导致专线节点异常的真实环节 | 故障发生机理 | 用户侧直观表现 | 对应核查与排障动作 |
| :--- | :--- | :--- | :--- |
| **1. 国内入口机遭 DDoS 攻击或关停** | 专线必须有国内公网入口接纳家庭宽带流量。同行 DDoS 攻击入口 IP，或国内云机房触发高防黑洞与合规清退 | 某组地区甚至**全部节点瞬间超时**，数小时后更新订阅恢复 | 执行**更新订阅**拉取切换后的新入口域名/IP，参阅[所有节点同时超时排查](/troubleshooting/articles/nodes-all-timeout) |
| **2. 专线带宽池晚高峰打满（QoS 丢包）** | 专线端口存在硬性速率上限。晚间 `21:00` 数千人同时看 4K 视频把专线挤满时，超出配额的数据包被交换机直接丢弃 | 延迟（RTT）依然只有 `25ms`，但下载跌至几百 KB/s，视频缓冲 | 避开编号靠前的热门节点（如香港 01–03），切换至编号靠后或次主力节点 |
| **3. 境外落地机故障或二次链路中断** | 专线到香港后，转发至日本、美国或台湾某台落地 VPS 的下游网线断流、宿主机宕机或欠费 | 香港节点全部正常，但**唯独台湾 02 或美国 01 显示 `0B` / 超时** | 属于局部落地故障，切换同地区其他编号节点，参阅[局部节点超时与 0B 解读](/troubleshooting/articles/nodes-partial-region-timeout) |
| **4. 本地宽带“最后十公里”与 UDP 限速** | 家用光猫会话耗尽、Wi-Fi 信道拥挤，或本地运营商对跨境 UDP 大流量（如 Hysteria 2 / QUIC）实施间歇性丢包 | 手机 5G 流量下飞快，连上家里宽带 Wi-Fi 就断流或卡顿 | 对比手机蜂窝网与家宽表现，切换至 TCP 类协议（VLESS/Trojan/SS），参阅[晚高峰卡顿分层定位](/troubleshooting/articles/high-latency-packet-loss-peak) |

## 四、IEPL vs IPLC vs 公网隧道中转 vs 直连技术对比表

下表将当前代理行业主流的四类传输架构进行了全维度横向对比，帮助你在不同价位下建立合理的工程预期：

| 对比维度 | 第一代：境外公网直连（Direct） | 第二代：公网精品网直连（CN2 GIA / 9929 / CMIN2） | 第三代：国内公网隧道中转（Public Transit / BGP Relay） | 第四代：BGP 多线入口 + IEPL / IPLC 跨境内网专线 |
| :--- | :--- | :--- | :--- | :--- |
| **工作层级与路径** | 本地宽带 → 公网国际出口 → 境外 VPS | 本地宽带 → 运营商精品国际出口 → 境外精品机房 | 本地宽带 → 国内中转云服务器 → 公网国际出口 → 境外落地 | 本地宽带 → 国内 BGP 入口 → 运营商私有跨境内网 → 境外落地 |
| **跨境段是否过公网出口** | 是（走普通 163 / 4837 / CMI 公共出口） | 是（走高优先级精品队列，拥塞较小） | 是（由国内云服务器代为穿越公网国际出口） | **否**（走政企二层以太网或点对点私有租赁电路） |
| **三网晚高峰抗丢包能力** | 极弱（晚高峰丢包率常达 `10%–35%`） | 较强（精品网抗拥塞好，但直连 IP 易暴露） | 中等（解决本地跨网问题，但受制于中转机出国公网质量） | **强**（跨境段几乎零公网拥塞，稳定性上限最高） |
| **典型华南至香港 TLS RTT** | `35–90ms`（晚高峰抖动剧烈，常绕路） | `15–35ms` | `20–45ms` | **`12–28ms`**（全天候延迟曲线平直） |
| **客户端可见连接地址** | 直接暴露境外落地服务器真实 IP | 直接暴露境外精品机房真实 IP | 国内中转机的公网 IP 或 CNAME 域名 | 国内 BGP 专线接驳机的公网 IP 或 CNAME 域名 |
| **抗端口阻断与更换成本** | 极差（境外 IP 被阻断需付费换 IP） | 差（精品网 IP 昂贵，替换成本极高） | 较好（加密隧道保护落地，入口被封可随时切 DNS） | **极好**（跨境走内网，落地 IP 隐藏幕后，仅需维护国内入口） |
| **最常见故障薄弱点** | 晚高峰国际出口拥塞、IP 端口失联 | 遭大流量攻击导致回程绕回普通路线 | 国内中转机因流量突发被云厂商限速或清退 | 国内入口遭 DDoS 攻击、低价盘专线带宽严重超售、落地 IP 脏 |
| **站内关联品牌定位示例** | 早期自建节点或极低价引流节点 | 部分高端定制或混合节点池补充 | [灵猫网络](/brands/lingmao/)（中转优化）、[光速云](/brands/guangsuyun/)（含隧道中转备份） | [光速云](/brands/guangsuyun/)、[微风网络](/brands/weifeng/)、[星岛梦](/brands/xingdaomeng/)、[唯兔云](/brands/weitu/)、[一翻云](/brands/yifan/)、[SOGO云](/brands/sogo/) 等 |

::: warning 选型认知纠偏：不要把“专线”当成唯一指标
在实际使用中，**「优质的公网 BGP 中转（带宽充裕、入口稳定）」往往比「严重超售、5.6 元年付万人共用的所谓 IEPL 专线」体验更好**。判断线路优劣必须结合实测吞吐、异常节点占比和晚高峰表现综合评估，详见[稳定机场核查标准](/airport/stable/)。

## 五、香港节点深度解析：低 TLS RTT 优势与 AI / 送中结构性矛盾

在几乎所有机场的节点列表中，**香港（Hong Kong, HK / HKG）** 都排在第一分组且占比最高——例如在 `data/brands.json` 记录中，[光速云](/brands/guangsuyun/) 与 [可信云](/brands/kexin/) 测速图均含 `香港×20`，[微风网络](/brands/weifeng/) 与 [宇宙云](/brands/yuzhou/) 测速图均含 `香港×15`（占总节点数的 `30%–36%`）。香港节点既是全行业的速度基本盘，又伴随着最突出的 **「AI 锁区与流媒体送中矛盾」**（详见二级专题 [香港节点深度分析](/routes/hong-kong/)）。

### 1. 香港节点的三大核心优势（基于本地实测截图证据）

1. **全站最低的物理往返延迟（RTT）**：香港机房距深圳、广州入口机直线光纤不足 50 公里。经深港/广港专线过境后，华南用户 TLS 握手延迟低至 `12–22ms`，华东与华北用户普遍在 `30–48ms`。
2. **极致的单线程与多线程并发吞吐上限**：由于延迟极低，TCP 拥塞窗口能瞬间爬升至峰值。回顾本站留存的实测截图（`measured`）：
   - **[微风网络](/brands/weifeng/)（`2026-07-19 18:38:20 CST`，Miaoko 珠海联通 9Gbps 32 线程，VLESS）**：`香港 01–15` 平均速度高达 **`468.91–546.20 MB/s`**（折合 `3750–4369 Mbps`），且 NAT 类型均为 `FullCone`；
   - **[无忧链接](/brands/wuyou/)（`2026-07-18 21:40:48 CST` 晚高峰，Miaoko 珠海联通 9Gbps 32 线程，VLESS）**：香港主力节点平均速度达 **`518–554 MB/s`**；
   - **[宇宙云](/brands/yuzhou/)（`2026-08-11 21:04:24 CST` 晚高峰，Miaoko 珠海联通 9Gbps 32 线程，VLESS）**：除 `香港 01` 为 `0.00B` 外，其余 `香港 02–15` 均速达 **`470–550 MB/s`**（FullCone）；
   - **[光速云](/brands/guangsuyun/)（`2026-08-19` 归档批次，Miaoko 珠海联通 9Gbps **单线程**，VLESS 70 节点）**：单线程测试下香港均速依然跑出 **`375–424 MB/s`**；在 `2026-08-11 14:32:56 CST` 的 MAI-TEST-BOT（珠海联通 5Gbps 32 线程，Shadowsocks）中，`HK 03–19` 均速稳定在 `54.43–75.07 MB/s`。
3. **HKIX 交换中心枢纽**：香港拥有亚太最大的互联网交换中心 **HKIX**，Cloudflare、Google、GitHub、Telegram 等主流 CDN 均在本地设有大容量缓存，刷网页与下代码无需跨洋去美国。

### 2. 香港节点的两大结构性短板：AI 原生封锁与 YouTube 送中

- **第一，OpenAI（ChatGPT）、Claude 与 Google Gemini 的地区合规封锁**：
  截至 `2026-11-23`，OpenAI、Anthropic 与 Google 的官方支持地区均**不包含中国香港（HK）**。若香港节点使用纯原生香港本地出口 IP 且未在服务端配置 DNS 解锁或新加坡/美国二次分流，直接访问网页版 ChatGPT 会报 `Unsupported Country` 或 `403 Forbidden`。
  > **实测证据对照**：在 [光速云](/brands/guangsuyun/) `2026-08-19` 归档目录的三网 Miaoko 实测图（广西移动、长沙电信、河北联通）中，**香港专线节点的 OpenAI 解锁状态多数显示为 `仅APP(HK)`（仅移动端 App 可用，网页端受限），而 Gemini 列则大面积显示为 `失败`**。
- **第二，高密度大陆流量引发的 YouTube `送中(CN)` 问题**：
  单台香港落地 IP 每天承载海量携带中文环境或大陆定位特征的流量，极易被 Google 自动化定位系统判定为服务于中国大陆用户，从而将其 YouTube 区域强制标记为 **`CN（送中）`**。
  > **实测证据对照**：在 [无忧链接](/brands/wuyou/) `2026-07-18 21:47:23 CST` 的流媒体实测图（`wuyou-2.jpg`）中，尽管其余 49 个节点正常解锁，但首位的 **`香港HKG-01` 在 `INTL_youtube` 一栏明确显示为 `送中(CN)`**，导致 YouTube 会员后台播放与画中画功能失效（排查见 [YouTube 送中成因与修复](/ai-media/youtube/)）。

## 六、日本节点深度解析：IIJ、软银（SoftBank）与 NTT 落地差异

当香港节点在 AI 工具受阻，而美国节点又因 `150ms+` 跨洋延迟影响响应时，**日本（Japan, JP / TYO / OSA）** 是兼顾 **「亚洲低延迟（50–80ms）」** 与 **「原生支持 ChatGPT / Claude / Netflix / 动漫流媒体」** 的黄金折中选择。主流品牌通常配置 `10 个` 左右日本节点，但背后对接的日本上游运营商（ASN）不同，晚高峰体感差异显著（详见二级专题 [日本节点落地解析](/routes/japan/)）：

| 日本常见上游 / 落地线路 | 常见自治系统号（ASN）与定位 | 延迟与吞吐特性 | 优势场景 | 常见短板与晚高峰风险 |
| :--- | :--- | :--- | :--- | :--- |
| **IIJ（Internet Initiative Japan）** | `AS2497`（日本老牌商业 ISP 与数据中心骨干） | 东亚互联路由直接，沪日/广港日专线接驳后延迟约 `45–68ms` | 网页开发、ChatGPT/Claude 实时对话、日本本土站点 | 部分共享 VPS 宿主机的 IIJ 国际端口较小，晚高峰易触发突发限速 |
| **软银（SoftBank / BBTEC）** | `AS17676` / `AS4725`（日本主力宽带与移动运营商） | 端口带宽充裕，对中国联通及香港 IX 互联吞吐极高，延迟 `48–75ms` | 4K/8K 视频流媒体、大文件下载、主机联机更新 | 机房段 IP 共用人数多时易触发 Google 验证码，部分段 Netflix 仅自制剧 |
| **NTT（NTT Communications）** | `AS2914`（全球 Tier-1 顶级国际骨干网） | 国际带宽极大，但面向中国大陆公网直连时易出现绕行或互联点拥塞 | 适合作为香港/新加坡 IEPL 专线出境后的海外大带宽落地 | 若无国内中转或香港专线托底，国内三网直连 NTT 在晚高峰丢包率极高 |
| **KDDI / 索尼 So-net / 本土商宽家宽** | `AS2516` 等本土接入网 | 带宽上限相对机房较小，多以高倍率或定制节点形态提供 | DMM、AbemaTV、TVer 等严苛校验日本本土家宽 IP 的应用 | 采购成本高，普通 `1x` 节点池罕见，多为 `2x–5x` 节点 |

### 日本节点的实测表现与异常案例警示

从本站留存的实测截图来看，日本节点整体吞吐处于第三梯队，但需警惕 **「个别节点极低速或送中」**：

## 七、新加坡、台湾、美国及其他欧美冷门节点特点

除港日外，**新加坡（SG）**、**台湾（TW）**、**美国（US）** 与欧美冷门节点各自承担着不可替代的分流角色：

### 1. 新加坡节点（Singapore, SG / SIN）：高吞吐亚太 AI 枢纽与送中重灾区
- **吞吐与 AI 优势**：新加坡是东南亚海缆枢纽，经广港/深港专线接驳后延迟约 `40–65ms`，实测吞吐仅次于香港（[宇宙云](/brands/yuzhou/) 晚高峰正常节点 `331–523 MB/s`、[微风网络](/brands/weifeng/) `135–401 MB/s`、[无忧链接](/brands/wuyou/) 晚高峰 `94–352 MB/s`、[光速云](/brands/guangsuyun/) `55–73 MB/s`）。且新加坡属于 OpenAI、Claude 与 Gemini 官方支持区——如光速云 `2026-08-19` 长沙电信 Miaoko 图中，当港/台/日/美节点在 Gemini 上大面积失败时，**新加坡节点成功实现 `Gemini 解锁(SG)`**。
- **送中与限速风险**：新加坡广播 IP 极易被大陆流量污染。在光速云 `2026-08-19` 流媒体图（`guangsuyun-miaoko-streaming-ai.jpg`）中，**`新加坡 01–10` 及 `电信-新加坡01` 在 YouTube 列全部显示为 `送中(CN)`**；[灵动云](/brands/lingdong/) `2026-07-20/21` 历史实测同样记录了新加坡 YouTube 送中。此外，无忧链接 `SIN-02`（`17.59 KB/s`）、宇宙云 `新加坡07`（`9.60 KB/s`）与待核实实体快狸 `Singapore08`（`9.60 KB/s`）均存在单点限速。另需留意资料冲突：如 [二猫云](/brands/ermao/) 正文曾写“少了新加坡这一站”，但同页 `2026-10-19` 测速表却列有 `新加坡 46ms / 407Mbps`。

### 2. 台湾节点（Taiwan, TW / TPE）：华语流媒体刚需与高故障率短板
- **核心价值**：台湾节点（特别是 HiNet 商宽或原生落地）是观看 **巴哈姆特动画疯**、繁体字库 **台湾区 Netflix / Disney+** 的刚需入口。
- **高异常率实证**：受限于台海带宽成本与机房限制，台湾节点普遍数量少（常仅 5 个）、吞吐较低且异常率最高：[微风网络](/brands/weifeng/) `2026-07-19` 图中 **`台湾 02` 为 `0.00B / 0.00B`（断流）**；[光速云](/brands/guangsuyun/) `2026-08-11` 图中 `TW 04` 仅 `8.40 MB/s`，`2026-08-19` 河北联通图中 `台湾 01` 仅 `4.79 MB/s`，且 **`台湾 01–06`、`08–10` 及 `电信-台湾01/02` 均出现 YouTube `送中(CN)` 与多节点 `Disney+ 失败`**；[可信云](/brands/kexin/) 台湾节点仅 `3.86–27 MB/s`；[灵动云](/brands/lingdong/) `2026-07-20/21` 历史实测中，台湾落地广播 IP 在 **Netflix 与 Disney+ 上甚至被识别为欧洲西班牙（`ES`）**。

### 3. 美国节点（United States, US / LAX / SJC）：跨洋物理延迟与 AI / 美区原生基准
- **物理延迟与吞吐**：跨太平洋光缆物理距离决定了美西（洛杉矶/圣何塞）节点的最低真实 RTT 也在 **`135–195ms`** 之间。受高延迟带宽延迟积（BDP）制约，美国节点吞吐普遍低于亚太（光速云 `08-11` 为 `54–71 MB/s`、微风 `9.90–21.03 MB/s`、无忧 `12–18 MB/s`、宇宙云 `8.33–12.36 MB/s`），同时需剔除坏节点（如光速云 `08-19` **`美国 02 = 1.60 KB/s`**、可信云 **`US 05 = 688.93 KB/s`**、灵动云历史记录 **`美国 01` 整节点失败**）。
- **核心定位**：美国是 ChatGPT、Claude、Gemini、美区 Netflix/HBO Max 及海外金融风控的原生基准大本营，是亚太节点解锁失效时的终极兜底选区。

### 4. 欧洲、东南亚、南美等冷门节点（英/法/德/土/泰/马/巴/韩）
[光速云](/brands/guangsuyun/) 宣称覆盖英、法、德、土、泰、马、巴等 12 个地区；[SOGO云](/brands/sogo/) 宣称覆盖 15 个国家和地区（`2026-08-11` 测速图实际可见 12 地区）；[星岛梦](/brands/xingdaomeng/) 覆盖韩国与东南亚。此类冷门节点多采用“香港/新加坡专线出境 + 国际公网二次中转”，RTT 达 `200–380ms`，专供跨区订阅、小语种电商或本地化测试，不建议作日常主力。

## 八、节点延迟影响因素：区分单次 TLS RTT 与 HTTPS Ping 体感延迟

为什么在客户端一键测速时所有节点延迟都显示 `18ms`、`24ms` 一片翠绿，点开网页却白屏转圈 10 秒钟？解开这一误区必须分清四种不同的延迟测量口径（详见二级专题 [低延迟节点真相：TLS RTT 与 HTTPS Ping](/routes/low-latency/)）：

| 延迟指标名称 | 测量协议与触发位置 | 实际测量到的物理路径范围 | 能否发现“落地机断网”或“目标站 403”？ | 常见欺骗性与排障盲区 |
| :--- | :--- | :--- | :--- | :--- |
| **1. ICMP Ping** | 操作系统 `ping` 命令（L3 网络层） | 本地电脑 ⇄ 国内中转入口机公网 IP | **完全不能** | 只测了你家到深圳/广州入口机的距离；高防入口禁 Ping 时显示超时但代理其实可用 |
| **2. TCP Ping（连接延迟）** | 向节点端口发起 `SYN → SYN-ACK` 握手 | 本地客户端 ⇄ 国内中转入口机监听端口 | **完全不能** | 国内入口机在本地直接代答 `SYN-ACK`，哪怕跨境专线已彻底断掉，TCP Ping 仍显示 `20ms` |
| **3. TLS RTT（测速图常用）** | 在 TCP 之上完成代理或 TLS 握手往返 | 测试后端 ⇄ 节点握手往返（受入口卸载影响） | **部分能** | 反映测试机房到节点的传输握手延迟，但不包含远端 DNS 解析与目标网站响应耗时 |
| **4. HTTPS Ping / URLTest** | 通过完整代理链路请求 `generate_204` 并收到 `HTTP 204` | **本地 → 国内入口 → 跨境专线 → 境外落地 → 远端 DNS → 目标站 → 返回** | **能（最接近真实网页体感）** | 唯一验证全链路四段通畅的指标；但若测试 URL 为 `gstatic.com`，仍测不出 `chatgpt.com` 是否被 403 拦截 |

**实测案例印证**：
1. 在 [光速云](/brands/guangsuyun/) `2026-08-11` 截图中，多数香港节点 RTT 极低，但同组 **`HK 香港 20` RTT 却飙升至 `201ms`**，`HK 香港 02` 则为 `0B`；[全球云](/brands/quanqiu/) `2026-08-11` 图中的日本节点 RTT 也普遍接近 `200ms`，提示跨境或二次转发存在绕路。
2. 在 [灵动云](/brands/lingdong/) `2026-07-20/21` 历史实测摘要中明确记录了 **“速度 20–80MB/s、但 HTTPS 延迟偏高”**——这是因为落地机远端 DNS 解析缓慢或多级中转首包建立时间（TTFB）较长，导致打开网页慢，但连接建立后的大文件测速依然能跑高带宽。因此日常看网页秒开能力必须盯住 `HTTPS Ping / URLTest` 与本地 [DNS 与 Fake-IP 配置](/guides/dns-setup/)。

## 九、下载与上传吞吐解析：32 线程并发测速 vs 单线程真实体感

看到 `MAI-TEST-BOT` 或 `Miaoko` 截图里满屏 **`400 MB/s`**、**`546 MB/s`** 的成绩，为什么自己用千兆宽带下载却只有 `30–60 MB/s`？读懂吞吐数据必须跨过三道专业门槛（详见[为什么客户端测速与实际下载速度差异大](/troubleshooting/articles/bandwidth-multiplier-speedtest-diff)）：

### 1. 严格区分 `MB/s`（兆字节每秒）与 `Mbps`（兆比特每秒）

**大写 `B`（Byte）与小写 `b`（bit）相差整整 8 倍（`1 Byte = 8 bits`）**：
- **测速截图（`MAI-TEST-BOT` / `Miaoko`）单位是 `MB/s`（或 `KB/s`、`B`）**：与浏览器下载文件显示的每秒兆字节一致。
- **运营商宽带与 `2026-10-19` 品牌参考表单位是 `Mbps`**：家庭“1000M 千兆宽带”即 `1000 Mbps`，扣除协议开销后物理下载极限约为 **`112–118 MB/s`**；300M 宽带下载极限约为 **`35–37 MB/s`**。

| 测速图数值（单位：`MB/s`） | 换算为带宽速率（单位：`Mbps`，×8） | 对应所需的本地物理宽带规格 | 实际应用场景意义 |
| :--- | :--- | :--- | :--- |
| **`1.60 KB/s` – `17.59 KB/s`** | `0.013 Mbps` – `0.14 Mbps` | 属于**严重限速/残障节点** | 连纯文本网页都难以加载（如光速云 `美国02=1.60KB/s`、微风 `日本05=8.00KB/s`、无忧 `SIN-02=17.59KB/s`） |
| **`3.86 MB/s` – `8.40 MB/s`** | `30.88 Mbps` – `67.20 Mbps` | 相当于 50M–100M 家宽水平 | 可流畅观看 1080P 与普通 4K 视频（YouTube 4K 约需 `25–35 Mbps` 即 `3.5–4.5 MB/s`） |
| **`20 MB/s` – `75 MB/s`** | `160 Mbps` – `600 Mbps` | 匹配主流 300M–600M 家庭光纤 | 4K/8K 视频秒拖进度条、高速下载（如光速云 `08-11` 5Gbps 后端实测区间） |
| **`375 MB/s` – `554 MB/s`** | **`3000 Mbps` – `4432 Mbps`** | **远超家庭千兆宽带上限**（需 `5Gbps / 9Gbps` 机房专线后端测出） | 反映服务端节点池具备 `3–4.5Gbps` 级总余量；普通千兆家宽用户单机最高只能跑到约 `115 MB/s` |

### 2. 机房 `5Gbps / 9Gbps` 32 线程并发 vs 家庭单线程体感

以 [光速云](/brands/guangsuyun/) `2026-08-19` 归档目录的 5 张 Miaoko 实测图为例：在广西移动、长沙电信、河北联通 **`@2Gbps 后端、6 线程、Shadowsocks`** 下，测出速度为 `20–53 MB/s`；而在珠海联通 **`[A14-1] 9Gbps 后端、VLESS`** 下，香港均速跃升至 `375–424 MB/s`；微风网络、无忧链接、宇宙云在 **`[A11-32] 珠海联通 9Gbps 32 线程`** 下更是测出 `468–554 MB/s`。32 线程并发测的是机场节点水池的“总出水量上限”，而日常打开网页或视频初期只有 1–4 个并发连接，单线程无丢包才是体感流畅的关键。

### 3. 警惕家庭宽带非对称上传瓶颈（Upload Bottleneck）

国内千兆家宽的下行虽达 `1000Mbps`，但上行通常被运营商限制在 **`30–50Mbps`（仅 `3.75–6.25 MB/s`）**。一旦本地网盘同步或视频会议占满这 `4MB/s` 的上传通道，发往代理节点的 TCP `ACK` 确认包就会在本地光猫排队，导致下载速度跟着暴跌。

## 十、丢包率、抖动（Jitter）与晚高峰稳定性

在网络传输中，**高延迟不一定卡顿，但 `3%–5%` 的丢包（Packet Loss）和剧烈抖动（Jitter）足以摧毁实时交互体验**：
1. **TCP 重传退避与队头阻塞**：当链路出现 `3%–5%` 随机丢包时，TCP 拥塞控制算法（CUBIC/BBR）会频繁触发超时重传与窗口减半，导致原本几十兆的数据流瞬间刹停等待补包，表现为 ChatGPT 流式输出卡死数秒、SSH 敲击卡顿。
2. **UDP 转发、QUIC 与 FullCone NAT**：浏览器默认使用基于 UDP 443 的 HTTP/3（QUIC）加载 YouTube 与网页。若节点不支持 UDP 或本地宽带晚高峰对 UDP 实施惩罚性 QoS 丢包，会造成网页前 5 秒空白等待回退 TCP。此外，外服联机游戏与实时语音高度依赖 **FullCone NAT（全锥形 NAT / NAT 1）**——在 [微风网络](/brands/weifeng/) `2026-07-19` 与 [宇宙云](/brands/yuzhou/) `2026-08-11` 的 Miaoko 截图中，香港节点均明确带有绿色的 **`FullCone`** 标识，有利于联机打洞与语音稳定（详见[游戏加速器与 NAT 专题](/vpn/gaming/)及[UDP 转发与防火墙排查](/troubleshooting/articles/udp-nat-firewall-blocks)）。

## 十一、线路倍率与实际流量消耗计算（0.5x / 1x / 2x / 5x）

“150GB 月流量为什么四天就耗尽了？”除订阅泄露外，绝大多数源于忽视了节点名称后的 **「计费倍率（Traffic Multiplier）」**（详见二级专题 [线路倍率计费规则与流量核算](/routes/multipliers/)）：

$$\text{面板实际扣除流量} = (\text{客户端实际上传流量} + \text{客户端实际下载流量}) \times \text{节点计费倍率} \times \text{协议封装开销系数(约 } 1.03\sim 1.08\text{)}$$

| 节点倍率档位 | 常见命名示例 | 真实传输 `10 GB` 时面板扣费 | `150 GB/月` 套餐在该节点下的真实可用量 | 典型适用场景与站内品牌对比 |
| :--- | :--- | :--- | :--- | :--- |
| **`0.1x – 0.5x`（低倍率线）** | `香港 闲时下载 0.5x` | 仅扣 **`1 GB – 5 GB`** | 扩展为 **`300 GB – 1500 GB`** | 挂机下载 Steam 游戏、大体积开源模型权重、长视频 |
| **`1.0x`（标准一倍线）** | `香港 IEPL 01 [1x]` | 实扣 **`10 GB`**（1:1） | 实打实 **`150 GB`** | 日常主力；站内如 [星岛梦](/brands/xingdaomeng/)、[无忧链接](/brands/wuyou/)、[唯兔云](/brands/weitu/)、[灵猫网络](/brands/lingmao/) 均声明 **「全线 1 倍流量 / 无倍率」** |
| **`1.5x – 2.0x`（精品专线）** | `日本 IPLC 精品 [2x]` | 扣除 **`15 GB – 20 GB`** | 缩水为 **`75 GB – 100 GB`** | 晚高峰主力线拥挤时的备选，或特定地区流媒体解锁 |
| **`3.0x – 10.0x`（高倍刺客）** | `美国 原生家宽 [5x]` | 暴扣 **`30 GB – 100 GB`** | 缩水为仅 **`15 GB – 50 GB`** | **严禁看视频或下载！** 仅限绑在特定分流规则上供 AI 文字对话或登录校验 |

**两条防坑铁律**：第一，检查 Clash 的 `自动选择（URLTest）` 策略组，务必把 `2x / 5x` 节点从自动测速组剔除，防止因延迟低 `2ms` 被自动选为主力刷 4K 视频；第二，切勿在客户端频繁手动点“全节点吞吐测速”——如 `MAI-TEST-BOT` 截图顶部所示，[光速云](/brands/guangsuyun/) 54 节点单轮 32 线程测速即消耗 **`19.4 GB`**，[可信云](/brands/kexin/) 55 节点单轮测速消耗 **`10.5 GB`**（排障见[流量耗尽与旧配置区分](/troubleshooting/articles/quota-expired-vs-stale-config)）。

## 十二、IP 地址类型：IDC 机房 / 商宽 / 住宅家宽、原生 vs 广播与 IPRisk 评分

到了全链路第四段（境外落地出口），决定目标网站是否放行的核心在于出口 IP 的 **「注册属性（原生 vs 广播）」** 与 **「风控信誉（ASN 类型与 IPRisk）」**：

1. **原生 IP（Native IP）vs 广播 IP（Broadcast IP）**：
   - **原生 IP**：Whois 注册国家与实际物理机房所在地完全一致，各大 GeoIP 数据库统一识别为当地。
   - **广播 IP**：将他国注册的闲置 IPv4 段通过 BGP 宣告在当前机房使用。由于各平台 GeoIP 库更新不同步，极易产生跨区识别漂移——典型实证即 **[灵动云](/brands/lingdong/) `2026-07-20/21` 实测中，其台湾落地节点在 Netflix 与 Disney+ 上被识别为西班牙（`ES`）**。
2. **机房 IP（IDC）vs 商宽/住宅 IP（ISP / Residential）与 IPRisk**：
   - **普通机房 IP（IDC）**：占常规机场节点的 90% 以上，共享人数多时 `IPRisk` 欺诈风险分偏高，Netflix 常仅解锁自制剧，Claude 网页版易封号，Google 常弹验证码。
   - **本土商宽 / 独享机房 IP**：多见于 `600–680 元/月` 定制套餐（如[光速云](/brands/guangsuyun/)、[星岛梦](/brands/xingdaomeng/)、[暮光加速](/brands/muguang/)、[全球云](/brands/quanqiu/)、[隐形人](/brands/yinxingren/)、[浪网](/brands/langwang/)的定制档 `vendor` 声明），风险分低，可稳定解锁全区流媒体与 AI。
   - **原生住宅家宽 IP（Residential）**：真实民用宽带 IP，风险分极低。需警惕部分平价共享机场（如[一翻云](/brands/yifan/)在 `20 元/月` 常规档宣称“原生住宅 IP”）的营销话术，真正民用家宽无法承受数十人跑 5Gbps 32 线程并发测速，绝大多数实为配置了 DNS 解锁的机房 IP，必须以流媒体与 AI 实测报告为准。

## 十五、节点选择四步标准流程（从拿到订阅到稳定分流）

1. **第一步：定边界（核对客户端体制与协议兼容性）**
   先确认服务商提供 **通用订阅链接** 还是 **仅限专属客户端**（如飞猫云、无忧链接 2026-10 起、Firefly 2026-10 起、灵猫网络 2026-10 起、SOGO云、闪跃、全球云、隐形人均不支持第三方订阅）。若使用 [Clash Verge Rev](/clients/clash-verge/)、[v2rayN](/clients/v2rayn/) 或 [Shadowrocket](/clients/shadowrocket/)，确保内核支持 `VLESS-Reality`、`Hysteria 2` 或 `AnyTLS`（详见[客户端软件专题](/clients/)）。
2. **第二步：筛地区（按业务锁定第一落地区与备份区）**
   将需求一分为二：**高速低延迟组（网页、下载、常规视频）** 首选 **香港（HK）**，华东/华北以 **日本（JP）** 或 **台湾（TW）** 为备选；**高风控解锁组（ChatGPT、Claude、Gemini、美区流媒体）** 避开原生香港节点，直接锁定 **新加坡（SG）**、**美国（US）** 或 **日本（JP）**。
3. **第三步：验健康（剔除 `0B` 死节点、高倍率刺客与送中节点）**
   避开所有人默认扎堆的 `01` 号节点（如宇宙云 `香港01=0.00B`、无忧 `香港HKG-01` 送中、灵动云 `美国01` 失败）：优先选 **`1x` 倍率且编号居中的节点（如 05–12 号）**；执行一次客户端 **URLTest（真连接延迟）** 淘汰超时与高延迟绕路节点（如 `HK 20 = 201ms`）；打开 YouTube 核对左上角地区角标确认未 `送中(CN)`。
4. **第四步：做分组（利用规则分流实现“各走各路”）**
   在 [Clash 配置](/guides/clash-setup/) 与 [分流规则](/guides/split-routing/) 中，将主策略组设为香港/日本 `1x` 节点保网速，将 `AI / OpenAI / Claude / Gemini` 策略组手动固定在一条已验证通过的新加坡或美国节点上，防止自动切节点引发 AI 封号。

## 十八、常见问题（线路与测速高频 FAQ）

### 直连、公网中转和 IEPL/IPLC 专线在物理架构上到底差在哪一段？

核心差异在于从国内入口到境外落地机房这中间的一跳。直连由本地家庭宽带直接通过公网国际出口连接境外服务器，晚高峰极易遭遇主干网拥塞与端口阻断；公网隧道中转在国内增设一台云服务器做流量接力，优化了本地跨网路由，但跨境段依旧走公网国际出口；IEPL 与 IPLC 专线则将跨境段迁入基础运营商的私有内网电路，绕开公网国际出口拥堵，从而在晚高峰维持稳定的低往返延迟。

### 为什么品牌资料里从 5.6 元/月到 680 元/月都写着 IEPL 专线，实际晚高峰体验却天差地别？

标注 IEPL 仅说明跨境传输段包含以太网专线环节，完全不代表带宽独享或国内入口永不拥堵。决定最终体感的核心变量还有三个：国内 BGP 入口服务器的抗攻击能力与公网接入带宽余量、服务商实际采购的专线物理带宽被多少名在线用户同时复用（超售比），以及境外落地机房出口带宽与 IP 质量。

### 客户端测速显示香港节点延迟只有 20ms，为什么打开海外网页或对话 AI 依然一直转圈？

客户端列表常见的 20ms 往往只是本地设备到国内深圳或广州中转入口机的 TCP 或 TLS 握手延迟（TLS RTT），甚至由国内入口机直接代答了握手请求，并未包含跨境专线传输、境外落地服务器向目标网站发起 DNS 解析以及等待目标服务器首字节响应的完整耗时。只有观察完整 HTTP 204 请求的 HTTPS Ping 并核查落地 IP 是否被目标站点风控，才能定位转圈根因。

### 香港节点延迟最低、吞吐最高，为什么反而不建议作为 ChatGPT 和 Gemini 的主力节点？

香港具备距华南物理距离最近的天然优势，实测吞吐经常突破 400MB/s，但 OpenAI、Anthropic 与 Google 均未将中国香港列入原生开放服务区。除非服务商在香港落地上额外配置了往新加坡或美国的 DNS/分流二次解锁，否则原生香港 IP 访问网页版 ChatGPT 极易被拦截，在光速云 2026-08-19 归档实测中也表现为香港专线 OpenAI 仅限移动端 APP 且 Gemini 多数失败。

### 日本节点的 IIJ、软银（SoftBank）和 NTT 落地在实际使用中有什么区别？

这三家是日本最常见的上游骨干与落地运营商。IIJ 对东亚互联延迟控制较好，适合网页浏览与 AI 交互，但部分机房晚高峰带宽池较紧；软银（SoftBank）大带宽吞吐强且对中国联通路由友好，适合 4K 流媒体与大文件拉取；NTT 作为大型国际骨干网覆盖广，但在公网直连或普通回程下晚高峰更容易出现跨网抖动与绕行。

### 测速图里的 MB/s 和品牌表格里的 Mbps 怎么换算，为什么跑出 500MB/s 我自己下载只有 30MB/s？

1 Byte 等于 8 bits，因此 100 MB/s 等于 800 Mbps。第三方测速图（如 MAI-TEST-BOT 与 Miaoko）普遍使用珠海联通 5Gbps 或 9Gbps 机房专线作为测试后端，并开启 32 线程并发拉取测速块，测出的是服务端节点池的理论并发上限；而普通家庭宽带多为 300Mbps 至 1000Mbps（理论下载上限约 37.5MB/s 至 115MB/s），且浏览器或单线程应用无法吃满 32 线程并发。

### 测速报告里出现 0B/s 或几 KB/s 的节点意味着这家机场不能用吗？

不能直接等价为全盘不可用，但直接暴露出该品牌在测试时刻存在离线死节点或限速残障节点。例如光速云 2026-08-11 图中的香港 02 为 0B、微风网络 2026-07-19 图中的台湾 02 为 0.00B 且日本 05 为 8.00KB/s、宇宙云 2026-08-11 图中的香港 01 为 0.00B。如果单张测速图中失效节点占比低于 5% 且主力节点正常，通常属于局部维护；若大面积出现 0B，则需警惕上游断流或欠费停机。

### 为什么有些品牌文字介绍写着 VLESS 或 Trojan 协议，但 2026-08-11 测速截图却显示 Shadowsocks？

这种协议口径差异在站内 31 家品牌档案中非常普遍（如星岛梦、二猫云、唯兔云、光年梯、SOGO云、可信云、速界等）。常见原因包括：服务商为兼容旧版测速后端单独维护了一套 Shadowsocks 订阅分组、不同套餐层级下发了不同协议、或品牌宣传文案更新滞后于实际节点部署。选型时应以实际导入客户端后查看到的节点协议字段为准。

### 什么是节点倍率（0.5x / 1x / 2x / 5x），为什么我的 100GB 月流量三天就用光了？

节点倍率是服务商按线路采购成本设定的流量扣减乘数。实际扣除流量等于你真实产生的上下行流量乘以该节点倍率。如果客户端开启了 URLTest 自动选择，且未将 2x、5x 甚至 10x 的高倍率 IPLC 或原生家宽节点排除在自动测速组之外，后台刷 20GB 的 4K 视频在 5x 节点下会直接扣掉 100GB 账面额度。

### 什么是原生 IP、广播 IP 和 YouTube 送中（CN），它们和线路快慢有关系吗？

原生 IP 指 IP 的注册归属地与物理机房所在地一致；广播 IP 则是将其他国家注册的 IP 段通过 BGP 宣告在当前机房使用。YouTube 送中（CN）是指由于使用某出口 IP 的中国大陆用户过多且伴随携带大陆位置信息，导致 Google 将该境外 IP 的地理位置库强制修正为中国（CN），进而关闭后台播放与 Premium 权益。这纯粹是落地 IP 信誉与位置库问题，与跨境专线快不快毫无关系。

### 为什么 2026-10-19 的非晚高峰汇总表格不能用来给各家机场排速度名次？

因为原始品牌资料中的 2026-10-19 表格不仅缺少测试截图、未披露测速工具名称、后端带宽与并发线程数，而且 15 家不同品牌的各地区延迟与带宽数值高度趋同（例如香港全部集中在 21–27ms 与 477–548Mbps 之间），无法排除模板化填表或非严格控制变量的可能，因此本站仅将其列为品牌资料（vendor）参考，绝不据此生成速度排行榜。
