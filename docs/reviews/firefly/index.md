# Firefly深度评测：主表与 08-09 历史合并审计、2026-10 纯专属端与零实测缺口

**更新日期：2026-11-24** · **数据分级：`vendor` + `conflicted` + `unverified`（无本地 `measured` 实测截图）** · **定位：品牌独立深度评测**

在代理机场的资料整理工作中，最容易迷惑消费者的从来不是「资料太少」，而是 **「同一家品牌在不同时间点留下了两套相互错位的档案」**。**Firefly（又称 Firefly 萤火虫）** 正是《32家机场品牌清单.txt》中最典型的双档案合并样本：它在主表位列前十（`#8`），高调宣传「IPLC 专线、VLESS 协议、8 元/月起、原生 IP 与 2026-10 专属客户端」；而在同一份文档末尾的 `2026-08-09` 历史附录里，它又以「Firefly 萤火虫」的名义多出了一套详尽的月付至三年付价目表、支付方式限制与同系品牌关联说明。

如果我们像普通导航站那样只抄主表，读者就会漏掉 **「无微信支付」「与微风网络等同系」「多周期 64 折来源」** 以及 **「08-09 明确写着无逐地区实测数据」** 这些关键事实；如果只看历史表，又会错过 **「2026 年 10 月起彻底转向专属客户端、不再提供订阅链接」** 这一足以改变选型逻辑的架构大转向。本篇评测将以双档案合并审计为切入点，彻底拆解 Firefly 的团队背景宣称、纯专属客户端锁定代价、全周期定价模型与「零实测截图」下的风险红线。

## 一、双档案合并审计：主表 `#8` 与 `2026-08-09` 历史记录到底差在哪？

在进入性能与价格评估前，我们必须先把 Firefly 的「档案身世」厘清。原始清单共列出 32 条品牌记录，经过去重核查后，实际只有 **31 个独立品牌**——被合并的那一条正是主表的 **`Firefly`** 与文末附录的 **`Firefly 萤火虫`**。两者共用相同的套餐命名体系（`年付版 / Lite / Plus / Blaze / Nova / 不限时`）、相同的 8 折新用户优惠码 `firefly` 以及一致的 `IPLC + VLESS` 定位，确凿为同一实体。

但把两份相隔两个多月（`2026-08-09` vs `2026-10-19`）的档案并排对照，就能看出 Firefly 在这两个月间经历的明显信息演变与审计冲突：

| 审计维度 | `2026-08-09` 历史档案（Firefly 萤火虫） | `2026-10-19` 当前主表（#8 Firefly） | 合并审计结论与风险提示 |
|---|---|---|---|
| **渠道参数与官网** | 记录有一套历史推广渠道标识（与主表参数不一致） | 记录另一套当前渠道标识；总表备注「免翻墙访问官网」 | **双邀请码参数冲突仅保留在后台数据审计中**（本评测不展示任何推广域名或外链）；两处均无非推广主域名，`officialUrl` 保持 `待核实` |
| **客户端与订阅策略** | 未写明强制专属客户端 | 明确写明 **「2026 年 10 月起专属客户端，下载登录即用（不提供订阅链接）」** | **重大架构变化**：意味着旧教程或老用户记忆中的第三方订阅导入已失效 |
| **团队背景与同系关联** | 写明「现有资料记录（未独立实测）8 年团队」；明确披露 **「与微风、飞鸟和一云梯存在明确同系关系」** | 仅写「海外技术团队维护线路，客服 7×24 小时在线，夜间由 AI 客服值守」 | 「8 年团队」缺乏独立开业时间佐证；与 [微风网络](/reviews/weifeng/) 同系是理解其客服与产品风格的重要线索 |
| **套餐周期展示** | 完整列出 **月付 / 季付 / 半年 / 年付 / 两年 / 三年** 全部 26 项标价，并注明「季9 / 半85 / 年8折，最高约64折」 | 仅列出 6 档基准月付/年付/不限时价格，未再展开季付至三年付 | 历史上存在极深的长周期折扣，但当前是否仍保留多周期与叠加规则 **待下单页实时核实** |
| **支付方式** | 明确记录 **「支付宝 / USDT（无微信）」** | 未提及支付方式 | 历史限制极具实操价值，仅依赖微信支付的用户需提前留意 |
| **测速与证据状态** | 明确写着 **「未提供可比的逐地区测速数据」** | 附带一张 `2026-10-19 非晚高峰` 文本表格（香港 27ms/547Mbps 等） | 本地 **零实测截图**；10-19 无来源表格不可升级为实测，整品牌保持 `vendor` 评级 |

这种跨时间对比之所以重要，是因为它打破了单一宣传页制造的静态幻觉：Firefly 并不是一家信息完全透明、历史证据完备的老牌机场，而是一家在 **2026 年秋季主动收缩了第三方订阅开放度**、且迄今在独立测速档案库里依然交白卷的专线品牌。

## 二、「8 年团队」宣称、同系关联与 `2026-10` 纯专属端的架构代价

### 1. 「8 年团队」为什么不能直接等于「8 年老牌机场」？

在机场评测行业，「运营年限」是最常被模糊化的概念之一（详见 [如何核验机场宣称的运营年份](/brands/articles/verify-brand-operating-years)）。Firefly 历史资料中提到 **「8 年团队」**，但既没有标注 Firefly 品牌本身的正式上线年份，也没有提供过往多年可连续追溯的测速归档或独立官网历史快照。

需要区分两个完全不同的事实：一个运维团队可能先后孵化、更名或并行运营过多个代理品牌，因此自称「拥有 8 年行业运维经验」；但这并不意味着当前这个叫 Firefly 的品牌主体已经连续稳定履约了 8 年。更何况，历史档案还白纸黑字地记录了它 **「与微风、飞鸟和一云梯存在明确同系关系」**。对比我们在 [微风网络深度评测](/reviews/weifeng/) 中观察到的特征——同样主打 VLESS 协议、同样配备「7×24 在线且夜间由 AI 客服值守」、同样在年付小包之上拉起 25–27 元月付梯队——这种产品基因的趋同确实印证了同系运作的痕迹。

同系关联是一把双刃剑：积极的一面是团队在供应链采购、基础客服响应和客户端打包上通常比「草台班子单人小机场」更有章法，不至于轻易因为一次小故障就失联；消极的一面则是 **如果用户想通过买两家机场来做「异构容灾备份」**，同时买 Firefly 和微风网络就可能撞上同一套上游线路或同一个运维团队，一旦上游入口波动或发生维护事件，两家同时受影响的风险显著高于无关联的独立品牌。

### 2. 2026-10 纯专属端（无订阅链接）：省了什么，锁死了什么？

Firefly 主表最醒目的政策拐点是：**自 2026 年 10 月起改用官方专属客户端，下载登录即用，不提供订阅链接**。这与本站收录的 [飞猫云](/reviews/feimao/)、[灵猫网络](/reviews/lingmao/)、[SOGO云](/reviews/sogo/)、[闪跃](/reviews/shanyue/) 以及 [全球云](/reviews/quanqiu/) 属于同一股「封闭客户端潮」。

站在架构与排障视角，厂商砍掉通用订阅链接的真实动机通常有三点：防订阅被爬取倒卖、简化小白上手售后压力、以及在客户端内统一控制节点路由与协议参数。虽然 Firefly 在两份档案中口径非常统一地标注了 **VLESS 协议**（在全库动辄「文案写 VLESS 实测变 SS」的环境里，至少文字口径没有自相矛盾），但 **一旦切断通用订阅链接，VLESS 的开放生态红利对用户而言就几乎归零了**：

- **Clash / Mihomo / Shadowrocket / sing-box 全线出局**：你无法将 Firefly 导入 [Clash Verge Rev](/clients/clash-verge/)、Shadowrocket 或 v2rayN，也就失去了自定义 `rules` 精细分流的能力。日常工作中如果你想让 ChatGPT 走美国节点、Claude 走日本节点、公司 Git 走直连、国内网银彻底不碰代理，专属客户端往往只提供粗糙的「智能分流 / 全局模式」开关，一旦内置规则库过时，排查 [特定网站无法打开](/troubleshooting/articles/specific-sites-unreachable) 或 [DNS 劫持与泄漏](/troubleshooting/articles/dns-leak-hijack-fix) 会变得极其被动。
- **软路由与非主流平台受阻**：尽管品牌宣称「不限客户端及设备数量」，但如果没有标准订阅链接，家里的 OpenWrt（OpenClash / Nikki / PassWall2）、Apple TV、游戏主机或 Linux 无桌面服务器几乎无法接入，所谓的「不限设备」实质上被限制在「官方专属客户端覆盖且持续签发证书的常规手机/电脑系统」之内。
- **退出与故障转移成本飙升**：普通订阅机场如果客户端崩了，换个客户端就行；专属客户端一旦遭遇证书掉签、iOS 商店下架或系统升级闪退，用户在等待官方发新版之前完全无计可施（参见 [专属客户端锁定与迁移备选指南](/troubleshooting/articles/client-migration-backup)）。

## 三、零实测截图缺口审计：为何绝不能轻信 `10-19` 表格里的 547Mbps？

在实测证据维度，Firefly 是第二批 10 家品牌中 **证据缺口最典型的一家**。截至 `2026-11-24` 审计日：
1. **未入选 `2026-08-11` 16 家实测压缩包**：本地 `docs/public/images/speedtests/` 目录下没有任何 Firefly 的 `MAI-TEST-BOT` 或 `Miaoko` 原图；
2. **`2026-08-09` 历史档案亲自确认无测速**：原话明确写着「未提供可比的逐地区测速数据」；
3. **仅有主表附带的 `2026-10-19 非晚高峰` 文本表格**：香港 `27ms / 547Mbps`、台湾 `39ms / 135Mbps`、新加坡 `42ms / 445Mbps`、日本 `57ms / 147Mbps`、美国 `143ms / 30Mbps`。

请特别警惕这组 `2026-10-19` 文本数字！不仅因为它是「非晚高峰」且缺失工具、后端、线程和原始截图，更因为它在跨品牌审计中暴露出高度模板化特征——同清单里 15 家品牌的 `10-19` 表格香港全部落在 `21–27ms / 477–548Mbps`，新加坡全部落在 `42–46ms / 383–445Mbps`，甚至还出现了 **Firefly 核心特色只列「覆盖香港、新加坡、日本、美国」四地，但 `10-19` 表格里却多出一行「台湾 39ms / 135Mbps」** 的口径漂移！

## 常见问题

### 为什么在历史资料中会看到「Firefly 萤火虫」和「Firefly」两条记录？它们是同一家机场吗？

是同一家品牌。本站对原始资料做去重审计后确认，主表条目与 2026-08-09 历史档案共用完全一致的品牌入口域名体系、相同的 8 折优惠码 firefly，以及高度重合的 Lite、Plus、Blaze、Nova、年付版与不限时套餐命名，已合并为单一品牌档案管理，仅在后台保留了两组历史参数差异记录。

### Firefly 2026 年 10 月起改用专属客户端后，还能在 Clash 或 Shadowrocket 里导入订阅吗？

按 2026-10-19 更新的主表资料，Firefly 明确标注「专属客户端，下载登录即用（不提供订阅链接）」。这意味着 Clash Verge Rev、Shadowrocket、v2rayN、sing-box 以及 OpenWrt 软路由用户都无法通过标准订阅 URL 导入节点，迁移自由度与自定义分流能力会受到直接限制。

### Firefly 资料里提到的「8 年团队」和「同系关联」可信吗？能当成运营 8 年的老牌机场吗？

不能直接等同。历史档案原话为「现有资料记录（未独立实测）8 年团队」，并未给出具体品牌开业年份或可查证的历史域名记录，因此本站将开业年份标为待核实。同时历史记录披露其与微风网络、飞鸟、一云梯存在同系关系，说明背后可能存在共用运维或上游链路的情况，但不能替代本品牌独立实测。

### Firefly 为什么没有任何本地实测测速截图？2026-10-19 表格里的 547Mbps 能信吗？

Firefly 既未被收录进 2026-08-11 的 16 家 MAI-TEST-BOT 实测压缩包，其 2026-08-09 历史记录也明确写着「未提供可比的逐地区测速数据」。主表附带的 2026-10-19 非晚高峰表格（如香港 27ms/547Mbps）缺乏截图、工具与后端说明，且与同清单其余 14 家数值高度趋同，本站严格定级为 vendor 参考文本，不作为实测采信。

### Firefly 的优惠码 firefly（8 折）能用在 96 元年付版吗？多周期叠加 64 折是怎么算的？

96 元年付版（60GB/月）明确标注「优惠码不适用」。至于历史档案提到的「季 9 / 半 85 / 年 8 折，最高约 64 折」，算法是在 Lite/Plus/Blaze/Nova 年付本身 8 折的基础上，再叠加新用户 8 折码 firefly（0.8 × 0.8 = 0.64）。但 2026-10 主表未再列出季付至三年付周期表，长周期与叠加规则是否仍然有效需以实时结账页为准。

### Firefly 支持微信支付吗？对国内用户付款有什么限制？

依据 2026-08-09 历史资料，Firefly 明确标注支付方式为「支付宝 / USDT（无微信）」。如果该支付配置延续至今，习惯仅用微信付款的用户会面临不便；同时品牌资料未公开退款条款，不支持退款或仅退余额的风险均处于待核实状态。

### Firefly 汇总表写着「免翻墙访问官网」，为什么评测页仍然把官网标为待核实？

因为原始品牌清单只提供了推广注册地址，从未附带任何独立的、不含推广参数的品牌官方主域名。依据本站审计规则，绝不将推广链接伪装成官方网站，因此官网主域统一保持「待核实」，且本评测正文不嵌入任何推广域名或外链。

### 在没有任何本地实测截图的前提下，普通用户该怎么评估 Firefly？

建议采取「最低单月试错 + 不碰长周期」原则。由于无本地速度图与流媒体/AI 实测图，且 2026-10 起改用封闭专属端，切勿被历史资料里的两年/三年付 64 折低价吸引而一次性预付数百上千元；如果确有兴趣，最多用 25 元月付 Lite（叠加优惠码若生效约 20 元）自测晚高峰与专属端稳定性。
