faq:
  - q: 日常上网应该选 Rule 规则模式、Global 全局模式还是 Direct 直连模式？
    a: 日常 99% 的使用时间都应保持在 Rule 规则模式，它可以让国内网站走本地宽带直连、海外网站按规则走代理节点。Global 全局模式会让几乎所有非局域网流量强行绕道海外节点，导致国内视频和网银变慢且消耗大量倍率流量，仅适合临时排障一两分钟；Direct 直连模式则全部直连，用于快速测试本地宽带自身是否正常。
  - q: 切换为 Global 全局模式后，为什么连国内网站都打不开或网页反而明显变慢？
    a: 常见有两个原因：一是切换到全局模式后，客户端需要从最顶层的 GLOBAL 策略组单独选定一个有效海外节点，许多默认配置文件在 GLOBAL 组里初始停留在 DIRECT 或失效节点上，导致流量卡死；二是就算选定了海外节点，国内高清图片和视频也会被迫绕行境外服务器再回国，延迟和丢包率都会明显上升。
  - q: 策略组里的 url-test 自动选择和 fallback 故障转移有什么区别，用哪个更稳？
    a: url-test 会定期向测速 URL 探测延迟并自动切换到当前毫秒数最低的节点，适合纯网页浏览但晚高峰容易频繁跨区跳 IP；fallback 则严格按照节点列表从上到下的优先顺序保持固定出口，只有排在首位的节点完全超时不可用时才顺延切换到下一个，对 AI 工具、长连接办公和登录态敏感站点更稳妥。
  - q: 为什么不建议直接修改订阅下载到本地的原始 YAML 文件来添加个人规则？
    a: 因为每次在客户端点击更新订阅时，机场远端下发的新配置文件会直接覆盖本地原始 YAML，你手工添加的个人规则和 DNS 参数会全部丢失。正确做法是保留原订阅纯净不变，通过客户端提供的 Merge 覆写或 Script 脚本功能，在更新后自动将局部修改注入最终配置。
  - q: 修改了 Clash 的 Profile 覆写脚本或扩展配置导致内核崩溃打不开网页怎么回滚？
    a: 切勿直接卸载软件或强删系统网络注册表。只需右键当前订阅配置取消勾选或停用刚刚启用的 Merge 与 Script 覆写项，在关闭系统代理状态下重新更新一次原始订阅，再点击重启内核即可在 30 秒内完全还原到修改前状态。
  - q: 为什么 YAML 覆写配置里明明肉眼看着对齐了，保存后内核还是报语法错误？
    a: YAML 解析器对格式极其严苛，只允许使用半角空格缩进（通常为两格），一旦混入 Tab 制表符、冒号后缺少半角空格、或者粘贴了中文全角引号和逗号就会触发 unmarshal errors。写入覆盖前应在终端用只读 YAML 校验命令先行检查语法树。
  - q: 开启局域网共享 allow-lan 后会带来什么安全隐患，应该怎么正确配置？
    a: 开启 allow-lan 后客户端的混合端口会从仅监听本机 127.0.0.1 变为监听局域网网卡，如果当前处于公共 Wi-Fi、学校内网或开启了公网端口映射，同一网络下的陌生设备就可能扫描并蹭用你的代理端口甚至消耗套餐流量。在公共网络环境下应关闭 allow-lan，仅在家庭信任局域网临时共享时开启并绑定内网访问控制。

# Clash 配置教程：三大运行模式、策略组设计、Profile 覆写与 YAML 校验

> **核心结论（Answer-First）**：掌握现代 Clash 系客户端（包括 **[Clash Verge Rev](/clients/clash-verge/)**、**FlClash**、**Clash Nyanpasu**、**[Clash Meta for Android](/clients/clash-meta/)** 与 **Stash**）的配置核心，关键在于抓牢三件事：**「日常固定使用 Rule 规则模式」**、**「按业务属性拆分布局 select / fallback / url-test 策略组」**、以及 **「通过局部 Merge 覆写而非直接改写原订阅文件来守护配置稳定性」**。任何修改核心配置与覆写脚本的操作，事前必须保留可运行的原始 Profile 快照，保存前先做只读 YAML 语法校验，一旦报错立即停用覆写并恢复原始订阅即可 30 秒安全回滚。

如果你尚未完成订阅链接导入，请先阅读前序指南 [机场订阅教程](/guides/subscriptions/)。若已经能够正常拉取节点列表，请按本教程逐层梳理核心运行逻辑。

## 一、三大运行模式（Rule / Global / Direct）底层机制与误区

打开任意 Clash 或 **[Mihomo 内核](/clients/mihomo/)** 客户端的「代理（Proxies）」界面，顶部都会出现三个模式切换标签。很多新手以为“开了全局才算彻底翻出去”，这是导致国内网银瘫痪与套餐流量暴毙的最大误区。

| 运行模式 | 核心数据包转发机制 | 国内网站与微信/网银走向 | 海外目标网站走向 | 适用场景与常见致命误区 |
| :--- | :--- | :--- | :--- | :--- |
| **Rule（规则模式）** | **【日常唯一主力推荐】** 读取配置文件底部的 `rules` 列表，自上而下逐行匹配域名、规则集或 GeoIP | 命中 `GEOSITE,cn` / `GEOIP,CN` 或局域网段，**走本地宽带直接连接（`DIRECT`）** | 命中海外或兜底规则，**交由你选定的地区代理策略组转发** | **99% 时间必须停留在 Rule 模式**；既能保证国内视频满速，又能省去多余倍率流量 |
| **Global（全局模式）** | 跳过所有业务域名分流规则，直接将非局域网保留段的全部请求统一交给顶层 **`GLOBAL` 策略组** | **被迫绕行海外节点再回国**，国内访问延迟翻倍且高速消耗机场流量 | 全部走 `GLOBAL` 策略组当前选中的单一出口节点 | **仅用于 1–2 分钟临时排障对照**（验证某冷门海外站点是否因规则漏写才打不开）；**经典陷阱**：切到全局后忘记去 `GLOBAL` 组里选中海外节点，导致停在 `DIRECT` 或失效节点上全网打不开 |
| **Direct（直连模式）** | 绕过代理转发逻辑，所有外部连接直接通过本地物理网卡直出 | 走本地宽带直接连接 | 走本地宽带直接连接（受阻站点无法打开） | **用于 5 秒快速对比排障**：无需彻底关闭客户端或改系统代理，即可一键验证当前故障是不是机场节点引起的 |

### 为什么不建议用“直接关闭系统代理”代替“切 Direct 模式排障”？
当客户端开启了底层接管（例如 TUN 模式）时，单纯在界面切换为 `Direct` 可以让内核维持监听而不把本地 DNS 缓存一下子弄乱，帮你立刻区分究竟是 **本地宽带断网** 还是 **机场节点超时**；排障结束后只要点回 `Rule` 即可瞬间恢复分流。关于更深层的规则匹配顺序，可延伸阅读 [代理分流规则配置指南](/guides/split-routing/)。

## 二、策略组（Proxy Groups）类型拆解与科学设计

机场面板生成的 Clash YAML 通常会包含多个策略组。理解 `select`、`url-test`、`fallback` 与 `load-balance` 四种核心机制的差异，能帮你直接避开“节点自己乱跳导致 AI 封号”与“网页视频断流”。

| 策略组类型 | 节点切换决策逻辑 | 延迟稳定性与流量特性 | 最佳适用业务场景 | 潜在风险与避坑提示 |
| :--- | :--- | :--- | :--- | :--- |
| **`select`（手动选择）** | 由用户人工点选固定某一条具体节点，或指向下级某个子策略组 | 出口 IP 完全固定不变，不产生后台额外测速流量 | **AI 工具（ChatGPT/Claude）、网银登录、SSH 长连接、排障验证** | 若当前手动选中的单台落地机突然维护宕机，需要人工切换到同地区下一个编号 |
| **`url-test`（自动测速）** | 按 `interval`（如每 300 秒）向 `url` 发起 HTTP 204 测速，自动切换至最低延迟节点 | 理论上延迟最低，但会持续产生少量后台测速请求 | **普通网页浏览、YouTube 视频加载、GitHub 下载** | 若 `tolerance` 容差设得太小，晚高峰抖动会导致出口 IP 在不同机房/地区间高频乱跳，**严禁直接用于 AI 账号或敏感流媒体登录** |
| **`fallback`（故障转移）** | 严格按 `proxies` 列表从上到下的顺序检测，只要第 1 条节点存活就死守第 1 条，只有彻底超时才切向第 2 条 | **兼顾高可用与 IP 稳定性**，不会因为 10ms 延迟波动而乱跳节点 | **日常主力综合组、远程办公会议、需要稳定出口的代理组** | 排在最前面的节点未必永远是速度最快的，需人为把主力优质节点放在列表靠前位置 |
| **`load-balance`（负载均衡）** | 按轮询（round-robin）或一致性哈希（consistent-hashing）把不同连接分散到多个节点 | 理论上多连接并发吞吐上限更高 | **多线程下载、大并发爬虫或同出口 IP 无要求的并发请求** | 使用 `round-robin` 时同一个网页的不同资源会从不同国家 IP 发出，极易触发安全校验踢出登录态 |

### 推荐的分层策略组架构（兼顾极速与防风控）
1. **顶层主力入口组（如 `🚀 节点选择`，类型 `select`）**：内部挂载「香港主力（`fallback`）」、「日本/新加坡备选（`url-test`）」以及手动单节点，平时选择低延迟 `1x` 倍率节点保障日常网页秒开。
2. **AI 独立固定组（如 `🤖 AI 专线`，类型 `select`）**：只纳入新加坡、日本、美国等支持 OpenAI / Anthropic 的节点，**人工固定一条稳定节点**，彻底避开自动测速乱跳引发的风控与香港节点地区封锁（实测差异见 [AI 与流媒体兼容专题](/ai-media/)）。
3. **流媒体地区组（如 `🎬 流媒体`，类型 `select`）**：按片库归属手选台湾、新加坡或日本正常节点，避开测速显示 `0B` 或出现地区漂移的异常节点（参见 [单地区节点超时与 0B 解读](/troubleshooting/articles/nodes-partial-region-timeout)）。

## 三、核心基础参数：`mixed-port`、`allow-lan` 与性能开关

在阅读或微调 Clash / Mihomo YAML 头部基础配置时，以下四个关键字段直接决定本地端口安全与响应速度：

1. **混合监听端口（`mixed-port: 7897` 或 `7890`）**：
   同时在本地回环地址监听 HTTP、HTTPS 与 SOCKS5 协议请求。大多数现代客户端（如 Clash Verge Rev 默认使用 `7897`，部分旧配置使用 `7890`）只需这一个端口就能接管系统代理和终端环境变量。如果本机同时装有多个代理软件导致端口占用报错，可在设置里修改为 `17897` 等未冲突端口。
2. **局域网共享与绑定安全（`allow-lan` 与 `bind-address`）**：
   - 默认值 `allow-lan: false` 表示端口仅对本机 `127.0.0.1` 开放，安全系数最高。
   - 当你需要让局域网内的手机、Switch 或另一台电脑通过填你电脑内网 IP 共享代理时，才临时把 `allow-lan` 设为 `true` 并建议配合 `bind-address` 限定或只在可信家庭 Wi-Fi 下开启。
   - **安全警告**：在咖啡厅、酒店、校园网等公共局域网下切勿长期开启 `allow-lan: true` 且无密码鉴权（`authentication`），否则同一网段内的任意主机都可能通过扫描端口白嫖你的代理通道与流量。
3. **TCP 并发与统一延迟（`tcp-concurrent` 与 `unified-delay`）**：
   - `tcp-concurrent: true` 允许内核对解析出多个 IP 的域名并发发起 TCP 握手，取最快响应的一路建立连接，对多 CDN 节点域名提速明显。
   - `unified-delay: true` 让测速计算剔除不同代理协议的握手次数差异，得出的延迟数值更接近真实传输体验，适合在 Mihomo 系客户端中开启。
4. **开机自启与静默启动（Silent Start）**：
   在桌面端设置中开启“静默启动”可以让软件开机后自动缩入系统托盘而不弹大窗口。但**切记先核对“关闭软件时是否自动关闭系统代理”**，确保即使电脑异常关机或你主动退出客户端，也不会在系统注册表留下死端口导致开机断网（详见 [已连接或关代理后网页打不开排查](/troubleshooting/articles/connected-no-internet)）。

## 四、Profile 覆写（Merge / Script）合并风险与 YAML 缩进校验

为了在每次更新订阅后不丢失自己补充的分流规则或 DNS 优化参数，Clash Verge Rev、Clash Nyanpasu、Stash 等现代客户端均提供了 **「Profile 覆写（Override）」** 体系。用得好它是最强工具，用错则是内核崩溃（`Mihomo 核心启动失败`）的头号源头。

### 1. `Merge（YAML 合并）` vs `Script（JS 脚本）` 怎么选？
- **Merge（YAML 局部合并，新手与大多数场景首选）**：只需写几行你希望新增或覆盖的键值，客户端会在每次应用配置时把它们合并到订阅 YAML 上。支持使用 `prepend-rules`（把你的自定义规则插在原规则最顶部优先匹配）、`append-rules` 或局部替换 `dns` 段落。
- **Script（JavaScript 动态脚本，进阶专用）**：通过 `main(config)` 函数编程式修改节点过滤、正则分组、策略组重构。灵活性极高，但一旦脚本里有变量 `undefined`、空指针或引用了原订阅不存在的策略组名，**会导致整个配置生成失败**，需要用客户端的日志功能定位报错行数。

### 2. 覆写合并的四大高风险踩坑点
1. **错误地用“全量网络配置”覆盖局部字段**：不要从网上随便复制一份长达几百行的陌生全套 YAML 塞进全局 Merge，里面往往包含失效的规则集地址、冲突的 `listen` 端口或与当前 Mihomo 内核版本不兼容的过时参数。
2. **策略组名称引用不存在**：例如你在 `prepend-rules` 里写了 `- DOMAIN-SUFFIX,openai.com,🤖 AI`，但机场原订阅里策略组叫 `💬 OpenAI` 而不叫 `🤖 AI`。保存瞬间内核就会直接报 `proxy group 🤖 AI not found` 并拒绝启动。
3. **YAML 缩进与全角字符灾难**：YAML 严格依赖 **两个半角空格缩进**，**绝对禁止使用 `Tab` 键**，所有冒号 `:` 与列表短横线 `-` 后面必须跟一个半角空格。此外，节点名称或策略组名称若包含特殊冒号或 emoji，在手动写规则时建议合理核对字符串完整匹配。
4. **多覆写文件相互打架**：同时启用“全局扩展配置”和“单个订阅的局部覆写”修改同一块 `dns` 或 `rules` 时，合并顺序可能产生意料之外的覆盖结果。原则上只保留一套清晰生效的覆写入口。

### 3. 只读命令：修改或启用覆写前的 YAML 语法校验与端口监听核查
在你准备应用一份本地保存的 YAML 片段或测试导出配置是否存在缩进/制表符错误时，可以先在终端运行 **只读语法检查命令**（不会修改任何配置文件，也不会连接网络）：

```powershell
# OS: Windows (PowerShell)
# 目的: 只读检测指定 YAML 文件是否误含 Tab 制表符或中文全角标点符号（零修改风险）
# 请将路径替换为你本地保存的测试片段路径
Select-String -Path ".\test-override.yaml" -Pattern "`t|：|，"
```
**输出解读**：如果有任何输出行，说明文件里混入了 `Tab` 制表符或中文全角冒号/逗号，直接放入 Clash 覆写必然报错，请先改回半角空格与英文半角符号。

```powershell
# OS: Windows (PowerShell)
# 目的: 只读确认客户端本地混合监听端口（如 7897）是否已成功拉起，且未与其他软件端口冲突
# 风险: 纯只读网络端口状态查询，不修改任何系统设置
Get-NetTCPConnection -LocalPort 7897 -State Listen -ErrorAction SilentlyContinue | Select-Object LocalAddress, LocalPort, OwningProcess
```
**输出解读**：如果看到 `LocalAddress` 为 `127.0.0.1` 且能查到 `OwningProcess` 进程号，说明内核已正常启动并独占监听该混合端口；若 `LocalAddress` 显示 `0.0.0.0` 则代表当前开启了 `allow-lan: true` 局域网共享，处于公共网络环境时应及时关闭以防端口被同网段陌生设备扫描蹭用；若完全无输出，则说明核心根本未能成功拉起（或配置了其他端口号），需去日志面板查看内核启动报错。

```bash
# OS: macOS / Linux (Terminal)
# 目的: 利用系统 Ruby 内置解析器做只读 YAML 结构语法检查
# 风险: 纯只读文件解析，不会写入或更改原配置
ruby -e "require 'yaml'; YAML.safe_load(File.read('test-override.yaml')); puts 'YAML Syntax OK'"
```
**输出解读**：屏幕打印 `YAML Syntax OK` 代表缩进与引号闭合完全合法；若输出 `psych.rb: ... syntax error` 或 `did not find expected key` 并给出具体行号（如 `line 14`），直接对照行号修好缩进即可，无需启动内核反复试错。

### 4. Merge 与 Script 安全局部覆写参考范式（防冲突写法）
编写 `Merge` 扩展配置时，只需声明需要追加或微调的局部键值，绝不要粘贴全套外部模板。例如仅需把某条公司内网域名置顶直连、把 AI 工具域名导向固定分组时，推荐使用 `prepend-rules` 前置插入（前置规则永远优先于机场原订阅规则匹配）：

```yaml
# 示例：Clash Verge Rev 局部 Merge 覆写安全片段（仅作结构演示，策略组名须与你订阅一致）
prepend-rules:
  - DOMAIN-SUFFIX,corp.example.invalid,DIRECT
  - DOMAIN-SUFFIX,openai.com,🤖 AI 专线
```

若进阶用户使用 JavaScript `Script` 脚本对节点进行筛选或重组策略组，务必在 `main(config)` 函数开头加入防御性边界检查：先判断 `config`、`config.proxies` 与 `config.rules` 数组是否存在且非空，再执行过滤或 `unshift` 操作；否则一旦机场某次临时返回空列表，未做空值保护的脚本会抛出 `TypeError` 并直接阻断所有订阅加载。

## 五、日志面板、连接面板与配置异常排查对照矩阵

改完模式、策略组或覆写后，不要靠“盲猜感觉打不开”来判断问题，而是直接利用客户端内置的两个观测工具定位真实走向：

1. **连接（Connections）实时追踪面板**：
   - 在客户端打开「连接」界面，输入你想测试的域名（如 `openai.com` 或某个国内网银域名）过滤。
   - 重点看三列：**Rule（命中规则）**、**Chains（实际出站节点链）** 与 **Upload/Download（实时字节流）**。如果某国内网站显示走了海外节点，说明规则顺序漏配或被全局模式接管；如果海外请求根本没出现在列表里，说明请求没进代理端口（可能是系统代理没开或需要开 TUN 模式）。
2. **日志（Logs）级别过滤排查**：
   - 排障时将日志级别临时切为 `Info` 或 `Debug`，观察启动瞬间是否有 `error` 或 `warning` 字样（常见如 `can't download rule-provider`、`dns listen failed`、`proxy not found`）。
   - 若启动即闪退或内核报错弹窗，可直接对照 [Mihomo 核心启动失败与 YAML 报错排查](/troubleshooting/articles/clash-verge-mihomo-yaml-fail) 定位具体字段错误。

| 异常症状与报错信号 | 最可能的核心诱因 | 10 秒低风险自查动作 | 对应修正与后续处置路径 |
| :--- | :--- | :--- | :--- |
| **切到 `Global` 全局模式后，连百度和 B 站也彻底打不开** | 切入全局后忘记去 `GLOBAL` 策略组手动点选可用海外节点，默认停留在无效节点或配置异常上 | 打开代理面板展开最顶层的 `GLOBAL` 组查看当前选中项及测速状态 | 在 `GLOBAL` 组中点选一条可用低延迟节点测试，排障完立刻切回 **`Rule`** 模式 |

### 进阶专题延伸规划（持续深入方向）
在跑通本页基础模式与局部覆写后，站内后续可按以下细分场景继续深化参数调优：
- **端口与共享安全**：进一步核查 `mixed-port` 端口占用、`allow-lan` 与 `bind-address` 局域网访问控制边界。
- **并发与测速精准度**：评估 `tcp-concurrent`（TCP 并发握手）与 `unified-delay` 对多 IP 域名与真实协议延迟测算的改善。
- **安全模式与脚本隔离**：系统掌握扩展脚本异常时的安全模式脱困流程，确保任何覆写实验都具备可瞬间回退的安全垫。

## 六、高风险修改警示与 30 秒标准化回滚方案

> [!WARNING]
> **修改核心覆写、DNS 参数或 Script 脚本属中高级风险操作**：
> 1. 动手编辑全局扩展配置、全局扩展脚本或 DNS 覆写前，**务必先右键当前可用的订阅卡片导出或复制备份一份纯正原始文件**。
> 2. **严禁通过关闭 Windows Defender 或第三方杀毒软件**来解决内核启动报错或文件读写问题。
> 3. 如果配置失败引发全部网页打不开，切勿慌张去强行卸载重装软件或删除系统注册表。

**一旦保存配置后遇到内核崩溃、YAML 语法报错或全网断流，严格按以下 4 步执行 30 秒回滚：**

1. **停用刚启用的覆写与脚本（安全模式归零）**：
   - 打开 Clash Verge Rev「订阅（Profiles）」面板，右键当前激活的订阅卡片，取消勾选或清除你刚刚挂载的 **「扩展覆写（Merge）」** 与 **「扩展脚本（Script）」**。
   - 同时检查左侧设置或订阅页顶部是否启用了 **「全局扩展配置 / 全局扩展脚本」**，有的话一并取消启用。
2. **关闭系统代理并重拉原始干净配置**：
   - 先把软件左侧的 **「系统代理（System Proxy）」** 和 **「TUN 模式」** 开关暂时全部关闭（确保能通过本地宽带直连访问面板）。
   - 在「订阅」列表点击当前订阅的更新图标，从服务商远端重新拉取一份未受本地修改污染的原始 YAML 配置。
3. **重启核心（Restart Core）并清连接池**：
   - 进入客户端 `设置 -> 内核（Clash Core）` 点击重启内核，或者彻底退出客户端后重新打开。
   - 点击连接面板的关闭全部连接（Close All）清掉错误缓存。
4. **切回 Rule 模式逐项验证恢复**：
   - 在「代理」页顶部确认已回到 **「Rule（规则模式）」**，手动选中一条确认正常的节点后重新开启「系统代理」，测试国内外双站访问是否恢复正常。

## 七、常见问题

### 日常上网应该选 Rule 规则模式、Global 全局模式还是 Direct 直连模式？
日常 99% 的时间都请坚定保持在 **Rule 规则模式**，这样国内站点直连本地宽带高速响应、海外网站按规则走代理节点，既省流量又不影响微信和网银。`Global` 全局模式仅用于怀疑规则漏写时的 1–2 分钟临时排障对比；`Direct` 直连模式用于在不断开客户端的情况下 5 秒验证本地宽带本身有没有断网。

### 切换为 Global 全局模式后，为什么连国内网站都打不开或网页反而明显变慢？
最常见的误区是切到 `Global` 后，没有进入顶层 `GLOBAL` 策略组里手动选中一条可用的海外节点，导致流量停留在默认选项或失效节点上从而全网卡死。其次，即使选对了海外节点，由于 `Global` 跳过了国内分流规则，访问国内高清视频和图片也会先绕出国再绕回来，网速自然急剧变慢且浪费倍率流量。

### 策略组里的 url-test 自动选择和 fallback 故障转移有什么区别，用哪个更稳？
`url-test` 会周期性测速并自动追随当前延迟最低的节点，适合纯看视频刷网页，但在晚高峰波动时容易反复切换出口机房；`fallback` 会严格按列表顺序死守排在首位的节点，只有当首选节点真正超时不可用时才顺延切换到下一条。对于稳定性要求高或需要保持登录态的办公与 AI 场景，`fallback` 或 `select` 手动选点明显比 `url-test` 更稳妥。

### 为什么不建议直接修改订阅下载到本地的原始 YAML 文件来添加个人规则？
因为任何远程订阅在下次手动或定时更新时，都会用服务器新下发的配置整份覆盖掉本地原文件，你在原文件里辛辛苦苦加的规则和调整会瞬间清零。正确做法是始终让原始订阅保持只读干净，通过客户端自带的 `Merge` 局部合并或 `Script` 脚本功能在外部注入你的自定义规则。

### 修改了 Clash 的 Profile 覆写脚本或扩展配置导致内核崩溃打不开网页怎么回滚？
不需要删软件或重装驱动。立刻在客户端中取消启用你刚挂载的 Merge 覆写文件、JS 脚本以及全局扩展配置，暂关系统代理开关后重新更新一次原始订阅，最后点击重启核心（Core）即可在 30 秒内 100% 回到崩溃前的正常状态。

### 为什么 YAML 覆写配置里明明肉眼看着对齐了，保存后内核还是报语法错误？
肉眼对齐极易被编辑器自动插入的 `Tab` 制表符、行尾隐藏空格或中文全角冒号/引号欺骗。YAML 规范严禁使用 `Tab` 缩进，所有层级只能用半角空格，冒号与短横线后必须有空格。修改较长覆写前可用上文的终端只读校验命令先行扫一遍格式再导入。

### 开启局域网共享 allow-lan 后会带来什么安全隐患，应该怎么正确配置？
把 `allow-lan` 设为 `true` 相当于把你的本地代理端口向同一路由器下的所有设备敞开。如果电脑连接的是校园网、公司内网、酒店或咖啡厅公共 Wi-Fi，同一局域网内的其他人可能直接连上你的端口消耗你的机场流量，甚至带来审计风险。公共网络下务必保持关闭，仅在可信家庭路由环境需要让手机或主机走电脑代理时临时开启。
