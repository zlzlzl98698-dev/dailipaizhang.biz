# 更新订阅失败：HTTP 401/403/404/503 与被重定向排查指南

## 核心结论（Answer-First）

更新订阅报 `401/403/404/503` 或被重定向，说明请求已抵达远端或 CDN，故障出在鉴权、风控、路由或负载：`401` 多为 Token 失效重置；`403` 常因 Cloudflare WAF 盾拦截或拒绝 UA；`404` 多为域名变更或复制缺字；`502/503` 指向后端过载；`301/302` 需核对是否跳往新域名或登录页。

## 故障现象

各客户端的典型报错信息通常直接携带状态码或协议层错误字样：

- **Clash Verge Rev / Mihomo**：弹出 `Failed to update profile: status code 403`、`401 Unauthorized`、`404 Not Found`、`Get "...": stopped after 10 redirects`，或拉取到拦截页后报 `cannot unmarshal !!str <!DOCTY...`。
- **v2rayN**：底部日志区输出 `远程服务器返回错误: (403) 已禁止`、`远程服务器返回错误: (503) 服务器不可用` 或 `未能解析订阅地址（404）`。
- **Shadowrocket（小火箭）**：弹出 `Subscription update failed: HTTP 403`、`HTTP 404` 或提示 `Invalid data`（常见于被 `302` 重定向到了官网 HTML 登录页）。
- **OpenClash / PassWall / Nikki**：系统日志显示 `Download Profile Failed: The requested URL returned error: 403/503`。

## 先做 3 个低风险检查

1. **对比“直连更新”与“通过代理更新”**：如果你的机场订阅域名在本地运营商网络遭干扰，直连会失败，此时需借用尚可用的备用节点开启“通过代理更新”；反之，若你当前挂着的代理节点属于被滥用的公共机房 IP，Cloudflare 会直接给该出口弹 `403` 验证码页，改回 **“直连更新”** 往往秒成功。
2. **核对订阅链接是否完整且未填错成官网首页**：检查粘贴时是否漏掉末尾 Token 字符、混入了中文标点或换行空格，尤其注意区分“面板网页登录地址（含 `#/login` 或 `/dashboard`）”与真正的“API 订阅下发地址”。
3. **验证机场网页后台当前可访问性与服务政策**：用浏览器打开服务商最新有效网址，确认面板没有发布“更换独立订阅域名”、“临时防御维护”或“停用通用订阅改用专属客户端”的公告。

## 深入拆解：Cloudflare 盾、客户端 `User-Agent` 差异与 `302` 跳转内幕

在所有 HTTP 状态码中，`403` 与 `301/302` 最容易让用户摸不着头脑，背后主要有三套服务端机制在起作用：

1. **Cloudflare WAF / 五秒盾（Managed Challenge & Bot Fight Mode）**：
   - 大多数机场为了隐藏源站 IP、抵御同行 DDoS 攻击，会把订阅域名套在 Cloudflare CDN 后面。一旦管理员在遭遇攻击时不小心把全站安全级别调成 `Under Attack`（五秒盾）或开启了免费的 **Bot Fight Mode**，Cloudflare 会在响应头里返回 `HTTP/2 403` 并附带 `cf-mitigated: challenge` 与一串 `<!DOCTYPE html><title>Just a moment...</title>` 脚本。
   - 普通浏览器能运行 JS 算出质询 Cookie 后放行，但 Clash Verge Rev、v2rayN、Shadowrocket 的订阅拉取器并不是完整浏览器，无法执行 JS 质询或点选验证框，于是全部卡在 `403` 或报 YAML 解析 HTML 失败。
2. **客户端 `User-Agent`（UA）决定下发格式与放行权限**：
   - 现代机场面板（如 V2Board、Xboard、SSPanel 等）普遍采用“单一订阅 URL 按 UA 动态渲染配置”的设计——同一个链接，面板只有认出你的客户端身份，才知道该给你吐 YAML 还是 Base64：

| 客户端 / 请求工具发出的典型 `User-Agent` | 服务端面板通常返回的内容格式 | 常见 `403` 或解析翻车原因 |
| :--- | :--- | :--- |
| `clash-verge/v2.x`、`ClashMeta`、`mihomo/1.x` | 含策略组、分流规则与新协议（VLESS/Hysteria2）的完整 YAML | 若填成了极老的 `ClashForWindows` UA，部分面板为兼容旧内核会自动剔除 Reality 与 Hysteria2 节点 |
| `Shadowrocket/2.x` | Base64 编码的多协议节点 URI 列表（附带 `STATUS=` 剩余流量头） | 若被 302 跳转到网页，小火箭解码 HTML 失败报 `Invalid data` |
| `v2rayNG/1.x`、`v2rayN/6.x`、`v2rayN/7.x` | Base64 编码的标准节点串 | 个别面板开启严格 UA 白名单时漏加新版前缀导致返回 `403` |
| `SFA`、`SFI`、`sing-box` | sing-box 专用结构化 JSON 配置文件 | 旧面板未适配 JSON 模板时可能退回 Base64 导致客户端导入报错 |
| `Go-http-client/1.1`、`curl/8.x`、`python-requests` | **高概率直接拒绝（返回 `403` 或空文本）** | 服务端 WAF 将无特征默认编程库 UA 视为恶意爬虫或测速扫描器直接封禁 |

3. **`301 / 302 / 307` 重定向的三类真实去向**：
   - **良性新域名迁移（`301` / `307` 跳往新订阅域并保留路径参数）**：服务商旧订阅域名即将弃用，在网关层把 `https://old-sub.example.invalid/api/...` 跳转到 `https://new-sub.example.invalid/api/...`。但部分客户端为了防 Token 泄露，跨主域名跳转时不携带特定请求头或限制跳转层级，最好直接去后台复制新链接。
   - **鉴权失效跳登录页（`302 Found -> Location: /#/login`）**：Token 已被重置或套餐过期，部分前端路由框架不返回标准 `401`，而是把所有未授权路径统一 `302` 重定向到网页登录页，客户端跟着跳过去拉回一堆 HTML 代码。
   - **内网网关劫持跳转（`302` 跳往校园网/酒店认证页或反诈提示页）**：本地 Wi-Fi 尚未完成网页登录认证，或本地运营商对目标域名实施了 HTTP 重定向阻断。

## 分层原因排除

### 本地系统与网络

- **高频刷新触发本地 IP 速率限制（Rate Limit）**：短时间内连续狂点十几次“更新订阅”，或软路由与手机、电脑多台设备设置了每 5 分钟自动并发拉取，触发远端 Nginx / Cloudflare 的 IP 限流（返回 `429` 或 `403`/`503`）。
- **企业内网或校园网网关 URL 过滤**：公司深信服/帕拉迪等上网行为管理网关识别到 URL 中含有 `subscribe` 或长串随机 Token，直接伪造回复 `403 Forbidden`。

### 客户端与核心配置

- **自定义 User-Agent 填写不当或留空**：用户在客户端订阅设置里手动改乱了 `User-Agent` 字段（例如带了非法空格或换成了浏览器 UA `Mozilla/5.0`），导致面板把它当成网页访问返回了仪表盘 HTML，或因非白名单 UA 返回 `403`。
- **专属客户端强制锁定**：部分品牌在运营中途变更策略（如关闭第三方通用订阅通道，仅允许自研封装客户端通过私有加密接口拉取节点），此时原有的 Clash / v2rayN 订阅链接会永久返回 `403` 或 `404`。

### DNS 与路由分流

- **订阅域名命中本地 `REJECT` 或脏出口 IP**：若客户端正在运行的规则集把订阅域名误归入拦截列表，或“通过代理更新”选中的节点出口正被目标站点防火墙封禁，就会出现持续 `403`。
- **本地 DNS 缓存滞留旧源站 IP**：服务商已完成服务器迁云，本地路由器仍缓存着已退租的旧机器 IP，请求打过去自然报 `404` 或 `502 Bad Gateway`。

### 远端订阅与节点

- **`401 Unauthorized`**：用户改过官网登录密码触发联动重置 Token、手动点过“重置订阅信息”、账号因共享超限被封禁或套餐到期停机。
- **`403 Forbidden`**：Cloudflare WAF 人机质询误伤、服务端 UA 白名单拦截、或节点出口国家在面板侧被禁止访问订阅接口（例如部分机场禁止海外 IP 拉取国内中转订阅以防爬虫）。
- **`404 Not Found`**：面板重构更换了订阅路由路径、专用订阅子域名已废弃、或链接末尾缺失字符。
- **`502 Bad Gateway` / `503 Service Unavailable`**：机场后端数据库/PHP/Go 面板进程假死、遭遇流量攻击清洗中，或 Cloudflare 回源连接超时。

## 操作路径

### 步骤 1：在终端使用脱敏 URL 确认真实状态码、CDN 盾标识与跳转去向

以下命令统一使用标准脱敏占位地址 `https://sub.example.invalid/api/v1/client/subscribe?token=REDACTED`，本地自测时请替换为你的实际链接，**切勿将含真实 Token 的命令历史或输出发到公开群聊**。

**命令 A：模拟客户端 UA 探测状态码与 Cloudflare 响应头（macOS / Linux / OpenWrt）**

- **适用 OS**：macOS、Linux、OpenWrt（SSH 终端）
- **目的**：显式携带 `clash.meta` UA 仅拉取响应头，识别状态码、`cf-mitigated` 质询标志、`cf-ray` 追踪号与 `location` 跳转目标。
- **风险等级**：低风险（只读头部探测，不落地保存配置，不修改系统设置）。
- **预期输出解读**：
  - 若看到 `HTTP/2 200` 且 `subscription-userinfo:` 存在，说明直连 + 该 UA 完全正常；
  - 若看到 `HTTP/2 403` 伴随 `cf-mitigated: challenge` 与 `server: cloudflare`，100% 实锤为 Cloudflare 五秒盾拦截；
  - 若看到 `HTTP/2 301` 或 `302`，观察 `location:` 后面的地址是新订阅域名还是 `/login` 登录页。

```bash
curl -I -sS -A "clash.meta/1.18.0" \
  "https://sub.example.invalid/api/v1/client/subscribe?token=REDACTED" \
  | grep -iE "^(http/|location:|server:|cf-ray:|cf-mitigated:|content-type:|subscription-userinfo:)"
```

**命令 B：禁止自动跳转捕获原始状态码与响应头（Windows PowerShell）**

- **适用 OS**：Windows 10 / Windows 11
- **目的**：设置 `-MaximumRedirection 0` 阻止 PowerShell 偷偷跟着 `302` 跳到网页返回假 `200`，精准抓出第一跳状态码与 WAF 头。
- **风险等级**：低风险（只读网络请求）。
- **预期输出解读**：对照输出的 `Status`、`CfMitigated`、`CfRay` 与 `Location` 即可判断是盾拦截（`403` + `challenge`）、鉴权吊销（`401` 或跳 `/login`）还是后端宕机（`502/503`）。

```powershell
$u = "https://sub.example.invalid/api/v1/client/subscribe?token=REDACTED"
try {
  $r = Invoke-WebRequest -Uri $u -Method Head -MaximumRedirection 0 -Headers @{"User-Agent"="clash.meta/1.18.0"} -ErrorAction Stop
  [PSCustomObject]@{ Status = $r.StatusCode; ContentType = $r.Headers["Content-Type"]; Server = $r.Headers["Server"] }
} catch {
  $resp = $_.Exception.Response
  if ($resp) {
    [PSCustomObject]@{
      Status      = [int]$resp.StatusCode
      CfMitigated = $resp.Headers["cf-mitigated"]
      CfRay       = $resp.Headers["cf-ray"]
      Location    = $resp.Headers["Location"]
      Server      = $resp.Headers["Server"]
    }
  } else {
    Write-Output $_.Exception.Message
  }
}
```

> **iOS / Android 说明**：手机端切勿把含真实 Token 的订阅链接粘贴到不明第三方在线 HTTP 检测站。可直接打开手机浏览器隐身窗口访问**去掉路径后的面板主域名**测试是否弹 Cloudflare 验证码，并在客户端订阅编辑页切换“User-Agent”与“更新方式”对照排查。

### 步骤 2：按状态码执行针对性修复动作

1. **针对 `401` / `404`**：登录机场官网后台 → 检查套餐到期时间与剩余流量 → 在仪表盘重新点击“复制 Clash / 通用订阅地址”覆盖客户端旧链接。若怀疑旧链接曾在其他设备泄露，先点一次“重置订阅链接”再重新导入。
2. **针对 `403`**：
   - **第一步切换出口**：若刚才开了代理更新，先改为 **“直连更新（不通过代理）”**（国内家宽原生 IP 极少触发机场面向海外机房 IP 的 Cloudflare 质询，且部分机场只允许国内 IP 拉订阅）；若直连被阻断，换一个冷门低负载节点开启代理更新。
   - **第二步校准 UA**：在 Clash Verge Rev 右键该订阅 →「编辑信息」，在 `User-Agent` 栏显式填入 `clash.meta`（不要留空或填浏览器 UA）；在 v2rayN 订阅设置核对 UA 为默认客户端标识。
   - **第三步使用免盾独立订阅域**：若 `cf-mitigated: challenge` 证实服务商误给主站套了全局五秒盾，查看官网公告里的“备用免盾订阅域名”替换域名部分，或提交工单请管理员将 `/api/v1/client/subscribe` 路径加入 Cloudflare WAF 跳过（Skip）规则。
3. **针对 `502` / `503`**：立即关掉过短间隔（如每 10 分钟一次）的自动更新定时任务，改为 `1440` 分钟（24 小时）更新一次，静待 15–30 分钟后端恢复后再手动拉取。
4. **针对 `301` / `302` 重定向**：若 `Location` 指向新订阅域名，直接将客户端订阅 URL 更新为跳转后的新域名地址（减少中间跳转损耗）；若跳往 `/login`，按 `401` 流程回官网重取新 Token。

### 步骤 3：向客服提交工单的标准脱敏模板（防隐私泄露）

当确认是服务端 `403`（Cloudflare 盾锁死 API）或 `502/503` 需要提交工单时，直接发“连不上”往往来回沟通数小时，而直接贴原链接又有泄露风险。可复制以下**安全脱敏工单模板**提交给服务商面板工单系统：

```text
【故障简述】：第三方客户端更新订阅返回 HTTP 403（已排除套餐到期与链接拼写错误）
【测试时间】：2026-11-24 20:15 (UTC+8)
【客户端与版本】：Clash Verge Rev 2.x (User-Agent: clash.meta/1.18.0)
【订阅请求路径（已脱敏）】：https://sub.example.invalid/api/v1/client/subscribe?token=REDACTED
【直连与代理对照】：家庭宽带直连返回 HTTP 403；挂香港节点代理更新同样返回 HTTP 403
【响应头关键诊断】：Server: cloudflare, cf-mitigated: challenge, cf-ray: 8e78xxxxxx-HKG
【诉求】：麻烦核查订阅子域名是否误开启了 Cloudflare JS 质询/Bot Fight Mode 拦截了客户端 API，或告知当前可用的免盾备用订阅域名，谢谢！
```

## 什么结果算修复

- 客户端点击更新订阅后，状态码稳定返回 `200 OK`，响应内容为标准 YAML / Base64 / JSON 配置而非 `<!DOCTYPE html>` 网页代码。
- 客户端配置卡片正常刷新“更新时间”、节点列表与已用/总流量进度条，无 `401/403/404/503` 红色告警。
- 切换到更新后的任意可用节点执行真连接测速，能正常返回毫秒级延迟并打开网页。

## 若仍失败怎么办

1. **状态码返回 `200` 但节点列表为空**：若 `403` 消失了但拉回来的是 0 个节点，请转入 [更新订阅 HTTP 200 但返回空白内容排查](/troubleshooting/articles/sub-http-200-empty)。
2. **从 HTTP 报错变为证书错误或超时**：若更换备用域名后报 `x509` 或 `timeout`，请继续阅读 [更新订阅提示 TLS 证书错误、DNS 解析失败或超时](/troubleshooting/articles/sub-tls-dns-timeout)。
3. **服务商转为纯专属客户端或长期失联**：若确认该品牌已彻底关闭通用订阅仅保留自研 App，可前往 [机场深度评测目录](/reviews/) 与 [服务失联与专属端替代方案](/security/alternatives/) 核查品牌政策变更；若官网与全部订阅域连续多日 `502/404` 且无任何通告，请按 [机场跑路识别与止损步骤](/security/shutdown/) 保留凭证及时止损。

## 高风险操作与回滚提示

- **严禁关闭杀毒软件或 Windows Defender 防火墙**：HTTP `401/403/404/503` 是远端服务器或中间 CDN 返回的七层协议状态码，关闭本机安全防护不仅完全无效，还会让系统暴露于恶意风险之下。
- **严禁在公开论坛、GitHub Issue 或群聊粘贴未脱敏的订阅链接**：订阅 URL 中的 `token=` 等同于你的账号流量提货券，一旦泄露会被他人盗刷耗尽流量甚至触发多 IP 封号；不慎外泄后请第一时间在面板后台点击 **“重置订阅链接”** 作废旧码。
- **修改客户端 UA、更新间隔与本地 DNS/Hosts 的回滚**：
  - 若在步骤 2 中手动修改客户端订阅属性的 `User-Agent` 后发现拉取到的节点协议变少，右键编辑该订阅将 `User-Agent` 清空恢复客户端出厂默认值并重新更新即可回滚。
  - 若排障期间曾修改过本地 `hosts` 文件强制指定订阅域解析 IP，在服务端恢复后请务必打开 `C:\Windows\System32\drivers\etc\hosts`（Linux/macOS 为 `/etc/hosts`）删除对应测试行并执行 `ipconfig /flushdns` 还原默认动态解析。

## 常见问题

### 更新订阅报 403 Forbidden，是不是机场跑路了？

不一定。403 最常见于 Cloudflare WAF（五秒盾或 Bot Fight Mode）拦截了当前代理节点的出口 IP、订阅后端拒绝了默认的 User-Agent，或短时间内高频点击更新触发了速率限制。建议先切换“直连更新”或调整客户端 User-Agent 后隔 5 分钟再试，并确认机场网页后台能否正常打开。

### 为什么原本好好的订阅链接突然报 401 或 404？

401 通常意味着账户重置了订阅 Token、修改过面板密码或订阅已过期被吊销；404 则多见于服务商更换了订阅下发域名、迁移面板路由，或链接粘贴时末尾缺少了几个字符。

### 客户端提示重定向次数过多或被跳转到网页登录页怎么处理？

当旧订阅接口下线并把所有请求 302 跳转到官网登录页或公告页时，客户端会因拉取到 HTML 而解析失败。此时需要登录官网获取最新订阅地址，切勿把官网网页网址直接当作订阅地址填入。

### 为什么订阅链接在电脑浏览器里能正常打开下载，放进客户端更新却报 403？

浏览器拥有完整的桌面 User-Agent、Cookie 存储能力与 JavaScript 执行环境，能自动通过 Cloudflare 的静默质询；而代理客户端仅发起无状态的纯 API 请求，若服务商误对订阅子域名开启了人机质询或屏蔽了客户端默认 UA（如 Go-http-client），就会出现浏览器能下、客户端报 403 的差异。
