# 为何客户端测速与实际下载/网页体感差异大及倍率计算详解

## 核心结论（Answer-First）

测速跑出数百 Mbps 而实际“网页发粘、下载慢、流量掉得快”，主要源于四个机制落差：**多线程测速掩盖了单连接丢包与限速**、**网页体感更看重 TLS 首包时间（TTFB）而非峰值带宽**、**CDN 调度绕路或送中**，以及**未算入节点 0.5x–5x 倍率乘数**。切忌长期用高倍率节点频繁跑全量测速。

## 故障现象

- **跑分与下载落差**：看到基于 Miaoko 或 MAI-TEST-BOT 等测速工具的历史截图动辄显示峰值数百 Mbps，自己浏览器单线程下载 GitHub/海外安装包却只有 1–3 MB/s。
- **网页体感发粘**：油管 4K 跑得动，但打开图文网页、AI 对话页面需要等 2–4 秒才开始渲染，或者经常转圈后突然全部刷出。
- **单位换算与流量误解**：客户把测速图显示的 `100 Mbps` 当成 `100 MB/s`（实际 `100 Mbps ≈ 12.5 MB/s`）；或者跑完一轮“全节点自动测速”后，发现机场后台剩余流量一下子少了十几 GB，而客户端主界面当天记录只用了 2–3 GB。

## 先做 3 个低风险检查

1. **换算单位 `Mbps` 与 `MB/s`**：网络测速工具绝大多数使用比特单位 **Mbps**（Megabits per second），浏览器和下载器使用字节单位 **MB/s**（Megabytes per second），两者相差 **8 倍**（例如 `80 Mbps` 理论最大下载速度约等于 `10 MB/s`）。
2. **检查当前选中的节点后缀倍率**：查看节点名末尾是否带有 `x2`、`x3`、`x5`、`×0.5` 等标识。如果是高倍率节点，首先停止对它运行“带宽吞吐测速（Speedtest）”，仅用低消耗的“延迟测试（URLTest）”即可。
3. **关闭浏览器冗余扩展或使用无痕窗口对比**：部分浏览器广告屏蔽插件、安全扫描插件或缓存损坏会拖慢渲染；用纯净无痕窗口对比同一网页加载耗时，确认是不是浏览器自身卡顿。

## 分层原因排除

### 本地系统与网络

- **路由器或弱性能设备的加解密 CPU 瓶颈**：在千兆宽带环境下，早期的百元级硬路由、低功耗开发板运行单核软件加解密（如部分 TLS/AEAD 套件）时，单核跑满 100% 就会把代理总速度卡死在几十 Mbps，但电脑直连测速依然能跑满千兆。
- **本地网络 MTU 与分片丢包**：PPPoE 拨号加上代理隧道封装开销后，若内网 MTU 偏大引发分片丢包，大文件单线程吞吐会被 TCP 拥塞控制大幅压低。

### 客户端与核心配置

- **客户端“测速类型”概念混淆**：
  - **TCPing / URLTest（真连接测试）**：只发几十字节探测包，测的是往返延迟，不代表实际下载带宽。
  - **带宽测速（如客户端内建下载测速 / 外部并发测速）**：如果工具开了 16 个并发连接同时下载，即使单连接被限制在 2MB/s，总面板也能拼出 `32 MB/s (256 Mbps)` 的漂亮数字；可你平时用浏览器单线程下文件时依然只有 2MB/s。
- **部分客户端默认只统计本地物理字节**：客户端主界面的“今日已用流量”只计算经过本地网卡的原始字节数，**不会自动乘以机场后台设置的 2x/5x 节点倍率**，因此两边统计必然对不上。

### DNS 与路由分流

- **DNS 解析导致 CDN 就近分配出错**：如果你的 DNS 配置把海外域名交给了国内 DNS 解析（或反之），或者目标网站依赖的 CDN 把香港/新加坡节点误分配到了美国甚至欧洲服务器（典型现象如 YouTube 出现“送中”回流或跨洋绕路），即使节点本身带宽再大，跨洋单线程传输速度也会暴跌。
- **规则遗漏让国内大下载误走代理**：比如 Steam 游戏更新、网盘大文件或系统更新未命中直连规则，全部从高倍率代理节点走流量，既拖慢下载速度又飞快烧光套餐余额。

### 远端订阅与节点

- **节点单线程 QOS 限速**：部分服务商为了防止少数人占满母鸡带宽，会在节点服务器端配置单连接限速（比如单 TCP 流限制 30Mbps），多线程测速不受影响或影响较小，但单线程大文件下载怎么都冲不上去。
- **历史测速的时效与工具局限**：例如在测速归档记录中（如 2026-08-11 批次测试图），测试只证明当时特定协议、特定测试工具与测试机房下的瞬间表现；部分站点或线路在不同日期（如换用 VLESS/AnyTLS 协议后）表现也可能与早期 Shadowsocks 批次有所不同。

## 操作路径

### 适用平台说明

- **适用平台**：Windows、macOS、Linux、OpenWrt（完整执行终端单线程测速与倍率核对）；iOS 与 Android（重点核对客户端流量统计口径、关闭全节点带宽测速改用延迟测速，避免移动网络和套餐流量双重超额消耗）。

### 验证方法与倍率核算公式

1. **步骤 1：用公式准确核算倍率流量消耗**

   套餐实际扣除流量 = 真实上下行流量 × 节点倍率。

   | 真实使用/测速流量 | 节点倍率 | 后台实际扣除流量 | 典型场景风险提示 |
   | :--- | :--- | :--- | :--- |
   | 2 GB | `0.2x` / `0.5x` | 0.4 GB / 1.0 GB | 适合大流量下载或影音缓存（需关注限速与稳定性） |
   | 2 GB | `1.0x` | 2.0 GB | 常规标准计费，客户端本地统计与后台基本一致 |
   | 2 GB | `2.0x` / `3.0x` | 4.0 GB / 6.0 GB | 常见于优质中转或冷门落地节点 |
   | 2 GB | `5.0x` | 10.0 GB | 多见于高成本专线或特殊用途节点，切忌跑高清测速 |

   *提醒：机场订阅接口通常通过 HTTP 响应头 `subscription-userinfo` 返回 `upload` + `download` 总额，如果某机场同时启用了“全局倍率”或分节点倍率，应以机场用户后台账单为准。*

2. **步骤 2：在终端实测单线程吞吐与首包延迟（低流量消耗验证）**
   - **适用 OS**：macOS / Linux / Windows (Git Bash 或 WSL；Windows 原生 PowerShell 可用 `curl.exe`)
   - **目的**：仅消耗约 10MB 流量即可真实观测当前节点的单线程稳定速率（单位为字节/秒）与响应时间，避免运行第三方重型测速软件白白耗费几 GB 高倍率流量。
   - **风险等级**：低（只读下载测试文件并直接丢弃到空设备，不写入磁盘，也不修改任何代理配置）。

   ```bash
   # 将 127.0.0.1:7890 替换为你的客户端实际 HTTP 代理端口，下载约 10MB 样本包并输出单线程速率
   curl.exe -x http://127.0.0.1:7890 -o NUL -s -w "TTFB:%{time_starttransfer}s Total:%{time_total}s AvgSpeed:%{speed_download} Bytes/s\n" https://speed.cloudflare.com/__down?bytes=10485760
   ```
   *(注：macOS / Linux 请把命令中的 `curl.exe` 改为 `curl`，`-o NUL` 改为 `-o /dev/null`。)*

   - **预期输出解读**：
     - `AvgSpeed` 返回的是每秒字节数（Bytes/s），将其除以 `1048576` 即得到实际的 `MB/s`（乘以 `8` 近似 Mbps）。例如返回 `5242880 Bytes/s`，即单线程实测约为 `5.0 MB/s`（约 `40 Mbps`）。
     - 若单线程实测仅几十 KB/s 而网页又卡顿，重点观察 `TTFB` 是否高达数秒；若单线程达到 `10 MB/s+` 但某特定下载站慢，说明瓶颈在目标下载站本身的 CDN 限速，而非你的代理节点。

3. **步骤 3：排查客户端自动测速与国内流量误耗**
   - 检查 Clash Verge Rev / v2rayN / Shadowrocket 是否开启了过短间隔的“自动测速（Auto Test / Health Check）”且测试文件体积过大——标准的 `url-test` 检测地址应是轻量 204 状态页面（如 `generate_204`，几乎不耗流量），切勿把大文件地址填进定时健康检查栏。
   - 检查规则分流，确保百度网盘、阿里云盘、Steam/系统大更新全部命中 `DIRECT`（直连），不经过任何计费代理节点。

## 什么结果算修复

- 清楚核对当前使用节点的倍率（例如 `1x`），且后台流量扣除比例与单次轻量验证消耗匹配，不再出现“没下载东西却一夜掉几十 GB”的异常。
- 单线程 `curl` 测试样本 `TTFB` 稳定在合理值内，实际下载与网页加载表现符合同带宽单线程物理规律，不存在无故的数秒卡死。
- 客户端定期健康检查全部使用 `204` 空响应检测地址，几乎不产生额外流量支出。

## 若仍失败怎么办

- 如果在核对过直连规则和节点倍率后，发现即使无任何大流量操作且未泄露订阅，后台流量仍然出现严重异常飙升，需立刻前往机场后台 **重置订阅链接（Reset Subscription Token）** 并排查账号安全，参阅 [账号与订阅安全防护](/security/account-security/)。
- 如果单线程下载速度长期被死死限制在极低带宽（如白天非高峰期也始终低于 1Mbps），可参阅 [线路倍率计费与异常排查](/routes/multipliers/) 以及 [31 家品牌数据库](/brands/) 评估更匹配高吞吐需求的服务方案。

## 高风险操作与回滚提示

- **严禁使用第三方“免费多线程测速网站/脚本”去批量跑全列表高倍率节点**：部分网页测速默认直接拉取数百 MB 甚至数 GB 数据，在 `5x` 节点下跑两轮就能耗光整月轻量套餐，且该流量消耗**不可逆、无法退回**。
- **修改本地路由分流或覆写 Profile 防止国内下载走代理前，请先备份原规则配置**：如果误删规则或将 `MATCH` 误设为 `DIRECT` 导致需代理的网站打不开，只需还原修改前导出的配置文件或重新拉取一次原始订阅即可回滚。

## 常见问题

### 为什么测速图显示节点能跑 500Mbps，我自己下载文件或刷网页却只有几 MB/s 甚至卡顿？

测速机器人或测速软件（例如常见的多线程测速工具）通常使用 8–32 个并发线程向测速服务器拉取大文件，容易把短时带宽峰值拉满；而实际打开网页或单线程下载依赖极短时间内的单连接 TCP 拥塞窗口爬坡与 TLS 握手响应（TTFB）。如果节点存在轻微丢包、服务端限制了单连接速率、或本地分流误判了 CDN 地域，就会出现“测速很高、网页慢半拍”的落差。

### 节点名里的“2x”“5x”倍率是什么意思？测一次速会扣多少流量？

倍率代表该节点的流量扣费系数。以 1x 为基准，若你通过标注“5x”的专线节点下载或测速消耗了 1GB 真实网络数据，机场后台面板会扣除 1GB × 5 = 5GB 套餐流量。用高倍率节点频繁运行全节点测速，往往几分钟就会消耗掉数十 GB 额度，而客户端本地统计面板通常只显示“真实流量 1GB”，从而造成流量凭空消失的错觉。

### 测速显示 0B 或个别节点没有速度，就代表这家机场全挂了吗？

不一定。单次测速出现 0B 可能源自该节点正在临时维护、并发限制触发了拒绝连接、测试脚本与节点协议（如部分测速环境对 VLESS/Shadowsocks 兼容性不同）不匹配，或仅特定时段被阻断。必须结合测试时间、测速协议与同批次其他节点的响应状态综合判断，不能仅凭单一节点 0B 截图就下结论。
