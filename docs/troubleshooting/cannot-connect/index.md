faq:
  - q: 为什么节点延迟显示 40ms，但浏览器打开任何网页都转圈或报错 ERR_PROXY_CONNECTION_FAILED？
    a: 节点绿灯延迟只能说明代理核心自身连上了远端服务器，而浏览器打不开说明本地流量根本没交到代理核心手里。最高频诱因是系统代理端口与客户端监听端口错配（如系统仍指着 7890 而客户端监听 7897 或 10808）、SwitchyOmega 等浏览器插件锁定了旧端口、同时开了两套代理形成环路，或在 GLOBAL 模式下误选了 0B 失效节点。
  - q: 系统代理和 TUN 模式同时开启会更快吗？
    a: 不会，反而极易引发流量二次封装、路由环路或端口争抢，导致延迟飙升甚至全网断流。日常只代理浏览器与常规办公软件时，优先单独开启低风险的系统代理；需要接管终端命令行、Git、Python 或联机游戏时，再单独切换至 TUN 模式，两者应严格二选一。
  - q: 为什么退出代理软件后，连国内网站和聊天软件都一起断网了？
    a: 这是典型的「退端未清理残留」现象。客户端异常崩溃或强制结束进程时，没来得及撤销系统代理设置（仍指向已关闭的 127.0.0.1 端口），或者开启过 TUN 与 Fake-IP 后物理网卡 DNS 仍停留在本地回环地址。打开系统设置手动关闭「使用代理服务器」并刷新 DNS 缓存，即可在三十秒内恢复直连。
  - q: Google 和 YouTube 都很流畅，为什么唯独 ChatGPT、Claude 或 Gemini 提示地区不支持？
    a: 这属于目标平台基于出口 IP 归属地与风控评分实施的应用层拦截，并非代理断连。例如香港节点虽延迟极低，但在多份实测样本中频繁出现 OpenAI 仅限 APP 或 Gemini 不可用；此外旧规则集漏掉 AI 子域名、浏览器残留旧地区 Cookie 或内置安全 DNS 旁路，也会造成跨浏览器表现不一致。应先无痕复测，再将 AI 域名统一固定到可用日、新、美节点。
  - q: Clash Verge Rev 开启 TUN 模式后开关几秒内自动弹回，或者一开 TUN 全电脑断网怎么办？
    a: 开关弹回多因 Windows 未安装并启动 Service Mode 服务模式、缺少管理员权限，或 macOS 未批准系统网络扩展；一开就全网断联则常见于同时运行着企业 VPN（如 EasyConnect）、游戏加速器导致多张虚拟网卡争抢默认路由，或配置文件未开启内置 DNS。应先关闭 TUN 回滚网络，再退出冲突软件并安装服务模式。
  - q: v2rayN 刚勾选自动配置系统代理，没过几秒怎么就被自动还原成「清除系统代理」了？
    a: 这是后台其他程序在抢夺操作系统代理注册表项的典型表现。常见争抢源包括忘记关闭开机自启的旧版代理客户端、机场专属一键客户端、抓包调试工具（如 Fiddler / Charles）、企业下发的 PAC 自动配置脚本或系统安全优化卫士。彻底退出并禁用其余代理与抓包工具自启，清空残留 PAC 地址即可稳住状态。
  - q: 安卓手机的 v2rayNG 或 Clash Meta 锁屏几分钟就断连，切换 Wi-Fi 和 5G 后钥匙还在却没网怎么办？
    a: 安卓代理依赖系统 VpnService 在后台常驻，手机厂商严苛的省电策略会在息屏后冻结或杀死进程，必须将客户端加入电池优化白名单并锁定后台任务卡片。若在 Wi-Fi 与蜂窝数据切换后出现图标仍在却断流的假死状态，手动关闭再重新开启一次代理开关刷新底层隧道即可恢复。

# 连接不上排查：已连无网、TUN 失效与接管冲突

## 核心结论（Answer-First）

在所有代理故障中，最容易让用户陷入盲目重装误区的场景就是**「客户端节点测速明明绿灯正常，但电脑或手机就是打不开网页」**。此时节点链路大概率是健康的，真正的病灶卡在本地流量进入代理核心之前的接管环节：要么是**系统代理端口错配与多端抢占**，要么是**TUN 虚拟网卡权限或路由冲突**，要么是**分流规则与平台风控挡住了特定网站**，而在移动端则集中表现为**安卓后台省电杀进程与隧道假死**。

排障切忌病急乱投医去随意关闭杀毒软件，更不要动不动就执行会破坏本地桥接配置的系统网络栈全局重置。请顺着本地流量入口由浅入深推进，严格落实**「现象 → 可能原因 → 低风险检查 → 操作路径 → 验证标准 → 回滚提示」**六步流程，直达下方 7 篇核心三级实操手册。

## 一、按具体症状直达三级实操指南

| 你眼前遇到的核心症状 | 最高概率的故障诱因 | 第一步低风险定位动作 | 对应三级实操指南 |
| :--- | :--- | :--- | :--- |
| 节点绿字有延迟，但 **所有网页都打不开**，报 `ERR_PROXY_CONNECTION_FAILED` | 系统代理端口不匹配、插件锁定旧端口、双端环路、出站误切 `REJECT` | 核对 7890/7897/10808 端口对齐，查客户端连接监控页有无请求进入 | [节点已连接但所有网页打不开排查](/troubleshooting/articles/connected-no-internet) |
| 主流外网流畅，**仅 ChatGPT / Claude / Gemini 或个别站不可达** | 出口地区风控（如香港受限）、分流误走直连、Cookie 或 DoH 干扰 | 开浏览器无痕窗口复测，查连接日志确认全套子域名落点地区一致 | [仅个别网站与 AI 工具打不开排查](/troubleshooting/articles/specific-sites-unreachable) |
| 开启 **TUN 模式开关弹回**，或开启后全机断网、命令行不走代理 | 未装 Service Mode 服务、多虚拟网卡路由打架、配置未开 `dns.enable` | 立即关闭 TUN 回滚止血，排查企业 VPN / 加速器等其余虚拟网卡 | [TUN 开启无效与虚拟网卡冲突修复](/troubleshooting/articles/tun-not-working) |
| 不清楚该开 **TUN 还是系统代理**，两者互切后出现部分应用断流 | 同时开启叠加环路、切换后旧代理或 Fake-IP 缓存未清理 | 坚持二选一原则，切换后刷新系统 DNS 缓存并核对系统代理状态 | [TUN 与系统代理区别及切换断网修复](/troubleshooting/articles/tun-vs-system-proxy) |
| **v2rayN 运行正常**，但浏览器完全不走代理或系统代理被自动还原 | 底部路由误选直连、他端抢占注册表、PAC 脚本残留、扩展覆盖 | 核查状态栏为「自动配置系统代理」，退出其他自启代理与抓包工具 | [v2rayN 系统代理失效与自动还原排查](/troubleshooting/articles/v2rayn-system-proxy-fail) |
| **安卓 v2rayNG / Clash Meta** 锁屏断连，或 Wi-Fi 切 5G 假死 | 电池优化后台强杀、VpnService 权限被抢占、切网隧道句柄失效 | 设为不限制电池优化并锁后台卡片，切网假死时重启一次隧道开关 | [安卓客户端节点失效与后台断连保活](/troubleshooting/articles/android-v2rayng-clash-disconnect) |
| 日志伴随 **TLS handshake failed / 证书未生效**，实际全网无法建连 | 本地系统时钟与标准时间偏差超过 30 至 60 秒协议容忍窗口 | 关代理直连完成 NTP 校时，重启代理内核后重新测试 | [系统时间不同步导致 TLS 握手失败](/troubleshooting/articles/time-sync-tls-cert-error) |

## 二、先做 30 秒最小闭环测试：秒分「浏览器问题」还是「系统与核心问题」

在调整任何底层路由之前，先执行一次零风险的本地最小闭环验证：

1. **确保仅单一接管方式生效**：暂时关闭 TUN 模式与浏览器里的所有代理扩展（如 SwitchyOmega），只保留当前客户端的「系统代理」并记下客户端首页显示的本地监听端口号（例如 Clash Verge Rev 默认常见 `7897` 或 `7890`，v2rayN 常见 `10808`/`10809`）。
2. **用命令行直连本地代理端口做探针**：在终端执行 `curl -I -x http://127.0.0.1:<监听端口> https://www.google.com`（按实际端口替换）。
   - 如果命令行迅速返回 `HTTP/1.1 200 OK` 或 `301`，说明**代理核心、监听端口与远端节点 100% 健康**，问题彻底锁定在浏览器自身（扩展插件抢占、浏览器内置安全 DNS 旁路、Cookie 污染或代理设置未跟随系统）。
   - 如果命令行直接报 `Connection refused`，说明本地端口未监听或核心未跑起来；如果报 `Timeout` 或 `TLS error`，问题则落在客户端核心路由、节点本身或系统时钟上。

## 三、场景一：节点绿灯但所有网页打不开（端口错配与系统代理残留）

这类故障最典型的特征是「客户端看起来一切正常，浏览器却寸步难行」，甚至一关软件连国内网站也跟着瘫痪。

- **现象**：客户端延迟测试一片绿字，但浏览器访问国内外所有网页都报错 `ERR_PROXY_CONNECTION_FAILED`、`ERR_TIMED_OUT` 或空白转圈；强制关闭或异常退出客户端后，系统连百度、微信网页版等国内直连也打不开。
- **可能原因**：
  1. **系统代理端口与核心监听端口不一致**：例如曾经运行过旧版 Clash 留下了 `127.0.0.1:7890` 的系统代理配置，现在换用监听在 `7897` 或 `10808` 的新端后，浏览器依然把请求发往空置的 `7890` 端口。
  2. **多软件与浏览器扩展争抢入口**：电脑同时运行了两款代理软件、机场专属一键客户端、抓包软件（Fiddler / Charles），或浏览器安装了代理管理插件并锁定在某个已失效情景模式，导致流量掉进黑洞或形成本地循环环路。
  3. **代理模式与节点组误设**：无意间将代理模式切到了 `GLOBAL`（全局）并恰好选中了一条实测 `0B` 的死节点或 `REJECT` 拦截出站，致使全网流量被一刀切阻断。
  4. **异常退端遗留脏开关**：软件闪退、直接杀进程或电脑异常断电时，客户端没来得及把系统代理开关置回关闭。
- **低风险检查**：核对客户端首页实际监听的 Mixed/HTTP 端口与操作系统「网络和 Internet → 代理」中的地址端口是否完全一致；打开客户端「连接（Connections）」监控面板，刷新一次网页，看是否有新连接记录跳出、命中了哪条分流规则以及最终走了哪个出站节点。
- **操作路径**：先彻底退出所有多余代理客户端、抓包工具与游戏加速器，保证后台仅存一套代理内核；将浏览器代理扩展暂时停用或切回「系统代理」模式；把客户端出站模式切回「规则（Rule）」，确认主策略组选中的是当前实测有响应的正常节点；在客户端里手动关闭再重新打开一次「系统代理」开关，让程序重新写入干净的端口映射；若是退出客户端后依然断网，直接进系统代理设置关闭「使用代理服务器」并清空 PAC 自动配置脚本栏。
- **验证标准**：客户端连接监控页稳定记录国内流量走 `DIRECT`、海外流量走代理节点，浏览器国内外网页均快速加载；关闭代理软件后国内直连无缝恢复。
- **回滚提示**：排查过程中不要贸然删除系统里的原有网络适配器配置或运行全局网络重置命令；调整浏览器插件情景模式前先记住原情景名，验证通畅后再按需清理冗余插件。完整步骤见 [节点已连接但所有网页打不开排查](/troubleshooting/articles/connected-no-internet)。

## 四、场景二：仅 AI 工具或个别网站打不开（分流分裂、IP 风控与浏览器差异）

能流畅看 YouTube、刷 GitHub，唯独打开 ChatGPT、Claude 或 Gemini 就吃闭门羹，或者同一个节点在 Chrome 报错、换个无痕窗口却能进，这种局部不可达几乎全是应用层策略问题。

- **现象**：常规海外站点畅通无阻，但 ChatGPT 弹出地区不支持或 `Access Denied`，Claude 拒绝登录，Gemini 提示所在国家不可用；连着新加坡、台湾或香港节点打开 YouTube 却被识别为 `送中(CN)`；同一台电脑不同浏览器结果截然相反。
- **可能原因**：
  1. **出口地区风控政策差异**：节点延迟低不等于 AI 和流媒体解锁。本站留存的 `2026-08-19` 光速云 Miaoko 实测样本显示，香港专线节点延迟虽低，但 OpenAI 多为 `仅APP(HK)`、Gemini 多数显示 `失败`，且新加坡、台湾多条线路记录到 YouTube `送中(CN)`；`2026-07-18` 无忧链接实测中香港 HKG-01 也出现 YouTube `送中(CN)`。盲目把 AI 流量留在香港或高风险共享出口必然撞墙。
  2. **分流规则滞后导致域名分裂**：老旧规则集未完整收录 AI 平台新增的鉴权、静态资源或 WebSocket 子域名，导致主页面走美国节点，登录验证或 API 接口却落入了 `DIRECT` 直连或香港节点，触发跨国会话风控秒拒。
  3. **浏览器状态与安全 DNS 旁路**：浏览器历史 Cookie 缓存了之前误用受限 IP 留下的地区标记；或者 Chrome/Edge 默认开启的「使用安全 DNS（DoH）」直接向外部解析域名，绕开了客户端分流与规则匹配。
- **低风险检查**：第一时间打开浏览器全新**无痕/隐私窗口**访问目标站点，十秒剥离历史 Cookie 与插件缓存；同时盯着客户端实时连接日志，搜索目标平台主域及关联子域名，核对它们是否全部命中同一个代理策略组并落到同一国家出口。
- **操作路径**：清除目标 AI 或流媒体网站的站点 Cookie 与本地存储；在浏览器设置中关闭独立安全 DNS（DoH），让解析权回归代理客户端（详见 [DNS 错误排查专题](/troubleshooting/dns-error/)）；更新分流规则集，为 ChatGPT、Claude、Gemini 等风控敏感服务建立独立策略组，手动固定到经过验证的日本、新加坡或美国干净节点，**切忌把 AI 策略组绑在自动测速组上高频跨国跳 IP**。
- **验证标准**：常规窗口与无痕窗口表现一致，能够稳定完成对话与内容加载，客户端连接日志显示所有相关子域名均统一命中同一解锁地区出站。
- **回滚提示**：手动修改分流覆写规则新增 AI 独立策略组前，务必先导出备份原覆写文件；一旦新规则触发语法报错，直接还原备份即可恢复全网运行。专题与实操指南可延伸阅读 [仅个别网站与 AI 工具打不开排查](/troubleshooting/articles/specific-sites-unreachable)、[分流规则配置](/guides/split-routing/) 及 [ChatGPT](/ai-media/chatgpt/)、[Claude](/ai-media/claude/)、[Gemini](/ai-media/gemini/)、[YouTube](/ai-media/youtube/) 专项解锁排查页。

## 五、场景三：TUN 模式无效、虚拟网卡冲突与系统代理自动还原

许多开发者和游戏用户希望终端 CLI、Git、Python、Docker 或 UWP 软件也能自动走代理，因此开启了三层 TUN 虚拟网卡，却常常遭遇开关弹回、一开即断网或与系统代理来回打架的窘境。

### TUN 模式与系统代理核心边界对照

| 对比维度 | 系统代理（System Proxy） | TUN 虚拟网卡模式（TUN Mode） |
| :--- | :--- | :--- |
| **接管层级** | 应用层（写入操作系统 HTTP/SOCKS 代理地址） | 网络层（创建虚拟网卡并接管系统三层路由表） |
| **覆盖软件范围** | 浏览器与主动读取系统代理的桌面软件 | 几乎全部本机进程（含终端 CLI、Git、游戏、UWP 等） |
| **所需系统权限** | 普通用户权限即可，零驱动依赖 | Windows 需管理员/Service Mode 服务，macOS 需批准网络扩展 |
| **故障与冲突风险** | 低风险；冲突仅限于端口被他端覆盖或 PAC 抢占 | 中高风险；易与企业 VPN、加速器虚拟网卡冲突，或引发 Fake-IP 残留 |
| **推荐默认用法** | 日常浏览网页与轻办公的首选默认模式 | 按需开启；**切忌与系统代理长期叠加混开** |

### TUN 失效与 v2rayN 系统代理自动还原的六步诊断

- **现象**：在 Clash Verge Rev 中点击开启 TUN 模式，开关数秒后自动弹回关闭并报 `Service Mode not installed` 或 `wintun error`；或者 TUN 成功开启后电脑瞬间全网断联；而在 v2rayN 中则表现为状态栏刚设为「自动配置系统代理」很快就被默默还原成「清除系统代理」，或浏览器始终走直连。
- **可能原因**：
  1. **特权服务与内置 DNS 缺失**：Windows 未安装启用 Service Mode 服务，或 macOS 未在系统「隐私与安全性」中放行网络扩展；另一大常见疏忽是配置文件里未开启 `dns.enable: true`，TUN 接管三层数据包后缺少内置 DNS 接应，导致全机域名解析停摆。
  2. **多张虚拟网卡路由表打架**：后台同时运行着企业 SSL VPN（如 EasyConnect、GlobalProtect）、网游加速器或旧客户端残留的虚拟网卡，多方同时向系统写入 `0.0.0.0/0` 默认路由，数据包彻底迷失方向。
  3. **协议栈兼容性问题**：Windows 部分老旧网卡驱动或安全软件环境下，TUN 的 `system` 协议栈易出现高 CPU 占用或间歇断流。
  4. **系统代理注册表被争抢**：v2rayN 自动还原多因旧代理软件开机自启、机场专属客户端驻留托盘、抓包工具或企业下发的自动代理脚本持续覆写 Windows `Internet Settings` 注册表；另有部分用户是误把 v2rayN 底部路由设为了「全部直连」。
- **低风险检查**：先打开操作系统「网络连接 / 网络适配器」列表，核对是否存在两张及以上启用中的虚拟网卡；核查开机自启项与系统托盘图标，列出所有涉及代理、加速、抓包与企业 VPN 的常驻程序；在 v2rayN 底部确认路由模式为「绕过大陆」而非「全局直连」。
- **操作路径**：
  - **TUN 排障**：如果开启 TUN 后已断网，立刻遵循**「先止血回滚，再排冲突」**原则——先关掉 TUN 开关并核对物理网卡 DNS 为自动获取；彻底退出企业 VPN 与游戏加速器；在 Clash Verge Rev 设置中点击安装并启用 Service Mode 服务模式，核对配置已开启 `dns.enable: true`，若 `system` 栈断流可切换为 `mixed` 或 `gvisor` 栈对照测试。
  - **v2rayN 系统代理排障**：退出并禁用一切冲突代理与抓包工具的开机自启，清空系统代理里残留的未知 PAC 链接；在 v2rayN 底部确认选中「自动配置系统代理」，核对浏览器设为「使用系统代理设置」。
- **验证标准**：开启 TUN 后系统仅存在一张健康虚拟网卡，终端测试外网请求准确出现在客户端连接日志中；使用系统代理时 v2rayN 状态栏端口稳定锁定不再自动回弹，浏览器流量正常入站。
- **回滚提示**：在确认需要 TUN 接管命令行前，优先停留在低风险系统代理模式；若安装或切换 TUN 协议栈引发局域网失联或蓝屏风险，立即关闭 TUN、卸载异常虚拟网卡服务并重启电脑即可干净还原。详尽指南见 [TUN 开启无效与虚拟网卡冲突修复](/troubleshooting/articles/tun-not-working)、[TUN 与系统代理区别及切换断网修复](/troubleshooting/articles/tun-vs-system-proxy)、[v2rayN 系统代理失效与自动还原排查](/troubleshooting/articles/v2rayn-system-proxy-fail) 及 [TUN 模式原理与安全配置](/guides/tun-mode/)。

## 六、场景四：安卓 v2rayNG / Clash Meta 后台杀进程与切网断连

移动端与桌面端采用完全不同的系统网络接管模型。安卓系统只允许同一时刻运行一个 `VpnService` 隧道，且国内主流手机定制 ROM 对后台常驻进程的省电查杀极为激进，导致大量用户误以为「节点又挂了」。

- **现象**：安卓手机亮屏使用一切正常，锁屏放口袋几分钟后再打开，顶部的 VPN 钥匙图标已悄然消失，应用全线断连；或者从室内 Wi-Fi 走到室外自动切换为 4G/5G 移动数据后，钥匙图标明明还在，网页和 App 却彻底卡死无流量。
- **可能原因**：
  1. **系统省电与内存清理杀后台**：手机系统将 v2rayNG、FlClash 或 Clash Meta 判定为后台高耗电进程，在锁屏数分钟后直接冻结网络权限或强杀进程，连带回收 `VpnService` 隧道。
  2. **多款代理或 VPN 类软件抢占独占槽位**：同时开启了广告拦截工具、企业办公 VPN 或另一款加速器，后启动的应用会直接顶掉前者的 `VpnService` 授权。
  3. **网络接口切换后隧道句柄假死**：从 Wi-Fi 切到 5G 时底层出口 IP 与物理网卡已变，但旧的代理连接句柄未能即时重建，造成「图标在、没网走」的假死状态。
  4. **客户端版本停更或来源异常**：需要特别留意的是，NekoBox for Android 官方已明确提醒维护资源有限且警告切勿使用已被第三方控制的 Google Play 同名版本，使用非官方或老旧版本往往伴随严重断流与兼容隐患。
- **低风险检查**：下拉通知栏确认代理客户端的常驻通知与状态栏 VPN 钥匙图标是否还在；检查是否同时安装了其他基于本地 VPN 实现的去广告或企业接入应用；核对客户端安装包是否来自官方开源发布通道。
- **操作路径**：进入安卓系统「设置 → 应用管理 → 找到对应客户端（建议优先使用持续维护的 v2rayNG / FlClash / Hiddify）」，依次完成三项保活配置——将电池策略设为 **「无限制 / 允许后台高耗电」**、开启 **「允许后台自启动与关联启动」**、在多任务视图中下拉或点击菜单 **「锁定后台任务卡片」**；在 Wi-Fi 与蜂窝数据切换假死时，直接开关一次客户端主按钮刷新底层隧道；非必要慎开系统层的「阻止无 VPN 连接」，以免进程被杀后整机彻底断网。
- **验证标准**：锁屏静置 15 分钟以上唤醒手机，状态栏 VPN 钥匙图标与常驻通知保持存活，直接打开海外网页无需重连即可秒开。
- **回滚提示**：若开启了系统设置中的「始终开启的 VPN」或「阻止无 VPN 连接」后导致手机无法接入公司或酒店认证 Wi-Fi，先关闭该系统强约束选项，待完成网页认证后再开启代理客户端。完整各品牌手机保活细则见 [安卓客户端节点失效与后台断连保活](/troubleshooting/articles/android-v2rayng-clash-disconnect) 与 [安卓端后台保活与 VpnService 机制](/vpn/android/)。

## 常见问题

### 为什么节点延迟显示 40ms，但浏览器打开任何网页都转圈或报错 ERR_PROXY_CONNECTION_FAILED？

节点绿灯延迟只能说明代理核心自身连上了远端服务器，而浏览器打不开说明本地流量根本没交到代理核心手里。最高频诱因是系统代理端口与客户端监听端口错配（如系统仍指着 7890 而客户端监听 7897 或 10808）、SwitchyOmega 等浏览器插件锁定了旧端口、同时开了两套代理形成环路，或在 GLOBAL 模式下误选了 0B 失效节点。

### 系统代理和 TUN 模式同时开启会更快吗？

不会，反而极易引发流量二次封装、路由环路或端口争抢，导致延迟飙升甚至全网断流。日常只代理浏览器与常规办公软件时，优先单独开启低风险的系统代理；需要接管终端命令行、Git、Python 或联机游戏时，再单独切换至 TUN 模式，两者应严格二选一。

### 为什么退出代理软件后，连国内网站和聊天软件都一起断网了？

这是典型的「退端未清理残留」现象。客户端异常崩溃或强制结束进程时，没来得及撤销系统代理设置（仍指向已关闭的 127.0.0.1 端口），或者开启过 TUN 与 Fake-IP 后物理网卡 DNS 仍停留在本地回环地址。打开系统设置手动关闭「使用代理服务器」并刷新 DNS 缓存，即可在三十秒内恢复直连。

### Google 和 YouTube 都很流畅，为什么唯独 ChatGPT、Claude 或 Gemini 提示地区不支持？

这属于目标平台基于出口 IP 归属地与风控评分实施的应用层拦截，并非代理断连。例如香港节点虽延迟极低，但在多份实测样本中频繁出现 OpenAI 仅限 APP 或 Gemini 不可用；此外旧规则集漏掉 AI 子域名、浏览器残留旧地区 Cookie 或内置安全 DNS 旁路，也会造成跨浏览器表现不一致。应先无痕复测，再将 AI 域名统一固定到可用日、新、美节点。

### Clash Verge Rev 开启 TUN 模式后开关几秒内自动弹回，或者一开 TUN 全电脑断网怎么办？

开关弹回多因 Windows 未安装并启动 Service Mode 服务模式、缺少管理员权限，或 macOS 未批准系统网络扩展；一开就全网断联则常见于同时运行着企业 VPN（如 EasyConnect）、游戏加速器导致多张虚拟网卡争抢默认路由，或配置文件未开启内置 DNS。应先关闭 TUN 回滚网络，再退出冲突软件并安装服务模式。

### v2rayN 刚勾选自动配置系统代理，没过几秒怎么就被自动还原成「清除系统代理」了？

这是后台其他程序在抢夺操作系统代理注册表项的典型表现。常见争抢源包括忘记关闭开机自启的旧版代理客户端、机场专属一键客户端、抓包调试工具（如 Fiddler / Charles）、企业下发的 PAC 自动配置脚本或系统安全优化卫士。彻底退出并禁用其余代理与抓包工具自启，清空残留 PAC 地址即可稳住状态。

### 安卓手机的 v2rayNG 或 Clash Meta 锁屏几分钟就断连，切换 Wi-Fi 和 5G 后钥匙还在却没网怎么办？

安卓代理依赖系统 VpnService 在后台常驻，手机厂商严苛的省电策略会在息屏后冻结或杀死进程，必须将客户端加入电池优化白名单并锁定后台任务卡片。若在 Wi-Fi 与蜂窝数据切换后出现图标仍在却断流的假死状态，手动关闭再重新开启一次代理开关刷新底层隧道即可恢复。
