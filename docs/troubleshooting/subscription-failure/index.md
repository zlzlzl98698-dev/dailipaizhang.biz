faq:
  - q: 更新订阅时提示“不能在开启代理时更新”或“直接拉取失败”，应该先开还是先关代理？
    a: 绝大多数情况下应先关闭当前客户端的系统代理与 TUN 模式后再直连更新订阅，因为主流机场订阅域名通常在国内可直连或套有加速 CDN；如果当前节点已经全部失效，开着代理去更新订阅反而会把拉取请求送进死节点造成循环超时。只有确认订阅域名在本地直连被阻断或 DNS 污染时，才需要借助可用的备用节点或手机热点拉取。
  - q: 为什么客户端提示更新成功且返回 HTTP 200，节点列表却还是空的或显示 0 字节？
    a: HTTP 200 只表示服务器成功应答了这次 HTTPS 请求，不代表返回的正文就是当前客户端能解析的节点配置。常见原因包括套餐到期或流量归零后后端返回空列表或网页提示文本、把 Base64 通用订阅或 sing-box JSON 误导入了要求 YAML 格式的 Clash 客户端、面板根据 User-Agent 下发了空模板，或者该品牌仅支持专属客户端而不开放第三方通用订阅。
  - q: 更新订阅弹出 401、403、404、503 状态码时，最核心的区别是什么？
    a: 401 和 404 属于凭据与路径失效，多因在后台重置了订阅 Token、链接复制不完整带空格或接口路径变更，回面板重新复制即可；403 属于访问被防火墙拦截，常见于 Cloudflare 拦截机房代理 IP 或非标 User-Agent，需切换直连与代理更新对照；503 则是面板源站临时过载或维护，应查看公告并稍候重试。
  - q: 为什么同一个机场订阅在手机 Shadowrocket 正常，导入电脑 Clash Verge Rev 却少节点或直接报错？
    a: 机场面板通常会读取客户端发出的 User-Agent 请求头，按不同客户端动态下发不同协议集或配置格式。例如部分服务商会对不同工具分别下发 Shadowsocks 与 VLESS/AnyTLS 节点；此外停更的老旧内核会静默丢弃不识别的新协议，或者电脑端误启用了有语法冲突的全局覆写脚本，导致同一份订阅跨端表现大相径庭。
  - q: 部分品牌只提供专属客户端，为什么我找不到 Clash 或 Shadowrocket 订阅链接？
    a: 并非所有服务商都开放标准第三方订阅格式。部分品牌采用自研专属软件，仅允许账号密码一键登录而刻意关闭了 Clash、v2rayN 或 Shadowrocket 订阅导出接口。这类情况属于服务商产品策略而非软件故障，拿网页后台网址硬塞进代理客户端只会拉回 HTML 网页源码导致解析失败。
  - q: 订阅导入报错时，可以把订阅链接丢进网上搜到的第三方在线订阅转换站排查吗？
    a: 强烈不建议。完整订阅链接内嵌你的账号鉴权 Token，一旦粘贴到来源不明的公共在线订阅转换站点，对方服务器日志即可完整留存你的订阅凭证，进而存在流量盗刷或节点泄露风险。如需排查返回内容，优先在本地终端使用脱敏命令检查响应头，或直接使用服务商后台原生提供的对应客户端格式。
  - q: Shadowrocket 小火箭扫码或粘贴订阅后完全没反应，或者导入了节点却全部走直连怎么办？
    a: 导入无反应先检查链接首尾是否混入空格换行、协议头是否完整，以及该机场是否支持通用订阅；若节点已成功导入却所有网站均走直连，九成是因为小火箭首页的全局路由（Global Routing）被设为了「直连（Direct）」而非「配置（Config）」，将其改回配置模式并确认 iOS VPN 描述文件已授权即可恢复。

# 订阅失败排查：HTTP 状态码、空白订阅与解析冲突

## 核心结论（Answer-First）

在所有客户端里点击「更新订阅」，底层执行的都是一次标准的 **HTTPS GET 请求**，随后由客户端内置解析器把拉回来的文本反序列化为节点清单与分流规则。因此，订阅更新失败永远只有两大责任域：**网络传输层没拿到正确响应**（表现为 `401/403/404/503`、`302` 重定向、`TLS/DNS` 报错与超时），或者**应用解析层拿到了不认识的内容**（表现为 `HTTP 200` 却 0 节点、跨端节点数不一致、Shadowrocket 导入无反应）。

排障切忌在原链接上连续狂点几十次刷新，否则不仅查不出根因，还可能触发服务商源站或 Cloudflare WAF 的限流封禁。正确做法是先读出客户端日志或弹窗里的**精确状态码与错误关键词**，严格按照**「现象 → 可能原因 → 低风险检查 → 操作路径 → 验证标准 → 回滚提示」**六步法定位，并严守绝不把完整订阅链接交给陌生在线转换站的安全红线。

## 一、按报错特征与状态码直达三级实操指南

| 客户端报错特征 / 状态码 | 核心故障机理 | 首选低风险定位动作 | 对应三级实操指南 |
| :--- | :--- | :--- | :--- |
| 提示更新成功 / **HTTP 200 但 0 字节或 0 节点** | 格式与解析器错配、UA 下发空模板、套餐到期空体、仅限专属客户端 | 核对套餐有效状态、确认面板对应格式与是否开放第三方订阅 | [订阅 HTTP 200 返回 0 字节排查](/troubleshooting/articles/sub-http-200-empty) |
| 报 **401 / 403 / 404 / 503** 或被 **302 重定向到网页** | Token 被重置、WAF 拦截出口 IP 或 UA、链接截断、面板源站过载 | 核对链接完整性，在直连更新与代理更新之间切换对照 | [更新订阅 401/403/404/503 与重定向排查](/troubleshooting/articles/sub-http-401-403-404-503) |
| 报 **TLS handshake error / x509 / DNS fail / Timeout** | 系统时间偏差、本地 DNS 污染订阅域名、开着死代理拉取死循环 | 关代理直连对照、校对系统时间、切手机热点或备用订阅域名 | [更新订阅 TLS 错误与 DNS 超时排查](/troubleshooting/articles/sub-tls-dns-timeout) |
| **Shadowrocket 小火箭导入没反应 / 分流规则不生效** | 复制夹带空白符、iOS 剪贴板/VPN 权限异常、全局路由误选 Direct | 校验纯文本 URL、把全局路由切回「配置（Config）」并重授权 VPN | [Shadowrocket 无法导入订阅与规则排查](/troubleshooting/articles/shadowrocket-import-rules) |
| **同一订阅在 v2rayN 正常，在 Clash 缺节点或报错** | User-Agent 动态下发差异、旧内核过滤新协议、全局覆写脚本冲突 | 核对 Mihomo/Xray 活跃内核、暂时停用 Merge/Script 覆写对照 | [同一订阅在不同客户端表现不一致](/troubleshooting/articles/cross-client-inconsistency) |

## 二、安全底线与三项高频认知误区

动手排查订阅链接之前，必须先明确三条不可逾越的操作原则，避免排障演变成账号泄露或死循环：

1. **绝不泄露带 Token 的完整订阅链接**：订阅 URL 末尾的 `?token=` 或路径哈希等同于你的明文通行密钥。严禁将完整订阅地址粘贴到公开聊天群组、第三方测速机器人或非自建的陌生在线订阅转换网站；本地排查时也只截取脱敏后的响应头与前两行结构。详情参考 [账号与订阅安全指南](/security/account-security/)。
2. **先区分「专属客户端」与「通用订阅」**：并非所有机场都提供 Clash YAML 或 Base64 订阅地址。在站内档案记录中，部分品牌（如飞猫云、Firefly、无忧链接 2026-10 起、灵猫网络、SOGO 云、闪跃、全球云、隐形人）已采用仅限官方专属客户端的登录模式，不再输出第三方通用订阅链接。动手导入前先到 [品牌库](/brands/directory/) 核对客户端支持类型，切忌把官网后台登录网址直接粘贴进代理软件。
3. **警惕「挂着死代理更新订阅」的自我锁死**：当现有节点已经大面积失效时，如果在客户端开启了系统代理、TUN 模式或勾选了「通过代理更新订阅」，拉取请求会被硬生生送进死节点里，永远报超时。正确默认姿势是先关闭系统代理与 TUN 尝试直连拉取，只有在确认本地宽带直连屏蔽了订阅域名时，才启用「通过可用备用节点代理更新」。

## 三、场景一：HTTP 200 却返回空内容或 0 节点的四层拆解

比起直接弹出红字报错，`HTTP 200` 成功提示却刷不出任何节点往往更让人困惑。它说明 HTTPS 通信本身已经成功抵达服务器，问题全部出在服务端返回的正文内容与客户端解析规则不匹配。

- **现象**：客户端提示订阅更新成功或日志显示 `200 OK`，但拉下来的配置文件大小为 `0B`、打开策略组里节点数为 0，或紧接着弹窗提示 `yaml: unmarshal errors`、无法解析节点列表。
- **可能原因**：
  1. **账号账期失效返回空体**：部分面板为了避免前端报红，对套餐已过期或当月流量已归零的账号依然返回 `HTTP 200`，但正文是空的 `proxies: []` 或仅包含一条网页到期公告文本。
  2. **订阅格式与客户端解析器错配**：Clash Verge Rev / Mihomo 期待缩进严格的 YAML 文档（必须包含 `proxies:` 与 `proxy-groups:` 结构）；v2rayN / v2rayNG 通用订阅大多采用 Base64 编码的明文节点行（如 `vless://`、`ss://`）；原生 sing-box 则要求标准 JSON 结构。一旦拿 Base64 地址直接喂给未启用自动转换的 Clash，或者把后台网页 HTML 链接当成订阅导入，响应码虽然是 `200`，解析器却完全读不出节点。
  3. **User-Agent 识别落空**：不少机场面板通过识别 HTTP 请求头中的 `User-Agent` 自动决定下发哪种格式。若你在客户端手动修改了冷门或伪装 UA，面板可能误判为普通浏览器访问，直接返回一段登录页 HTML 源码（同样是 `HTTP 200`）。
  4. **服务商收紧第三方接口**：部分曾经开放订阅的品牌后续改为仅限自研专属端登录，旧订阅接口虽然还能吐出 `200` 响应，但内容已被清空或替换为升级客户端提示。
- **低风险检查**：直连登录服务商官网核对套餐有效期与剩余流量；检查面板是否针对 Clash、v2rayN、Shadowrocket、sing-box 分别提供了独立复制按钮；确认 URL 末尾是否带有对应格式参数（如 `&flag=clash` 或 `&flag=meta`）；在本地终端用只读脱敏命令 `curl -sI "你的订阅URL"` 查看 `Content-Type`（若返回 `text/html` 几乎可断定拉回了网页而非订阅文本）与 `Content-Length`。
- **操作路径**：账期异常先按 [套餐到期与旧配置过时区分](/troubleshooting/articles/quota-expired-vs-stale-config) 核实；格式错配时直接回面板点击对应客户端的专属复制按钮重新导入；若怀疑 UA 触发错误模板，在 Clash Verge Rev 配置文件设置中将 User-Agent 恢复为默认 `clash-verge` 或 `clash.meta` 后再拉取；如确认品牌已关闭第三方接口，则按需改用官方端或参考 [机场订阅通用教程](/guides/subscriptions/) 评估兼容方案。
- **验证标准**：重新拉取后本地配置文件体积恢复正常（通常在几十 KB 到数百 KB 之间），`Content-Type` 为纯文本或 YAML 类型，客户端策略组完整显示各地区节点清单。
- **回滚提示**：在重新导入或覆盖旧配置文件之前，先在配置列表里保留旧 Profile 副本或导出个人覆写脚本，确保排查若发现是面板临时故障时，仍可切回原有可用缓存。详尽排查见 [订阅 HTTP 200 返回 0 字节排查](/troubleshooting/articles/sub-http-200-empty)。

## 四、场景二：HTTP 401 / 403 / 404 / 503 与 302 重定向逐码拆解

状态码是服务端写给排障者最直接的诊断标签。先对照下表锁定状态码背后的机制，再执行对应动作：

| HTTP 状态码 | 协议层语义 | 代理订阅场景最高频诱因 | 首选修复方向 |
| :--- | :--- | :--- | :--- |
| **401 Unauthorized** | 身份凭据校验未通过 | 后台点击过「重置订阅链接」、Token 失效、账号异常停用 | 登录用户面板重新复制最新订阅 URL 替换旧链接 |
| **403 Forbidden** | 请求合法但被安全策略拒绝 | Cloudflare WAF 拦截当前机房代理 IP、异常自定义 UA、短时间高频刷新触发限流 | 切换「直连更新 / 代理更新」开关，还原标准 UA 并静候数分钟重试 |
| **404 Not Found** | 目标路径不存在 | 面板升级更换订阅路由、链接复制截断、首尾混入不可见空格或中文字符 | 彻底清空输入框后重新整段复制，核对前缀为完整 `https://` |
| **503 / 502** | 后端服务过载或网关超时 | 机场源站正在重启维护、遭遇攻击或反代节点与面板断连 | 查阅官方通知通道稍候重试，或切换面板公示的备用订阅域名 |
| **301 / 302** | 强制跳转重定向 | 校园网/酒店 Wi-Fi 未完成网页登录认证被劫持，或旧订阅域跳转至新域名/登录页 | 先关代理直连普通国内网站完成网络认证，再用手机热点对照拉取 |

### 401/403/404/503 与 UA 拦截的六步诊断闭环

- **现象**：点击更新订阅立刻弹出红字报错，状态码明确显示 `401`、`403`、`404`、`503`、`502` 或提示重定向次数过多 / 返回 HTML 登录页。
- **可能原因**：
  - **UA 拦截机制**：为了防止爬虫批量扫号或非法第三方聚合站转卖节点，许多机场面板与前置 Cloudflare WAF 会配置严格的 User-Agent 白名单规则，只放行 `clash.meta`、`ClashVerge`、`Shadowrocket`、`v2rayN`、`sing-box` 等主流客户端标识。如果用户自定义了奇特 UA、使用空 UA，或者客户端版本过老被列入拦截黑名单，就会直接收到 `403 Forbidden`。
  - **出口 IP 声誉拦截**：开启「通过代理更新订阅」时，如果当前所连落地机 IP 属于被 Cloudflare 标记为高风险的公共数据中心网段，同样会被直接挡在 403 验证页门外。
  - **凭据与路径变动**：重置订阅链接后旧 Token 立刻作废（`401`）；面板版本迁移导致订阅路径变动或粘贴漏字（`404`）；源站临时维护（`503`）。
- **低风险检查**：先把报错链接粘进纯文本编辑器检查首尾有无空格、回车或多余汉字前缀；核对客户端更新设置当前是「直连拉取」还是「走代理拉取」；查看当前 Profile 是否覆写了自定义 User-Agent。
- **操作路径**：遇 `401` / `404` 直接登录官网核对并重新复制完整新地址；遇 `403` 先关闭客户端代理切回本地宽带直连更新，同时将 UA 恢复为客户端默认值（如 `clash.meta`），切忌一分钟内连续点击十几次加重风控；遇 `302` 先通过浏览器确认本地 Wi-Fi 是否需要网页登录认证；遇 `503` 优先等待 10 至 30 分钟或换用官方备用订阅域名。
- **验证标准**：重新点击更新后状态码回归 `200 OK`，客户端更新时间刷新且无任何报错弹窗，节点列表同步更新完成。
- **回滚提示**：若更换备用订阅域名或切换更新模式后反而转为连接超时，立即还原为原有的主订阅域名与默认直连设置，避免叠加引入新的链路变量。完整逐码实操步骤见 [更新订阅 401/403/404/503 与重定向排查](/troubleshooting/articles/sub-http-401-403-404-503)。

## 五、场景三：TLS 证书错误、DNS 污染与订阅拉取超时

当客户端连 HTTP 状态码都拿不到，直接吐出 `x509`、`tls handshake timeout`、`EOF` 或 `dial tcp: lookup sub.example.com: no such host` 时，故障发生在 HTTPS 握手完成之前的网络解析与加密建连阶段。

- **现象**：拉取订阅持续转圈数秒后失败，日志提示 `x509: certificate has expired or is not yet valid`、`certificate signed by unknown authority`、`DNS lookup failed` 或 `i/o timeout`。
- **可能原因**：
  1. **本机时钟偏差**：电脑或路由器时间错误触发 X.509 证书有效期校验失败。
  2. **本地 DNS 污染或 hosts 残留**：运营商本地递归 DNS 对机场主订阅域名返回了虚假 IP 或 NXDOMAIN，或者本机 `hosts` 文件里留有陈旧的硬编码解析记录。
  3. **订阅域名直连被阻断**：部分服务商未及时轮换国内直连加速域，导致直连拉取在 TLS ClientHello 阶段即被重置（`RST` / `EOF`）。
  4. **代理死循环或中间人证书干扰**：挂着已失效节点开代理更新必然超时；部分公司内网审计网关会替换 HTTPS 证书导致系统报不可信签发机构。
- **低风险检查**：核对操作系统时间与标准北京时间误差是否在 30 秒以内；检查系统 `hosts` 文件是否误写入过订阅域名；关闭所有代理后在手机 4G/5G 热点网络下试拉一次，区分是本地宽带阻断还是订阅域名本身宕机。
- **操作路径**：时间有误先按 [系统时间不同步导致 TLS 握手失败](/troubleshooting/articles/time-sync-tls-cert-error) 完成直连 NTP 校时并重启客户端；若本地宽带直连被污染而手机热点正常，优先登录面板复制**备用订阅域名**，或者先连接客户端里仍存活的任意一条备用节点，再开启一次「通过代理更新订阅」完成拉取；如确认是本地 DNS 异常，排查路由器与系统 DNS 配置并参考 [DNS 错误排查专题](/troubleshooting/dns-error/)。
- **验证标准**：订阅拉取在数秒内完成，日志不再输出 `x509`、`no such host` 或 `TLS handshake timeout`，新节点清单顺利落盘。
- **回滚提示**：切忌为了跳过 `x509` 报错而永久开启客户端的「跳过证书校验（`skip-cert-verify`）」开关，那会让加密链路失去防中间人保护；如果临时通过代理更新了订阅，拉取成功后可按需恢复默认的直连更新选项。完整修复流程见 [更新订阅 TLS 错误与 DNS 超时排查](/troubleshooting/articles/sub-tls-dns-timeout)。

## 六、场景四：Shadowrocket、Clash Verge Rev 与 v2rayN 多端导入与协议差异

同一条订阅链接，在手机上用得好好的，一导入电脑就少了一半节点，或者干脆报错不识别——这是多端协作用户最常遇到的订阅疑难杂症。不同客户端的底层解析引擎、默认请求头与协议栈支持范围存在本质差异：

| 客户端 | 主流依赖内核 | 偏好的原生订阅格式 | 高频导入与解析差异点 |
| :--- | :--- | :--- | :--- |
| **Clash Verge Rev / FlClash** | Mihomo（原 Clash.Meta） | 标准 Clash YAML | 强依赖缩进规范与字段合法性；易受全局 Merge/Script 覆写冲突影响；停更旧 Clash 内核不认 VLESS/Hysteria 2 |
| **v2rayN / v2rayNG** | Xray-core / sing-box | Base64 通用节点串 / 多协议明文行 | 对不同协议需匹配正确核心（如 Hysteria 2 常交由 sing-box 处理）；纯 YAML 文件直接导入易解析异常 |
| **Shadowrocket（iOS）** | 自研闭源多协议引擎 | 通用 Base64 / 专属订阅 / 规则 `.conf` | 极度依赖「全局路由（Global Routing）」选对「配置」；iOS 剪贴板粘贴易带多余字符或未授权 VPN 描述文件 |
| **sing-box 原生端** | sing-box | 严格 Schema JSON | 对 JSON 字段版本要求严苛，不能直接吞入 Clash YAML 或旧版 Base64 链接 |

### 跨客户端表现不一致的真实机制与六步修复

- **现象**：同一份机场订阅在手机 Shadowrocket 或 v2rayNG 上能看到 60 多个节点且全部可用，导入电脑 Clash Verge Rev 或老旧客户端后节点数锐减，甚至直接提示不支持该协议；或者小火箭扫码导入毫无动静、导入后流量全部走直连。
- **可能原因**：
  1. **面板基于 UA 动态分流协议**：机场后台会根据请求头判断客户端能力并下发不同协议组合。本站实测档案中就记录过明确案例：光速云在不同测试工具与请求环境下，分别下发了 Shadowsocks 54/62 节点与 VLESS/AnyTLS 70 节点。如果某个客户端发送的 UA 被识别为老旧版本，面板就会隐藏新协议节点。
  2. **停更内核静默过滤新协议**：仍在使用早已停更的原版 Clash for Windows 或老旧 iOS 客户端（如仅支持传统协议的旧工具）时，面对订阅里的 VLESS、Reality、Hysteria 2 或 AnyTLS 节点，内核无法解析，只能自动跳过过滤，表现为「节点变少」或「策略组为空」。
  3. **自定义覆写脚本破坏原始结构**：Clash Verge Rev 用户开启了网上复制的全局 Merge 或 JavaScript 覆写脚本，如果脚本中引用了新订阅里不存在的代理组名称，导入时就会直接校验失败。
  4. **Shadowrocket 专属配置误区**：小火箭中把「全局路由」错选成「直连（Direct）」会导致节点虽在却全量直连；首次安装未完成 iOS 系统 VPN 描述文件授权会导致开关瞬间弹回；旧 VPN 配置残留也会阻断拉起。
- **低风险检查**：确认全部设备使用的是活跃维护内核（桌面优先 Clash Verge Rev / v2rayN / sing-box，手机优先 Shadowrocket / v2rayNG / FlClash，更多兼容明细见 [客户端软件兼容矩阵](/clients/)）；检查 Clash Verge Rev 是否挂载了第三方全局覆写；检查 Shadowrocket 首页「全局路由」是否为「配置（Config）」。
- **操作路径**：先在 Clash Verge Rev 中暂时关闭所有全局 Merge / Script 覆写，使用纯净原始订阅测试导入与节点数量；核对面板是否需要复制对应客户端的独立订阅参数（如为 Mihomo 勾选兼容标志）；Shadowrocket 用户在「配置」页面确认已加载有效分流规则、全局路由设为「配置」，若 VPN 按钮弹回则前往 iOS「设置 → 通用 → VPN 与设备管理」清理冲突旧配置后重新授权；对于仍停留在停更旧端的用户，按 [旧客户端安全迁移与配置备份指南](/troubleshooting/articles/client-migration-backup) 平滑升级。
- **验证标准**：手机端与电脑端导入后节点数量与协议类型符合面板预期，核心日志无 `unsupported proxy type` 报错，Shadowrocket 分流规则按国内外准确命中。
- **回滚提示**：在调整客户端 UA、更换分流配置文件或清理旧 VPN 描述文件前，务必在本地备忘录（离线加密保存）记下当前仍在正常工作的订阅源与自定义规则名称，一旦新配置不兼容即可一键切回。详尽分端指导见 [Shadowrocket 无法导入订阅与规则排查](/troubleshooting/articles/shadowrocket-import-rules) 与 [同一订阅在不同客户端表现不一致](/troubleshooting/articles/cross-client-inconsistency)。

## 常见问题

### 更新订阅时提示“不能在开启代理时更新”或“直接拉取失败”，应该先开还是先关代理？

绝大多数情况下应先关闭当前客户端的系统代理与 TUN 模式后再直连更新订阅，因为主流机场订阅域名通常在国内可直连或套有加速 CDN；如果当前节点已经全部失效，开着代理去更新订阅反而会把拉取请求送进死节点造成循环超时。只有确认订阅域名在本地直连被阻断或 DNS 污染时，才需要借助可用的备用节点或手机热点拉取。

### 为什么客户端提示更新成功且返回 HTTP 200，节点列表却还是空的或显示 0 字节？

HTTP 200 只表示服务器成功应答了这次 HTTPS 请求，不代表返回的正文就是当前客户端能解析的节点配置。常见原因包括套餐到期或流量归零后后端返回空列表或网页提示文本、把 Base64 通用订阅或 sing-box JSON 误导入了要求 YAML 格式的 Clash 客户端、面板根据 User-Agent 下发了空模板，或者该品牌仅支持专属客户端而不开放第三方通用订阅。

### 更新订阅弹出 401、403、404、503 状态码时，最核心的区别是什么？

401 和 404 属于凭据与路径失效，多因在后台重置了订阅 Token、链接复制不完整带空格或接口路径变更，回面板重新复制即可；403 属于访问被防火墙拦截，常见于 Cloudflare 拦截机房代理 IP 或非标 User-Agent，需切换直连与代理更新对照；503 则是面板源站临时过载或维护，应查看公告并稍候重试。

### 为什么同一个机场订阅在手机 Shadowrocket 正常，导入电脑 Clash Verge Rev 却少节点或直接报错？

机场面板通常会读取客户端发出的 User-Agent 请求头，按不同客户端动态下发不同协议集或配置格式。例如部分服务商会对不同工具分别下发 Shadowsocks 与 VLESS/AnyTLS 节点；此外停更的老旧内核会静默丢弃不识别的新协议，或者电脑端误启用了有语法冲突的全局覆写脚本，导致同一份订阅跨端表现大相径庭。

### 部分品牌只提供专属客户端，为什么我找不到 Clash 或 Shadowrocket 订阅链接？

并非所有服务商都开放标准第三方订阅格式。部分品牌采用自研专属软件，仅允许账号密码一键登录而刻意关闭了 Clash、v2rayN 或 Shadowrocket 订阅导出接口。这类情况属于服务商产品策略而非软件故障，拿网页后台网址硬塞进代理客户端只会拉回 HTML 网页源码导致解析失败。

### 订阅导入报错时，可以把订阅链接丢进网上搜到的第三方在线订阅转换站排查吗？

强烈不建议。完整订阅链接内嵌你的账号鉴权 Token，一旦粘贴到来源不明的公共在线订阅转换站点，对方服务器日志即可完整留存你的订阅凭证，进而存在流量盗刷或节点泄露风险。如需排查返回内容，优先在本地终端使用脱敏命令检查响应头，或直接使用服务商后台原生提供的对应客户端格式。

### Shadowrocket 小火箭扫码或粘贴订阅后完全没反应，或者导入了节点却全部走直连怎么办？

导入无反应先检查链接首尾是否混入空格换行、协议头是否完整，以及该机场是否支持通用订阅；若节点已成功导入却所有网站均走直连，九成是因为小火箭首页的全局路由（Global Routing）被设为了「直连（Direct）」而非「配置（Config）」，将其改回配置模式并确认 iOS VPN 描述文件已授权即可恢复。
