faq:
  - q: 节点测速全部显示 Timeout，一定是机场跑路了吗？
    a: 不一定。本地系统时间误差超过 60 秒导致 TLS 或 VLESS 握手被拒、本地宽带断网或未过校园网认证页、同时开启了其他代理软件或加速器抢占路由、套餐到期或当月流量耗尽、以及长期未更新订阅导致旧中转入口 IP 下线，都会表现为全部节点 Timeout。只有完成本地校时、直连对照、换手机热点复测且官网面板在多网络下连续失联，才应按服务商异常止损处理。
  - q: 为什么列表里只有香港或美国个别节点超时，其他节点正常？
    a: 这通常说明本地客户端、系统代理与基础网络运行正常，故障局限在单条线路或单一地区层面。常见原因包括该编号落地机正在例行维护或更换出口 IP、中转入口端口已轮换而本地订阅尚未刷新、运营商到该方向的跨境链路临时波动，或热门 01/02 号节点并发过载。先刷新订阅并切换同地区靠后编号即可绕行。
  - q: 系统时间只差了一两分钟，为什么会导致全部节点同时超时？
    a: 现代代理协议与底层 TLS 加密强依赖客户端与服务端的双向时间校验。VMess 协议内置防重放窗口，双方时间偏差超过约 90 秒即直接丢弃握手包；VLESS、Trojan 与 HTTPS 订阅依赖 X.509 证书有效期与 TLS 会话校验，本地时钟大幅偏移会触发证书未生效或已过期报错，在前端测速界面往往统一折算为红字 Timeout 或 -1ms。
  - q: 客户端测速显示 Timeout 或 0B，但手动选中节点后网页却能正常打开，这是怎么回事？
    a: 测速工具默认向固定的 204 检测地址发起高并发探测，若机场中转防火墙对高频测速做了限流、目标检测地址被临时屏蔽，或者本地测速超时阈值设置过短，都会出现假性 Timeout 或 0B。判断节点死活应以单节点打开常规海外网页或查看客户端连接日志中的真实往返状态为准，不要迷信一次批量延迟测速。
  - q: 套餐明明还有剩余流量，为什么节点列表突然全部超时且顶部出现异常提示节点？
    a: 先核对机场后台的账期截止时间与流量重置周期。许多月付套餐即便流量尚未用完，只要到达到期时间或跨入购买日重置窗口，后端就会即时停用节点并下发提示信息；此外不限时流量包与月付周期包的生效条件不同。登录用户中心核对有效状态并手动更新一次订阅，即可区分账期问题与旧配置过期。
  - q: 电脑休眠唤醒或 Windows 与 Linux 双系统切换后全部节点变红，最快的修复动作是什么？
    a: 休眠唤醒和双系统因主板硬件时钟基准（本地时间与 UTC）不一致，极易造成系统时间跳变数小时或数分钟。最快做法是先关闭系统代理与 TUN 模式，让操作系统直连 NTP 服务器强制同步标准时间，随后重启客户端核心进程再抽测两三个节点，无需卸载软件或重装订阅。
  - q: 软路由 OpenWrt 断电重启后 OpenClash 或 Nikki 全节点超时死锁怎么打破？
    a: 无备用电池的软路由在断电重启后，系统时钟会回退到固件编译日期。如果路由器开机后立刻把全部流量（含 NTP 校时请求）强行劫持进代理隧道，就会陷入「没校时导致代理握手失败，代理不通又导致无法校时」的死锁。正确解开方式是暂时停用代理插件，或将常见国内 NTP 域名与 UDP 123 端口加入直连放行列表，待时钟同步后再启动核心。

# 节点超时排查：全节点 Timeout 与单区失联分流

## 核心结论（Answer-First）

在代理排障中，客户端界面弹出的 `Timeout`、`-1ms` 或测速 `0B` 并不是某一种单一故障的代名词，而是客户端核心向目标中转入口发起 TCP 建连、TLS 握手或 URL Test 探测后，在预设等待窗口内未收到有效应答的统一结果。面对满屏红字超时，最容易浪费时间的操作就是反复点击全量测速、频繁重启软件或盲目怀疑服务商跑路。

高效定位必须先完成一次**「影响范围分流」**，把故障切分为三条独立路径：**全部节点同时超时**优先查基础联网、系统时钟 60 秒偏差、端口路由冲突与账号账期；**仅单个节点或特定地区超时 / 测速 0B** 优先刷新订阅并切换同地区冷门编号，借助容灾策略组绕开单点维护；**日志显式报证书与握手超时**则直接进入时间同步与 TLS 链路核查。

全篇严格遵循**「现象 → 可能原因 → 低风险检查 → 操作路径 → 验证标准 → 回滚提示」**六步排障标准，先以只读方式排除本地低风险诱因，所有配置调整均保留明确回滚路径，并直接衔接下方 4 篇核心三级实操指南。

## 二、低风险前置核查清单（动手改配置前先做）

在修改配置或调整路由器前，先完成四项只读、零副作用的前置核验：

1. **剥离基础断网**：关掉系统代理与 TUN 后直连国内常规网站，排除宽带断网或校园网/酒店 Captive Portal 认证页拦截。
2. **核对系统时钟**：对照手机标准时间与 `UTC+8` 时区，只要误差超过 30 秒就优先执行 NTP 校时。
3. **确认核心存活**：打开客户端日志确认核心进程正在运行，且后台无其他代理软件、加速器或企业 VPN 争抢路由。
4. **切手机热点对照**：电脑改连 4G/5G 热点抽测 2 个节点；若换网秒通，问题锁定在原宽带光猫、路由器或局域网防火墙。

## 三、深度原理：系统时间偏差 60 秒如何阻断 TLS 与现代代理握手

许多用户在电脑休眠唤醒、Windows 与 Linux 双系统切换、虚拟机挂起恢复，或者 OpenWrt 软路由断电重启后，发现昨天还满屏绿字的节点瞬间全红超时。明明国内网站和聊天软件一切正常，为什么唯独代理节点一个都连不上？核心原因在于现代加密代理协议把**「精确时间同步」**写进了安全握手的前置条件里。

### 1. 协议防重放窗口与 TLS 证书有效期双重约束

- **时间戳防重放机制（VMess 等协议）**：为了抵御网络中间人抓取历史加密数据包后原样重发（重放攻击），协议在加密认证头中强制嵌入当前 Unix UTC 时间戳。服务端收到握手请求后，会用自身精准的服务器时钟与客户端时间戳作差，常见容忍窗口在 60 至 90 秒左右。一旦本地设备时钟快了或慢了超过该阈值，服务端会直接静默丢弃数据包而不返回任何明文错误，客户端苦等几秒后就会在界面显示 `Timeout`。
- **TLS 握手与 X.509 证书有效期校验（VLESS / Trojan / AnyTLS / HTTPS 订阅）**：基于 TLS 1.3 的传输链路在握手阶段必须核验服务端证书的 `NotBefore`（生效时间）与 `NotAfter`（过期时间），并结合会话票据时间戳防伪。特别是无硬件时钟电池的嵌入式设备或软路由断电重启后，系统日期常被重置到固件编译时间甚至数年前，本地核心会认为远端合法证书「尚未生效（`certificate is not yet valid`）」或「已经过期」，立即中止 TLS 握手并报超时。
- **前端界面对底层报错的折叠**：不少图形化客户端的延迟测速模块为了界面简洁，会把 TCP 建连超时、TLS 握手被重置、认证时间戳被拒三种完全不同的失败原因统一折算为红字 `Timeout` 或 `-1ms`。只有点开客户端实时日志，才能看到 `x509`、`tls handshake timeout` 或 `EOF` 等真实线索。

### 2. 排查时钟偏差的六步标准闭环

- **现象**：全部节点（跨港、日、新、美多地区）同一时刻全红 `Timeout`，且故障多发生在休眠唤醒、跨系统重启、换装主板电池或软路由断电恢复之后；日志中可能夹杂 `x509: certificate has expired or is not yet valid` 或 `tls: handshake failure`。
- **可能原因**：操作系统未开启自动网络校时；Windows 默认按本地时间读写主板 RTC 而 Linux 按 UTC 读写导致双系统切换后时差 8 小时；代理开启期间把 NTP 域名或 UDP 123 端口错误送进已失效的代理隧道，导致校时与代理互相死锁。
- **低风险检查**：在终端执行只读时间查询——Windows PowerShell 运行 `Get-Date` 与 `w32tm /query /status`，macOS / Linux / OpenWrt 运行 `date -u` 对比标准 UTC 时间，确认误差是否超过 30 秒。
- **操作路径**：先关闭代理客户端的系统代理与 TUN 模式确保直连；Windows 打开「设置 → 时间和语言 → 日期和时间」，开启「自动设置时间」并点击「立即同步」（必要时管理员 PowerShell 运行 `w32tm /resync /force`）；macOS 在「系统设置 → 通用 → 日期与时间」核对自动设置与时区；OpenWrt 暂停代理插件后在系统设置中点击「与浏览器同步」或配置国内直连 NTP 源（如 `ntp.aliyun.com`、`cn.pool.ntp.org`），同步完成后**重启代理核心**。
- **验证标准**：本地时钟与标准北京时间误差收敛至 2 秒以内，重启内核后抽测 3 个不同地区节点均返回绿字延迟，日志不再输出 `x509` 或 `handshake failure`。
- **回滚提示**：若公司内网组策略锁定了企业内部域控 NTP 服务器，切勿私自删除域控时间配置；记录原 NTP 服务器地址后再临时同步，排查结束后如内网有域认证要求应恢复原企业 NTP 指向。详细全平台校准命令见 [系统时间不同步导致 TLS 握手失败](/troubleshooting/articles/time-sync-tls-cert-error)。

## 四、场景一：全节点同时超时 vs 单区/单节点 0B 超时分层诊断

把「全线失联」和「局部掉线」混为一谈，是日常排障中最容易误操作的地方。前者指向本地环境、账号状态或服务商全局入口故障；后者则往往只是跨境线路的常态维护或单点拥塞。

### 场景 A：全部节点同时超时（Timeout / -1ms）

- **现象**：订阅列表内所有国家与地区的几十个节点一键测速全部报红，逐一手动切换到香港、日本、新加坡、美国任意节点均无法打开网页，客户端连接监控中所有代理请求在握手阶段卡死并报 `i/o timeout` 或 `connectex` 失败。
- **可能原因**：本地基础网络中断或未通过公共 Wi-Fi 认证；本地系统时间偏移超限；电脑残留了已退出的旧代理软件路由或同时运行了多套代理/加速器造成端口与路由环路；账号套餐到期、流量清零或长期未更新订阅致使旧入口全部下线；宽带运营商对当前线路入口做了临时阻断；极少数情况下为服务商中转集群或核心节点全局故障。
- **低风险检查**：依次核查国内直连网页是否秒开、系统时钟误差是否在 30 秒内、任务管理器中是否存在多个代理内核并存，随后切手机 4G/5G 热点做单节点抽测。
- **操作路径**：先彻底退出其余所有代理工具、企业 VPN 与游戏加速器，仅保留当前主力客户端并暂时关闭 TUN 切回基础系统代理；直连登录服务商面板确认账号有效并手动更新一次订阅；如果手机热点畅通而家庭宽带全红，重启光猫与家用路由器刷新宽带拨号 IP 与 DNS 缓存；若日志显示核心自身无法监听本地端口，先查阅 [客户端无法启动排查专题](/troubleshooting/app-not-starting/) 清理残留进程。
- **验证标准**：在港、新、日三个地区各单点测试 1 个节点，均返回合理毫秒延迟，且浏览器访问常规海外测试页面可在数秒内完整加载，连接日志正常记录代理出站字节数。
- **回滚提示**：在未确认是家庭宽带异常前，不要贸然重置路由器出厂设置或执行 `netsh winsock reset` 清空系统网络栈；若临时切换了测试网络或改动了代理模式，确认结论后及时切回日常网络并还原原始模式。完整四层分流操作见 [所有节点同时超时分流排查](/troubleshooting/articles/nodes-all-timeout)。

### 场景 B：仅单个节点或特定地区超时 / 测速 0B

- **现象**：同一份订阅下多数地区节点测速绿字且访问顺畅，唯独你长期固定使用的某个编号（例如香港 01、台湾 02）显示 `Timeout`、`0B` 或速率跌至个位数 KB/s；或者某一个目标地区整组节点延迟突增，而邻近地区一切正常。本站留存的客观实测样本也反复印证了单点波动的常态性：在 `2026-08-11` 批次中，光速云 HK 02 出现 `0B/0B`、宇宙云香港 01 出现 `0.00B/0.00B` 且新加坡 07 仅 `9.60KB/s`、可信云日本 07 仅 `12.61KB/s`；在 `2026-07-19` 微风网络样本中，台湾 02 出现 `0.00B/0.00B` 且日本 05 仅 `8.00KB/s`。这些案例说明，单节点瞬间 `0B` 并不代表整家服务商崩溃。
- **可能原因**：该编号落地服务器正在重启、系统更新或更换上游机房 IP；机场更换了对应中转入口的端口号，但客户端仍在使用数周前缓存的旧配置；某一跨境出口方向发生海底光缆波动或晚高峰单向拥塞；热门的 01/02 号节点被大量用户手动死锁导致并发打满；或者单条线路本身被测速接口限流。
- **低风险检查**：采用**「三区抽样法」**——先在故障地区内跳过 01/02 号，随机抽测 05、08、10 等靠后冷门编号；再在相邻低延迟地区（如香港故障改测新加坡或台湾、日本故障改测新加坡）各抽测 1 个节点；查看连接日志区分 `i/o timeout`（中转入口或路径不可达）与 `EOF / connection reset`（远端落地重启或协议断开）。
- **操作路径**：在客户端点击一次**「更新订阅」**，同步服务商最新下发的中转域名与端口映射；将默认手动选点策略调整为支持自动健康检查的 `URL-Test`（按低延迟自动优选）或 `Fallback`（按预设优先级顺序自动故障转移），避免单台机器重启就让整个网络停摆；若整地区正在维护，临时把常规流量切至邻近地区，把对地区敏感的 AI 工具单独绑定到可用解锁区域（参考 [仅个别网站与 AI 工具打不开排查](/troubleshooting/articles/specific-sites-unreachable)）。
- **验证标准**：切换同地区靠后编号或启用 `Fallback` 后，目标页面恢复稳定加载，客户端日志不再持续重试已失效编号。
- **回滚提示**：如果你原本为特定工作或流媒体平台配置了固定地区分流规则，临时切到邻近地区过渡时请记录原节点组名称；待目标地区维护公告结束并恢复绿字后，再切回原定地区，以免长期跨区切换触发账号风控。详尽解读见 [单节点或特定地区超时与 0B 解读](/troubleshooting/articles/nodes-partial-region-timeout)。

## 五、场景二：套餐到期、流量耗尽与旧配置过时的快速区分

大量「昨天还能用、今天全节点超时」的求助，最后查下来既不是软件故障也不是宽带问题，而是账期变动与客户端静态缓存之间产生了信息差。许多代理客户端不会主动弹窗提醒你「套餐已经到期」，而是继续展示着旧配置文件里的节点名称，等你每次发起请求时再被服务端直接拒连，表面看起来与全局超时毫无二致。

- **现象**：节点列表表面完好无损，但全部节点连接超时或吞吐为 `0B`；或者刷新一次订阅后，节点列表被清空，只剩下一两条类似「剩余流量 0GB」「套餐已过期，请续费」的占位信息节点。
- **可能原因**：
  1. **账期到期或重置日误判**：不少用户以为月底还有几十 GB 流量就能继续用，却忽略了套餐有效期截止日；另一些用户把「按购买日每 30 天重置」误记为「每月 1 日重置」，导致临近周期末流量提前清零。
  2. **高倍率与全量测速偷跑流量**：在不经意间长期挂着 `2x`、`3x` 甚至 `5x` 倍率的专线节点下载大文件，或者频繁触发全节点多线程测速（实测样本中一次 32 线程测 54 个节点即可消耗 19.4GB 流量），导致原本充裕的月流量在几天内耗尽。流量计费机制可对照 [线路倍率计费机制详解](/routes/multipliers/) 与 [测速偏差与倍率核对](/troubleshooting/articles/bandwidth-multiplier-speedtest-diff)。
  3. **长期未更新订阅导致配置过时**：账号明明在有效期内且流量充足，但客户端里的 Profile 已经几个月没更新，期间机场完成了中转 IP 迁移、端口更换或 TLS 证书域名轮换，旧配置里写死的入口早已下线。
  4. **单次重置 Token 后忘记同步全部设备**：在面板重置了订阅链接并在手机端重新导入，却忘了电脑端或软路由仍在使用失效的旧 Token。
- **低风险检查**：关闭代理直连访问服务商官方入口（若忘存入口可先参考 [机场官网与入口核验规范](/brands/official-sites/) 谨防假冒站），依次核对账户页面的三个核心字段：**套餐到期时间戳**、**当月剩余流量（及不限时流量包余额）**、**下次流量重置日期**。
- **操作路径**：若账期和流量均健康，回到客户端执行一次**「更新订阅」**，同时核对配置文件的「上次更新时间」是否刷新为当前时刻；若更新订阅时直接弹出 `401`、`403`、`404` 或 `HTTP 200` 空内容，立刻转入 [订阅失败排查专题](/troubleshooting/subscription-failure/) 按状态码处理；若确认是不小心在面板重置了订阅 Token，则需把新复制的完整订阅链接同步覆盖到电脑、手机与软路由全部终端。
- **验证标准**：面板显示有效账期与充足余量，客户端配置刷新时间戳对齐当前时间，更新后随机抽测 2 个节点延迟恢复绿字。
- **回滚提示**：在客户端用新订阅覆盖旧 Profile 前，先导出备份你手动写过的自定义覆写规则或本地分流白名单，避免覆盖更新把个人规则一并抹掉。详细核对流程见 [套餐到期与旧配置过时快速区分](/troubleshooting/articles/quota-expired-vs-stale-config) 及 [不限时流量包计费规则](/pricing/non-expiring/)。

## 六、看懂测速差异：为什么 TCP Ping、URL Test 与真实下载结果常常打架

排障时，很多人因为过度迷信客户端自带的一键延迟数字，把本来能用的节点当成死节点，或者把已经丢包严重的节点当成健康节点。理清三种测速方式的原理边界，能避免大量无效折腾：

| 测速方式 | 底层测量对象 | 出现 `Timeout` 或 `0B` 时的真实含义 | 常见误判与避坑要点 |
| :--- | :--- | :--- | :--- |
| **TCP Ping（握手延迟）** | 本机到**国内中转入口**的 TCP 三次握手耗时 | 入口 IP 不可达、端口被封、或本地断网/防火墙拦截 | 只能证明中转入口活着，完全测不出跨境传输和海外落地机是否已宕机 |
| **URL Test（HTTP 204 延迟）** | 经由代理节点访问固定测试地址（如 `cp.cloudflare.com/generate_204`）的端到端往返耗时 | 本地时间偏差、落地机断网、测试地址被屏蔽、或高频并发探测触发入口防扫描限流 | 部分机场限制短时间并发测速，建议把并发数调低或改用单点实际访问网页验证 |
| **真实带宽测速（多线程/单线程下载）** | 从境外测速点经节点拉取大文件时的吞吐速率 | 单节点临时维护、落地带宽打满、或当前测试批次探测点受限 | 历史实测图里的个别 `0B` 仅代表该批次瞬时状态，且多线程全量测速极耗流量，日常排障严禁频繁跑全量下载测速 |

关于如何客观解读历史测速表、测试时间与证据边界，可进一步查阅 [测速与证据分级方法论](/methodology)。如果你发现节点并非完全超时，而是延迟绿字正常但网页完全打不开，请立即转向 [连接不上排查专题](/troubleshooting/cannot-connect/)；如果节点能连通但晚高峰持续丢包掉速，请转向 [连接慢、延迟高与丢包排查专题](/troubleshooting/slow-network/)。

## 七、何时判定服务商全局异常并启动止损与备选方案

当且仅当同时满足以下三项客观条件时，才可合理判定故障位于服务商侧而非本地环境：

1. **多网络与多设备交叉验证一致**：在家庭宽带与手机 4G/5G 热点两套独立网络下，已精准校时的两台设备访问全部地区节点均全红超时，且本地国内直连完全正常。
2. **账期与面板状态排除误判**：确认套餐未过期、流量未清零，但更新订阅持续报 `502`/`503`/超时，或官网面板与公告通道连续失联超过 24 小时。
3. **备用服务对照佐证**：在同一台设备切到另一家不同架构的备用订阅立刻满血连通，即可锁定当前主用服务商故障。

触发上述条件后，**立即停止继续修改本机网络栈或网卡驱动**，留存账单与工单截图，对照 [机场跑路识别与止损清单](/security/shutdown/) 与 [品牌替代与迁移方案](/security/alternatives/) 切换备用通道；提交工单务必对订阅链接中的个人 Token 脱敏，参见 [账号与订阅安全指南](/security/account-security/)。

## 常见问题

### 节点测速全部显示 Timeout，一定是机场跑路了吗？

不一定。本地系统时间误差超过 60 秒导致 TLS 或 VLESS 握手被拒、本地宽带断网或未过校园网认证页、同时开启了其他代理软件或加速器抢占路由、套餐到期或当月流量耗尽、以及长期未更新订阅导致旧中转入口 IP 下线，都会表现为全部节点 Timeout。只有完成本地校时、直连对照、换手机热点复测且官网面板在多网络下连续失联，才应按服务商异常止损处理。

### 为什么列表里只有香港或美国个别节点超时，其他节点正常？

这通常说明本地客户端、系统代理与基础网络运行正常，故障局限在单条线路或单一地区层面。常见原因包括该编号落地机正在例行维护或更换出口 IP、中转入口端口已轮换而本地订阅尚未刷新、运营商到该方向的跨境链路临时波动，或热门 01/02 号节点并发过载。先刷新订阅并切换同地区靠后编号即可绕行。

### 系统时间只差了一两分钟，为什么会导致全部节点同时超时？

现代代理协议与底层 TLS 加密强依赖客户端与服务端的双向时间校验。VMess 协议内置防重放窗口，双方时间偏差超过约 90 秒即直接丢弃握手包；VLESS、Trojan 与 HTTPS 订阅依赖 X.509 证书有效期与 TLS 会话校验，本地时钟大幅偏移会触发证书未生效或已过期报错，在前端测速界面往往统一折算为红字 Timeout 或 -1ms。

### 客户端测速显示 Timeout 或 0B，但手动选中节点后网页却能正常打开，这是怎么回事？

测速工具默认向固定的 204 检测地址发起高并发探测，若机场中转防火墙对高频测速做了限流、目标检测地址被临时屏蔽，或者本地测速超时阈值设置过短，都会出现假性 Timeout 或 0B。判断节点死活应以单节点打开常规海外网页或查看客户端连接日志中的真实往返状态为准，不要迷信一次批量延迟测速。

### 套餐明明还有剩余流量，为什么节点列表突然全部超时且顶部出现异常提示节点？

先核对机场后台的账期截止时间与流量重置周期。许多月付套餐即便流量尚未用完，只要到达到期时间或跨入购买日重置窗口，后端就会即时停用节点并下发提示信息；此外不限时流量包与月付周期包的生效条件不同。登录用户中心核对有效状态并手动更新一次订阅，即可区分账期问题与旧配置过期。

### 电脑休眠唤醒或 Windows 与 Linux 双系统切换后全部节点变红，最快的修复动作是什么？

休眠唤醒和双系统因主板硬件时钟基准（本地时间与 UTC）不一致，极易造成系统时间跳变数小时或数分钟。最快做法是先关闭系统代理与 TUN 模式，让操作系统直连 NTP 服务器强制同步标准时间，随后重启客户端核心进程再抽测两三个节点，无需卸载软件或重装订阅。

### 软路由 OpenWrt 断电重启后 OpenClash 或 Nikki 全节点超时死锁怎么打破？

无备用电池的软路由在断电重启后，系统时钟会回退到固件编译日期。如果路由器开机后立刻把全部流量（含 NTP 校时请求）强行劫持进代理隧道，就会陷入「没校时导致代理握手失败，代理不通又导致无法校时」的死锁。正确解开方式是暂时停用代理插件，或将常见国内 NTP 域名与 UDP 123 端口加入直连放行列表，待时钟同步后再启动核心。
