  - q: Miaoko 测试报告中的「IPType」和「IPRisk」字段分别代表什么？数值越低就一定解锁越好吗？

  - q: 报告里常见的「N/A」「未知」「失败 / 请求失败」和「待解锁」有什么本质区别？
    a: 红色「失败」或「请求失败」代表脚本发起了真实探测且被目标平台拒绝或连接异常；黄色「待解锁」或蓝色「未知」代表返回了中间受限特征或未能明确匹配国家码；灰色「N/A」则表示该项探测未执行、被跳过或超时未产出有效结果。切记：N/A、未知与待解锁都绝对不能当成「解锁」或「大概率支持」。

# AI 与流媒体兼容性测试指南：Miaoko 与 RegionRestrictionCheck 字段解读及 31 家品牌矩阵

> **核心结论（Answer-First）**：看懂一份代理节点兼容性报告，能帮你避开绝大多数「商家宣传全解锁、买完才发现根本用不了」的消费陷阱；反之，如果把 **`N/A`** 当成默认可用、把 **`2026-08-11` 纯带宽测速图** 当成流媒体背书、或者看到 **`AI_openai` 标绿就脑补 Claude 和 Gemini 也稳**，反而会被满屏彩色格子严重误导。本文逐列拆解 **Miaoko** 与 **RegionRestrictionCheck** 两大主流测试工具的工程字段含义，给出站内 **31 家去重机场品牌的 `measured` / `vendor` / `Not Tested` 完整对照矩阵**，并附上不耗流量的 5 分钟本地自测 SOP。

## 一、深度解读 Miaoko 与 RegionRestrictionCheck 报告的每一个核心字段

在中文代理排障与评测生态中，流媒体与 AI 兼容性测试主要围绕两套工具体系展开：**`RegionRestrictionCheck`**（开源单机命令行脚本，适合检测当前单一落地出口的即时状态）与 **`Miaoko`（含喵速插件）**（面向机场订阅的批量多节点探测面板，生成带颜色标签的横向矩阵图）。

结合本站真实留存的光速云两套不同模板 Miaoko 截图（三网 62 节点 `normalspeed` 模板与珠海联通 70 节点 `test - 基础流媒体` 模板）及无忧链接 `ynd - 御三家流媒体` 截图，真正读懂报告必须盯紧下面五大区块：

### 1. 基础环境、协议与双延迟列

- **顶部与底部元数据**：包含测试模板名称（如 `normalspeed`、`test - 基础流媒体`、`ynd - 御三家流媒体`）、测试后端运营商与带宽（如 `广西移动@2Gbps`、`长沙电信@2Gbps`、`河北联通@2Gbps`、`珠海联通 9Gbps单线程`）、并发线程数（`6 线程`、`32 线程` 或 `单线程`）以及底部测试时间戳。**务必核查底部有无具体年月日时间戳**——例如光速云 5 张归档 JPG 底部均未印出日期（标注 `archive-folder-only`），而无忧链接 `wuyou-2.jpg` 明确印有 `2026-07-18 21:47:23 (CST)`。
- **`类型`（协议列）**：直接显示脚本拉取并实际跑通的传输协议（如 `Shadowsocks`、`Vless`、`AnyTLS`）。阅读时一定要与品牌宣传文案交叉比对——本站审计发现，多款品牌文案写 `VLESS` 或 `Trojan`，实测截图却跑在 `Shadowsocks` 上，或像光速云 70 节点图一样混用了 `60 Vless + 10 AnyTLS`。
- **`TLS RTT` vs `HTTPS 延迟`**：Miaoko 底部明确给出了工程注释——`TLS RTT` 为 **单次数据交换延迟**，`HTTPS Ping`（HTTPS 延迟）为 **单次请求体感延迟**。两者常常差距悬殊：例如 `guangsuyun-miaoko-streaming-ai.jpg` 中 `JP日本02` 的 `TLS RTT` 仅 `262ms`，但 `HTTPS 延迟` 飙升到 **`3028ms`**！如果你打开网页首屏转圈发粘，真正拖慢体验的往往是高达两三秒的 `HTTPS 延迟`（详见 [低延迟与 TLS RTT 真相](/routes/low-latency/)）。

### 2. IP 质量与风控列：`IPType`、`IPRisk` 与 `ASN`

在 Miaoko 进阶模板（如光速云三网 62 节点 `normalspeed` 截图）和专业 IP 质量检测脚本中，这三列直接揭示落地服务器的“出身”与历史污点：

| 工程字段 | 实测截图常见取值示例 | 真实含义与实战判读标准 |
| :--- | :--- | :--- |
| **`IPType`** | `商宽/机房IP`、`ISP` / `Residential`、`Business` | 标识出口 IP 所属网络实体类型。平价与常规机场绝大部分显示 **`商宽/机房IP`**（即托管数据中心或商业宽带段，如光速云三网 62 节点全员显示 `商宽/机房IP`）；真正稀缺的民用家庭宽带才会显示 `ISP / Residential` |
| **`IPRisk`** | `LOW(1)`、`LOW(9)`、`MEDIUM(1)`、`MEDIUM(30)`、`HIGH` | 反映该出口 IP 在综合风控/欺诈库中的风险级别与分值。数值越低，触发 Cloudflare WAF 1020 或基础反爬虫挑战的概率通常越低；**但切忌绝对化**——实测中美区 `LOW(1)` 节点依然在 Gemini 全线失败，新加坡 `MEDIUM(30)` 反而全线解锁 |
| **`ASN`** | `US-KOMI-NET-AS401243`、`HK-LSHIY-USER-CONTENT-AS32167`、`TW-Peg Tech-AS398993`、`US-Yancy-AS138415`、`AS136258` | 出口 IP 归属的自治系统编号与上游实体。注意看 **前缀国家码与节点地名是否一致**（例如日本/新加坡节点挂着 `US-KOMI-NET`，说明属跨区广播段），同一 ASN 往往共享相近的风控命运（如 `AS136258` 下英/法/德/泰四国节点在 Gemini 列全部失败） |

### 3. 流媒体与 AI 探测列：`INTL_*`、`GMT_*`、`JP_*` 与 `AI_*` 全解

不同测试脚本会按平台地域属性给探测列加上前缀，弄懂前缀才能看清每列的真实门槛：

| 报告列名 | 对应目标平台 | 括号地区码与特殊状态重点看什么 |
| :--- | :--- | :--- |
| **`INTL_youtube`** | YouTube（含 GGC 与地域定位） | 盯紧是否出现橙色 **`送中(CN)`**、蓝色 **`未知`** 或跨区偏移（如美区节点显 `解锁(HK)`）；详见 [YouTube 送中排查](/ai-media/youtube/) |
| **`INTL_netflix`** | Netflix 非自制剧版权库 | 区分绿标全区 **`解锁(XX)`** 与受限 **`仅自制剧`**，同时核对括号国家码是否漂移（如光速云台湾节点显 **`解锁(GB)`**）；详见 [Netflix 解锁解析](/ai-media/netflix/) |
| **`INTL_disney_plus`** | Disney+ 国际流媒体 | 对非住宅机房封控较严，常出现台湾或欧洲节点标红 `失败` 或跨区识别为 `US`/`GB`/`HK` |
| **`GMT_bilibili`** | Bilibili 港澳台番剧区 | 显示 **`解锁(港澳台地区)`** 代表可看 B 站港澳台限定版权新番；许多机场在日、美、新节点上也通过服务端分流挂载了港澳台解锁 |
| **`INTL_tiktok`** | TikTok 国际版 | 除正常国家码外，常出现 **`解锁(ALISG)`**（经特定云/新加坡分流出口识别）或标红 **`失败`**；注意手机端还须叠加排查本地 SIM 卡运营商与系统语言 |
| **`INTL_dazn`** | DAZN 体育流媒体 | 极易受跨境分流影响，实测中美国节点常显 `解锁(TW)` 或黄色 **`待解锁`**，台湾节点显 `解锁(GB)` |
| **`JP_abema`** | 日本 Abema TV | 日本本土极严流媒体，常见红色 `失败` 或经特定分流后的 **`本土解锁(JP)`** |
| **`GMT_bahamutanime`** | 台湾巴哈姆特动画疯 | 动漫党核心指标，绿标 `解锁` 代表可正常观看台区正版番剧，红色 `请求失败` 则无法播放 |
| **`AI_openai` / `OpenAI`** | OpenAI / ChatGPT | 重点区分绿标全端 **`解锁(US/JP/SG/TW)`** 与受限的橙黄色 **`仅APP(HK)`**；详见 [ChatGPT 机场适配](/ai-media/chatgpt/) |
| **`Gemini`** | Google Gemini | 仅部分模板包含此列（如光速云三网 `normalspeed` 含 `Gemini`，而珠海联通 70 节点图与无忧链接图均不含）；极易大面积标红 `失败`；详见 [Gemini 区域可用性](/ai-media/gemini/) |
| **`INTL_steam`** | Steam 商店货币识别 | 显示 **`货币: HKD / JPY / USD / SGD / GBP`**，直观印证出口或分流归属地（如光速云台湾节点因走英国分流池导致 Steam 亦显 `货币: GBP`） |

### 4. 八种状态标签的精确工程语义（绝不误判灰色 `N/A`）

1. **`解锁(XX)`**（绿色）：探测成功且目标平台判定出口归属括号内的国家/地区。
2. **`本土解锁(XX)` / `解锁(ALISG)`**（绿色）：通过特定本土或特定分流网关解锁细分平台。
3. **`仅APP(HK)`**（橙黄）：移动端接口侥幸未封，但网页端已被地域封锁，不可作主力。
4. **`送中(CN)`**（橙色）：出口 IP 被 Google 定位回中国大陆，影响会员、离线与 Gemini。
5. **`待解锁` / `仅自制剧`**（黄色）：仅能打开基础页或自制内容，第三方核心版权/完整功能受限。
6. **`未知`**（蓝色）：目标返回了非标准响应，脚本无法确认归属地区，不可视为稳定解锁。
7. **`失败` / `请求失败`**（红色）：探测请求被明确拒绝、风控拦截或连接中断。
8. **`N/A`**（灰色）：**该项未测试、被前置过滤跳过或探测超时无返回——严禁将其解读为「支持」或「能用」！**

## 二、测试方法论与四大防误导铁律

在阅读本站或任何第三方社区的兼容性报告时，必须坚守以下四条方法论原则（完整证据标准见 [数据与测速方法论](/methodology)）：

1. **铁律一：严禁拿纯测速图和无工具文本表推导解锁**
   站内 `2026-08-11` 批次的 16 张 PNG 截图（涵盖光速云、SOGO、U1S1、二猫、飞猫、光年梯、极连、可信、灵猫、全球、速界、唯兔、星岛梦、一翻、宇宙及未入库实体快狸）与 `2026-07-19` 微风测速图，**全部只测速度、延迟与 UDP，没有任何 AI 或流媒体解锁列**；而 `2026-10-19` 附带在 15 家品牌资料上的五地非晚高峰文本表格更缺乏工具与原始截图，且跨品牌数值高度趋同。这两类数据 **零解锁证明力**。
2. **铁律二：严禁跨 AI 平台横向推导**
   实测已多次证明 `OpenAI 解锁 ≠ Gemini 解锁`，且全站现存实测图均不含独立 `Claude` 探测列。任何评测把「ChatGPT 能用」自动扩写为「全系 AI 畅通」，均属违规推导。
3. **铁律三：任何测试图都只是「单时刻快照」，不是永久契约**
   平台风控名单与机场后端落地 IP 池每周都在动态博弈。超过 30 天的历史截图（包括 `2026-07-18` 无忧链接、`2026-07-20/21` 灵动云历史摘要以及 `2026-08-19` 归档光速云截图）只能反映该品牌过往的运维透明度与典型问题模式，不能取代你当月用小额月付亲手验证。
4. **铁律四：区分「单线程解锁连通」与「晚高峰大带宽稳定」**
   Miaoko 流媒体检测脚本只向目标网站发送轻量级 HTTP/HTTPS 探测请求，**一个平均速度跌到 `1.60KB/s` 或 `17.59KB/s` 的拥塞节点，在流媒体探测列里照样可能亮起绿色的 `解锁(US)`**！必须把「解锁图」与「晚高峰速度/丢包图」交叉对照，才能判断能不能流畅看 4K。

## 四、5 分钟零脚本自测与 `RegionRestrictionCheck` 安全核验 SOP

买完一个月付试用套餐后，无需轻信商家宣传图，也不用冒着刷光流量的风险跑全节点 32 线程测速，按以下两套方法即可快速完成专业级验收：

### 1. 普通用户 5 分钟浏览器无痕自测 SOP（零额外流量浪费）

依次切到你打算当主力的 2–3 个常用节点（建议优先测 1 个香港 + 1 个日本 + 1 个美国或新加坡），全程在 **浏览器无痕窗口** 执行五步检查：
1. **查出口 IP 归属与 ASN**：访问 `ipinfo.io` 核对实际出口国家、城市与 ASN 组织名称，确认不是莫名其妙的跨洲绕行，同时排除 DNS 泄漏（参考 [DNS 污染与泄漏修复](/troubleshooting/articles/dns-leak-hijack-fix)）。
2. **查 YouTube 地区与送中**：无痕访问 `youtube.com` 看左上角国家码与广告是否正常，再试访 `music.youtube.com` 确认未报地区不可用；顺手点开一段 4K 60fps 视频查看 `Stats for nerds` 单线程 `Connection Speed`。
3. **查 Netflix 非自制版权剧**：登录账号后直接搜索一部知名第三方版权剧（不要只看首页自制剧海报），同时留意默认字幕与推荐榜单语言是否发生了 `GB`/`ES` 跨区偏移。
4. **查 ChatGPT 与 Gemini 独立可用性**：分别访问 `chatgpt.com`、`gemini.google.com` 与 `aistudio.google.com`，确认未报 `Unsupported country` 或 `Error 1020`，且登录后可连续完成 2–3 轮对话。
5. **谨慎评估 Claude**：先在客户端建立独立 `select` 策略组锁死单个美/日/新节点，用备用免费邮箱小号观察 3–7 天无 403/频繁验证码后再考虑接入重要账号（详见 [Claude 防封指南](/ai-media/claude/)）。

### 2. 进阶用户使用 `RegionRestrictionCheck` 单出口核验要点

如果你拥有自建落地 VPS（如做链式代理），或希望在本地终端只对「当前连着的这一条节点」跑一次结构化输出：
- 在开启了 [TUN 模式](/guides/tun-mode/) 或正确配置终端代理端口（`HTTPS_PROXY`）的环境下运行开源 `RegionRestrictionCheck` 脚本，只检测当前单条落地出口，单次探测消耗流量通常仅数 MB，完全不会像全订阅批量测速那样刷爆小流量包；
- 核对脚本输出时，重点留意 **IPv4 与 IPv6 两组结果是否一致**——如果 IPv4 全绿解锁但 IPv6 全部失败或偏移，记得回到客户端直接关闭 IPv6 出站（详见 [分流规则配置指南](/guides/split-routing/)）。

### 3. 识破「水分测试图」与裁剪绿标的五项快速核查清单

在社交群组或推广帖里看到某机场晒出一张「全绿解锁图」时，不要急着掏钱买年付，先花 30 秒核对下面五个防伪细节：
1. **看底部有没有完整年月日时间戳与工具版本**：如果图片故意裁掉底部测试日期、后端运营商和并发线程数，你根本无从分辨这是一周前的现状，还是半年前刚开服时留下的老古董快照（例如本站审计中明确标出了光速云 5 张归档图无底部时间戳、可信云 `08-11` 图日期被截断、微风文件名与图内真实日期不符等异常，绝不隐瞒）。
2. **看有没有把「节点数」偷偷过滤裁短**：正经全量报告会在底部标明 `概要=70/70` 或 `概要=50/50`，显示全订阅所有节点（包含失败、`0B`、`N/A` 与送中节点）；如果某张宣传图只截出精挑细选的 6 条绿标节点而隐藏了其余 50 条节点的失败与送中状态，参考价值近乎为零。
3. **看延迟列是不是同时展示了 `TLS RTT` 与 `HTTPS 延迟`**：只放本地 Ping 或单一 `TLS RTT` 掩盖了真实网页首屏体感，必须核对两项延迟以及晚高峰时间点（`20:00–23:30 CST`）。
4. **看括号里的国家码有没有发生跨区漂移**：一片绿色里藏着 `TW台湾 → 解锁(GB)` 或 `美国 → 解锁(HK)`，远看全是绿的，细看才会发现版权区或 Google 归属已经彻底偏移。
5. **看测试列有没有覆盖你真正要用的平台**：哪怕整张图把 Netflix、Disney+、Abema、Bilibili 全测绿了，只要图里没有 `Gemini` 列和 `Claude` 列，就绝对不能听信推广文案说「全系 AI 完美支持」，必须按 [机场避坑指南](/security/avoid-pitfalls/) 与 [月付机场筛选](/pricing/monthly/) 先小额自测。

## 五、常见问题

### Miaoko 测试报告中的「IPType」和「IPRisk」字段分别代表什么？数值越低就一定解锁越好吗？

IPType 反映出口 IP 归属的自治域类型（常见如商宽/机房IP、ISP 家庭宽带、Business 商业宽带），IPRisk 反映该 IP 在反欺诈与滥用库中的风险等级和分值（例如光速云三网图中常见的 LOW(1)、LOW(9)、MEDIUM(1)、MEDIUM(30)）。但数值越低不等于所有平台都能解锁：同一批实测中，IPRisk 低至 LOW(1) 的美国节点在 Gemini 列全部失败，反倒是 MEDIUM(30) 的新加坡节点全绿解锁(SG)，解锁结果需同时结合平台自身地区库与服务端分流规则判断。

### 报告里常见的「N/A」「未知」「失败 / 请求失败」和「待解锁」有什么本质区别？

红色「失败」或「请求失败」代表脚本发起了真实探测且被目标平台拒绝或连接异常；黄色「待解锁」或蓝色「未知」代表返回了中间受限特征或未能明确匹配国家码；灰色「N/A」则表示该项探测未执行、被跳过或超时未产出有效结果。切记：N/A、未知与待解锁都绝对不能当成「解锁」或「大概率支持」。

### 为什么站内明确禁止用 2026-08-11 批次的 16 张测速图或 2026-10-19 五地表格来判断 AI 和流媒体解锁？

因为 2026-08-11 的 16 张 MAI-TEST-BOT/MiaoSu 截图只包含延迟、下载速率与 UDP/NAT 类型，完全不含任何 AI 或流媒体检测列；而 2026-10-19 附带在 15 家品牌上的五地文本表格既无截图、无工具与线程说明，又存在跨品牌数值区间高度趋同问题。纯测速数据只能反映那一刻的吞吐，绝不能用来推导解锁兼容性。

### Miaoko 报告里的「TLS RTT」和「HTTPS 延迟」为什么有时相差十倍？看哪个更贴近实际体验？

TLS RTT 是单次 TLS 数据交换耗时，反映底层隧道握手的物理往返；HTTPS 延迟则包含建连及完整网页请求的体感耗时。例如在光速云珠海联通 70 节点图中，JP日本02 的 TLS RTT 为 262ms，HTTPS 延迟却高达 3028ms。日常打开 AI 网页端、刷社媒和加载图片，HTTPS 延迟往往更能反映首屏会不会发粘转圈。

### 为什么一张测试图里 OpenAI 显示绿标「解锁(US)」，却不能据此推定该机场也支持 Claude 和 Gemini？

OpenAI、Anthropic（Claude）与 Google（Gemini）三家独立维护地区白名单、ASN 封控黑名单与 GeoIP 位置纠偏库。光速云三网实测图已经给出了最直接的反证：日、美、台多节点在 OpenAI 列绿标解锁，但在同一行紧挨着的 Gemini 列全部标红失败；而现有实测图更没有任何独立的 Claude 探测列，因此严禁跨平台推导。

### 为什么站内 31 家品牌对照矩阵里没有「快狸」？

「快狸（kuaili）」虽然出现在 2026-08-11 的测速资料包（kuaili-20260811.png，50/50 节点 VLESS 纯测速图）中，但它完全不在 31 家品牌清单里，缺少套餐价格、运营年份、官网/推广入口与条款信息，且该图同样不含流媒体或 AI 解锁列。按本站数据审计规范，快狸已单独隔离归档为待补充证据实体（pending-evidence），不混入 31 家品牌矩阵。

### 如果正在使用不限时流量包或小流量套餐，可以经常自己跑 Miaoko 全节点批量测试吗？

绝对不建议。Miaoko 的全订阅测速与流媒体并发探测会在短时间内对几十个节点轮番下载测速文件，单次高线程跑分就可能消耗数 GB 甚至几十 GB 宝贵流量。使用不限时包或小流量包的用户，只应在浏览器无痕窗口里对打算使用的 2–3 个固定节点进行手工单点功能复核。
