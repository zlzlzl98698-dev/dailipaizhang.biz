faq:
  - q: 为什么代理已经连上且测速很快，ChatGPT、Claude 或 Gemini 却依然报错？
    a: 测速快只能证明从你本地设备到代理落地出口之间的链路带宽充足、延迟低，而 AI 平台是否放行取决于四大独立变量：出口 IP 所属国家是否在平台白名单内（香港默认不在 OpenAI、Anthropic 与 Google AI 常规支持区）、出口 IP 的 ASN 类型与历史滥用信誉（IPType 与 IPRisk）、本地 DNS 与分流规则是否漏域，以及浏览器残留的旧风控 Cookie。
  - q: 某机场的节点实测支持 ChatGPT，能直接推导出它也一定支持 Claude 和 Gemini 吗？
    a: 绝对不能。OpenAI、Anthropic 与 Google 三家采用完全独立的服务区域白名单、ASN 风控黑名单和 GeoIP 地理位置修正库。即便在同一家机场的同一批实测中（例如光速云 2026-08-19 归档目录 Miaoko 截图），很多节点在 OpenAI 栏显示分流解锁(US)或(JP)，但同一批节点在 Gemini 栏却大量显示失败；而 Claude 在现有公开实测图中甚至没有单独的探测列，因此严禁横向推导。
  - q: Miaoko 测试图里香港节点 OpenAI 显示「仅APP(HK)」是什么意思？能当主力使用吗？
    a: 「仅APP(HK)」指节点本身仍位于香港原生或未做网页分流出口，移动客户端部分 API 通道暂未拦截，但网页端（chatgpt.com）与桌面全功能处于地域封锁或高概率受限状态。在光速云 2026-08-19 归档目录的三网 Miaoko 测速图（62 节点 Shadowsocks）中，香港专线节点便普遍呈现仅APP(HK)。这种状态随时可能因平台收紧移动端校验而失效，不应作为主力生产力依赖。
  - q: 为什么 31 家机场品牌资料中，绝大多数都把 Gemini 标注为「视节点而定」？
    a: 因为 Google 对自有 GeoIP 地理位置数据库更新极其频繁，且与 YouTube 定位信号高度联动。一旦某个新加坡或台湾共享节点的出口 IP 被大量带定位权限的移动设备上报中国大陆坐标而发生「送中」，或者香港节点未将 gemini.google.com、aistudio.google.com 单独分流到支持区落地，Gemini 就会立即提示所在地区不受支持，因此任何机场都很难保障全部节点长期稳定可用。
  - q: 使用 Claude 时为什么很容易遇到 403 拦截或账号封禁？
    a: Anthropic 对商业数据中心（IDC）机房 IP 段、并发自动化特征以及账号登录期间的 IP 国家高频漂移极其敏感。如果使用大量用户共用的低价机房 IP，或在 Clash 等客户端中开启 url-test 自动测速导致对话期间出口在美、日、新之间频繁跳动，极易触发安全风控并引发账号停用。
  - q: 什么是 Netflix 的「仅自制剧」和「落地识别偏差（如台湾节点识别成 ES 或 GB）」？
    a: 当 Netflix 识别出出口 IP 属于普通商业机房代理时，会屏蔽第三方版权影片，只允许播放 Netflix 原创自制剧（Originals）。而为了提供全区版权库，许多机场会在后台通过 DNS 劫持或分流把流媒体流量统一送到少数专用落地机上，导致「节点名称所在国」与「实际识别版权国」不一致——例如灵动云 2026-07-20/21 实测记录中台湾落地被 NF/D+ 识别为西班牙（ES），光速云 2026-08-19 目录 Miaoko 图中 TW 台湾 01–10 的 Netflix 与 Disney+ 则显示解锁英国（GB）。
  - q: 什么是 YouTube「送中(CN)」，为什么新加坡和台湾节点在实测中反而经常出现？
    a: 「YouTube 送中(CN)」指海外节点的出口 IP 被 Google 地理定位系统纠正为中国大陆（CN），症状包括看视频无广告、离线缓存/后台播放受限、家庭组或部分音乐/版权内容异常。成因通常是大量安卓/iOS 手机在连着代理时开启了 Google 应用位置授权，把国内 GPS 与 Wi-Fi 定位信息持续关联到该节点 IP 上。在光速云 70 节点 Miaoko 实测中 SG01–10 与 TW 多节点均出现送中(CN)，而无忧链接 2026-07-18 实测中也记录了香港 HKG-01 送中(CN)。
  - q: 测速报告里的 IPType 与 IPRisk 字段怎么看？「原生住宅 IP」真的存在吗？
    a: 在 IP 质量检测与高阶测试面板中，IPType 用于区分出口 IP 归属的 ASN 类型（如 ISP 家庭宽带、Business 商业宽带、Hosting 数据中心机房），IPRisk 则反映该 IP 在欺诈库与滥用库中的风险评分。普通机房（Hosting）只要 IPRisk 够低且配合分流也能看流媒体，但面对 Claude 或 TikTok 等极严风控时，低风险 ISP/原生段更有优势；不过市面上少数商家宣称的「全节点原生住宅 IP」若无独立测试佐证，一律只能视为品牌宣传（vendor）。
  - q: 2026-08-11 批次的 16 张机场测速截图和 2026-10-19 表格，能用来判断哪家解锁 AI 或 Netflix 吗？
    a: 完全不能。2026-08-11 批次的 16 张 MAI-TEST-BOT / MiaoSu PNG 截图只记录了节点延迟、下载速率与 UDP/NAT 类型，没有包含任何 AI 或流媒体解锁探测列；而 2026-10-19 附带的五地文本表格更是缺少工具与方法论披露。判断解锁兼容必须查看包含对应测试列的 Miaoko 报告，或先购买短周期月付套餐在本地实测。
  - q: Miaoko 测试图里显示的「N/A」能算作基本支持或待解锁吗？
    a: 不能。测试表中的「N/A」通常代表该项探测脚本未执行、被前置条件跳过或通信超时未形成有效判定结果，它与明确标绿的「解锁(XX)」以及标红的「失败/请求失败」不同，绝对不能把 N/A 推定为可用。
  - q: 切换到了标注解锁的美国或日本节点，为什么浏览器打开 ChatGPT 或 Gemini 仍然报错？
    a: 这通常是本地环境残留了「被拒绝的历史状态」或分流配置漏域。建议先打开浏览器的无痕/隐私窗口清除目标站点 Cookie 与 LocalStorage 重试；若无痕模式仍报错，检查 Clash/sing-box 分流规则是否漏掉了认证与静态资源域名（如 oaistatic.com、anthropic.com、aistudio.google.com），以及客户端是否泄漏了本地直连 DNS。
  - q: 如果自己有可疑节点，应该如何用 RegionRestrictionCheck 或 Miaoko 自行验证？
    a: 如果你想检测当前本地客户端所连接的单条落地出口，可以在目标 VPS 或具备本地代理环境支持下运行开源的 RegionRestrictionCheck 脚本查看各大流媒体与 AI 返回码；如果是批量评测机场订阅里的几十个节点，则常借助 Miaoko 等支持多线程批量探测各平台与记录 TLS RTT、HTTPS 延迟的工具，同时务必先避开不限时流量包以免跑分消耗大量流量。

# AI 与流媒体解锁兼容指南：出口 IP、区域路由、DNS 与实测证据边界

> **核心结论（Answer-First）**：**「Proxy 能连通、测速几百兆，但 ChatGPT 报区域不可用、Claude 秒封、Gemini 提示不支持、Netflix 只出几部自制剧、YouTube 被定位回大陆」**——这些现象极少是客户端软件故障，而是目标平台对 **「出口 IP 信誉与 ASN 类型（IPType/IPRisk）」**、**「区域白名单与服务端分流路由」**、**「DNS 解析链路」** 以及 **「账号与浏览器本地缓存」** 四道关卡同时校验的结果。阅读本站任何品牌的 AI 与流媒体兼容信息时，必须严格区分 **「实测截图证据（measured）」**、**「品牌资料宣称（vendor）」** 与 **「未测试（Not Tested）」**，**严禁从「支持 ChatGPT」横向推导「一定支持 Claude 或 Gemini」**，更不能拿仅测速度的截图当解锁背书。

## 一、平台风控严苛度梯队：为什么同一条线路表现截然不同

跨国网络服务对于代理流量和机房 IP 的容忍度并非一刀切，从宽松到严苛大致分为四个技术梯队：

1. **第一梯队：CDN 就近调度与地理位置纠偏型（代表：YouTube）**：
   YouTube 通常不封锁普通数据中心（Hosting）IP，只要线路通畅就能播放 1080p 或 4K 视频。它的核心痛点不在“连不上”，而在于 Google 位置推理库一旦把某出口 IP 纠正为中国大陆，就会触发 **「YouTube 送中(CN)」**，影响无广告、后台播放及部分会员与音乐权限。
2. **第二梯队：版权分级与双层解锁检测型（代表：Netflix、Disney+、HBO Max）**：
   这类流媒体平台拥有庞大的地域版权分账协议。当它们识别到出口 IP 属于普通商业机房时，Netflix 往往不会直接封号或断连，而是降级为 **「仅解锁自制剧（Originals Only）」**，把第三方版权电影与热门剧集全部隐藏；Disney+ 与 HBO Max 则更倾向直接拦截报错。
3. **第三梯队：强区域白名单 + 机房并发风控型（代表：ChatGPT、Gemini）**：
   OpenAI 与 Google AI 在服务条款与技术网关层面对未覆盖地区（包括香港、部分高风险地区）执行明确拦截，同时配合 Cloudflare 或自有反滥用网关，对高并发共享机房 IP 频繁弹出人机验证、403/1020 错误或降级响应。
4. **第四梯队：账号连坐与住宅/运营商段倾向型（代表：Claude、TikTok）**：
   Anthropic Claude 与 TikTok 对高密度共享的廉价 IDC 机房段、异常自动化特征以及短时间内频繁跨国切 IP 极度敏感。一旦触发风控，往往不仅是单次网页报错，而是直接拒绝注册、触发手机二次验证甚至导致账号停用。

## 二、决定 AI 与流媒体能否正常访问的四大核心因素

无论使用哪一家机场或哪一款代理客户端，最终能否稳定使用 AI 与流媒体服务，均由下面四个层面的协同状态共同决定：

### 1. 出口 IP 信誉与 ASN 归属类型（原生/住宅 vs 商宽/机房）
目标网站在收到你的 HTTPS 请求时，首先读取的是最后一跳 **「落地出口服务器」** 的公网 IP，而非你本地宽带 IP，也不是机场用来接国内流量的「中转入口 IP」。平台会查询该出口 IP 所属的自治系统编号（ASN）：
- 属于亚马逊 AWS、Google Cloud、阿里云、DigitalOcean 或常见廉价托管机房的 IP，在风控库里普遍标记为 **数据中心（Hosting / DataCenter）**，极易在流媒体版权库和高敏 AI 平台受限。
- 若出口 IP 属于当地宽带运营商或商业宽带（ISP / Business），且同一出口上并发注册 AI 账号的陌生人较少，风控分值（IPRisk）就会明显更低。

### 2. 区域路由与服务端分流落地策略
很多用户只看节点名称写着「香港 01」「台湾 02」就以为流量一定从香港或台湾本地原生出口直出，其实大型专线机场普遍存在 **「入口地区 ≠ 落地地区 ≠ 特定域名分流落地地区」** 的三层转发架构：
- **普通直出节点**：比如香港节点直接由香港落地发出所有请求。由于香港不在 ChatGPT、Claude 与 Gemini 的常规支持列表内，此类节点访问 AI 必然触发区域拒绝。
- **服务端规则分流节点**：机场在落地机后端对 `openai.com`、`netflix.com`、`disneyplus.com` 等特定域名做了劫持转发（例如把香港节点上的 OpenAI 流量转送到美国或日本解锁机，或把台湾节点上的 Netflix 流量转送到英国或欧洲解锁机）。这能解释为什么节点明明叫「香港」却能打开 ChatGPT，也能解释为什么节点叫「台湾」看 Netflix 却变成了英国区或西班牙区片库。

### 3. DNS 解析链路与客户端分流精度
即便机场节点的落地 IP 本身完全干净解锁，如果本地客户端的 DNS 配置或分流规则出现偏差，一样会导致访问失败：
- **DNS 泄漏或直连解析**：如果浏览器开启了异步安全 DNS（DoH）且未走代理，或者客户端规则把某些二级 API 域名错误判为 `DIRECT`（直连），会导致身份认证请求走美国节点、而后续静态资源或 API 校验请求走本地宽带甚至香港节点，目标网关瞬间识别出「双地 IP 冲突」并直接拦截。
- **Fake-IP vs Redir-Host 影响**：在 Mihomo 或 sing-box 客户端中正确使用 Fake-IP（`198.18.0.0/16`）把域名交给远端落地解析，能够有效避免本地 DNS 污染导致的错误 CDN 调度；详见 [DNS 与 Fake-IP 配置指南](/guides/dns-setup/) 与 [DNS 泄漏与污染修复](/troubleshooting/articles/dns-leak-hijack-fix)。

### 4. 账号历史归属与客户端/浏览器本地缓存
目标平台绝不只看当前这一次请求的 IP。浏览器本地留存的 Cookie、LocalStorage、`cf_clearance` 风控令牌、账号创建时绑定的手机区号或 Google 付款资料国家，以及手机客户端里的语言、时区和 GPS 权限，都会参与最终决策。这也是为什么很多用户「明明换了可用美国节点，刷新网页却还是报同样错误」的根本原因——因为浏览器里留着上一次用香港 IP 访问时种下的拒绝凭证。

## 三、AI 工具专题适配解析：ChatGPT、Claude 与 Gemini 深度对照

为了避免把不同 AI 平台混为一谈，下面结合站内 `data/brands.json` 与 `docs/public/images/evidence/` 实测样本，逐一拆解三大主力 AI 平台的适配逻辑与风险边界。

### 1. ChatGPT（OpenAI）：网页端 vs App 端差异与 `仅APP(HK)` 现象
OpenAI 长期对未覆盖地区（包含中国大陆与香港）实施严格接入管控，但在工程实践中，机场对 ChatGPT 的适配呈现出三种截然不同的状态（详见 [ChatGPT 机场适配专题](/ai-media/chatgpt/)）：
- **全端支持区出口（`解锁(US)` / `解锁(JP)` / `解锁(SG)` / `解锁(TW)`）**：无论是直接落在美国、日本、新加坡、台湾的支持区节点，还是服务端做了 AI 落地转发的香港中转节点，只要在检测中显示带支持区国家码的绿标解锁，网页端 `chatgpt.com`、桌面端与手机 App 均能正常调用。
- **服务端部分覆盖导致同机场分化**：以站内保留的光速云 `2026-08-19` 归档目录 `guangsuyun-miaoko-streaming-ai.jpg`（珠海联通 9Gbps 单线程，70/70 节点）为例，`HK香港01`–`HK香港18` 的 `AI_openai` 列大多显示经后端分流后的 **`解锁(US)`** 或 **`解锁(JP)`**，但同属该机场的 `HK香港19`、`HK香港20` 以及 `电信-HK香港01`、`电信-HK香港02` 却全部显示为 **`N/A`**。这证明即便是同一家机场，主力常规编号节点与备用/特殊前缀节点的后端解锁策略也可能并不一致。
- **网页受限但移动端短暂通过的 `仅APP(HK)` 现象**：在光速云 `2026-08-19` 归档目录的三网普通测速截图（广西移动、长沙电信、河北联通各 62 节点 Shadowsocks）中，香港专线节点的 OpenAI 一栏普遍标注为 **`仅APP(HK)`**。这种现象的本质是 OpenAI 移动 App 部分 API 通道与网页端（叠加 Cloudflare 地域与设备风控）的校验严苛度不同步，香港未分流原生出口在移动端侥幸放行但网页端已拦截。**重要原则：不要把 `仅APP(HK)` 当作可靠生产环境**，一旦 App 版本升级或接口风控对齐网页端，随时会大面积中断。

### 2. Claude（Anthropic）：高敏机房风控与频繁切区杀手
相比 OpenAI，Anthropic Claude 的风控重心不仅在于「地区是否支持」，更在于 **「IP 滥用密度」** 与 **「会话及账号周期的地理连贯性」**（详见 [Claude 节点风控与防封指南](/ai-media/claude/)）：
- **机房 IP 共享封控极严**：当几十甚至上百名用户共用低价或高度同质化的廉价机房 IP 注册或高频请求 Claude 时，该 ASN 网段往往会被 Anthropic 风控系统重点标记。轻则注册收不到验证码或网页端 403，重则新号登录不久即遭遇 `Account disabled` 停用。
- **自动测速切节点（`url-test`）是大忌**：许多用户在 Clash Verge Rev 或 Shadowrocket 中习惯开启「自动选择最低延迟节点」，导致客户端每几分钟就因为波动把流量从日本切到新加坡、再跳到美国。对需要强账号认证的 Claude 而言，短时间跨国 IP 漂移会被视作账号共享或盗用风险，极大提升封号率。
- **证据边界提示**：在站内现有的 `2026-08-11` 16 家测速截图及所有留存的 Miaoko 流媒体测试图中，**均未包含独立的 `Anthropic/Claude` 探测列**。因此，无论是光速云、微风、星岛梦、唯兔云、一翻云还是速界资料中标注的“支持 Claude”，目前全部属于 **`vendor`（品牌资料声明）**；而二猫云、SOGO 云、隐形人等在档案中也仅对 Claude 标为“视节点而定”或无明确承诺。实际使用时，务必先用不绑定主力信用卡的备用邮箱测试节点稳定度，并在分流配置中将 `claude.ai` 与 `anthropic.com` **手动固定锁定到单个低复用美/日/新节点**。

### 3. Gemini（Google AI）：为什么多品牌档案普遍标注「视节点而定」
查阅 `data/brands.json` 会发现一个极其显著的规律：在所有明确披露了 AI 兼容明细的机场品牌中（涵盖光速云、飞猫云、微风网络、星岛梦、二猫云、无忧链接、唯兔云、Firefly、暮光加速、U1S1、灵猫网络、一翻云、SOGO 云、闪跃、全球云、隐形人），**绝大多数品牌均将 Gemini 归类为「视节点而定」**（详见 [Gemini 区域可用性与失败排查](/ai-media/gemini/)）。

更直观的实证出现在光速云 `2026-08-19` 归档目录的 Miaoko 三网实测中：即便在 OpenAI 显示分流解锁的节点批里，香港、日本、美国与台湾节点在 Gemini 一栏仍出现大面积失败。造成这种现象的客观技术原因有三点：
1. **Google 自有 GeoIP 与 YouTube 送中联动**：Google 拥有全球最庞大的终端位置数据回传网络。一旦某个新加坡或台湾节点被手机端上报位置污染并标为 `CN`（即 YouTube 送中），同属于 Google 体系的 `gemini.google.com` 几乎会同步拒绝该节点。
2. **香港节点默认拦截与分流覆盖不足**：香港同样不在 Google Gemini 常规开放区。如果机场后端的域名分流清单只转发了 OpenAI 却未囊括 `gemini.google.com`、`aistudio.google.com` 与 `generativelanguage.googleapis.com`，香港节点自然直接失败。
3. **Google 账号区服与环境校验叠加**：即便切到了美国或日本节点，若使用的 Google 账号本身付款资料长期绑定在不受支持区域、浏览器残留历史地域 Cookie，或者网页认证域名未同步走代理，同样会弹出区域不可用提示。

### 4. AI 工具对账户与 IP 一致性的四项核心要求
综合上述三大平台风控特征，稳定使用海外 AI 服务必须遵守四条账户卫生规范：
- **单平台固定单区出口**：在客户端分流规则中单独建立 `AI-Proxy` 策略组，采用 `select`（手动选择）而非 `url-test`（自动测速），长期固定使用 1–2 个美/日/新稳定节点。
- **全链路域名一致性**：确保主站、静态资源域名、API 接口以及 Google/Microsoft 第三方 OAuth 登录回调域名全部经过同一个代理策略组，防止「登录走美区、回调走直连」。
- **切节点必用无痕窗口验证**：从香港或失效节点切换至美国/日本可用节点后，务必新开浏览器无痕模式或清理目标站点 Cookie 与缓存再重新登录，避免被旧风控令牌拦截。
- **绝不把生产主力 AI 账号放进极低价公共池**：超低价（如一元或未实测极简集群）节点的出口 IP 复用率极高，极易引发风控连坐。

## 四、流媒体兼容深度解析：Netflix、YouTube 送中、Disney+、HBO Max 与 TikTok

与 AI 服务侧重区域白名单与账号风控不同，海外流媒体的核心技术矛盾集中在 **「版权区域识别」**、**「CDN 调度」** 与 **「位置漂移（送中）」** 三个层面。

### 1. Netflix 解锁三级状态与「节点地名 ≠ 落地识别区」偏差
在评估 Netflix 兼容性时，仅能打开登录页面没有任何意义，工程上必须区分为三个等级（详见 [Netflix 解锁解析](/ai-media/netflix/)）：
- **全区全解锁（Full Unlock）**：能够搜索并播放非自制剧（如第三方授权电影、热门日漫与本土剧集），测试面板显示绿色 **`解锁(XX)`**（括号内为真实识别的国家代码）。
- **仅解锁自制剧（Originals Only）**：Netflix 识别到出口 IP 为常见商业机房代理，屏蔽所有第三方授权片单，仅开放 Netflix 自家原创剧集。
- **完全拦截（Failed / 错误代码 E106 或 M7111-5059）**：直接提示检测到代理或解锁工具，无法起播视频。

特别需要注意 **「落地识别偏差（节点名与版权归属国不一致）」** 这一真实工程现象：很多机场为了用较低成本让大量普通中转节点都能看全库 Netflix，会在后端将流媒体域名统一 DNS 劫持到少数几台具备解锁能力的专用落地服务器上，由此在实测中留下明显偏差：
- **实测案例一（灵动云 `2026-07-20/21` 历史实测摘要）**：在 60 解锁测试记录中，明确标注 **「台湾落地识别偏欧（NF/D+ 识别 ES）」**——即用户连接的是台湾节点，但 Netflix 与 Disney+ 将你的版权地区识别为 **西班牙（ES）**。
- **实测案例二（光速云 `2026-08-19` 目录 `guangsuyun-miaoko-streaming-ai.jpg`）**：图中 `TW台湾01` 至 `TW台湾10` 节点的 `AI_openai` 识别为 `解锁(TW)`，但同一批台湾节点的 `INTL_netflix`、`INTL_disney_plus` 与 `INTL_dazn` 全部显示 **`解锁(GB)`**（即英国版权区）。同时，部分 `电信-HK香港01/02` 节点显示 `N/A`，未接入解锁分流池。

这种跨区解锁对普通看美剧用户影响不大，但如果你明确要看 **「台湾区限定中文字幕剧集或本土番剧」**，只凭节点名字选「台湾 01」反而可能扑空。

### 2. YouTube 体验、CDN 调度与 `送中(CN)` 成因及双品牌实证
YouTube 依托分布全球的 Google Global Cache（GGC）边缘缓存节点，在物理带宽充足时，1080p 乃至 4K 60fps 并不苛刻；真正频繁干扰日常体验的，是 **`YouTube 送中(CN)`** 以及 IPv6 路由绕远引发的 CDN 降速（详见 [YouTube 加速与送中排查](/ai-media/youtube/)）：
- **`送中(CN)` 的真实成因**：并非服务商把服务器迁回了中国大陆，而是大量安卓/iOS 用户在手机挂着代理时，仍开启了 Google Maps、YouTube App 或系统后台的 GPS/Wi-Fi 定位授权，导致同一个共享海外出口 IP 长期不断向 Google 上报中国大陆物理位置坐标；此外，部分低成本跨区广播（Anycast）IP 段本身在 Google 地理库中残留了历史权重异常。一旦 Google 将该 IP 纠正标记为 `CN`，用户就会遭遇无贴片广告、离线缓存与后台播放权限消失、YouTube Music 及部分会员家庭组异常等问题。
- **实证一（光速云 70 节点 Miaoko 实测）**：在 `guangsuyun-miaoko-streaming-ai.jpg` 中，**`SG新加坡01`–`10` 全部十个节点、`TW台湾01`–`06` 与 `08`–`10`，以及 `电信-台湾01/02`、`电信-新加坡01`、`电信-日本01`**，在 `INTL_youtube` 列均明确显示橙色 **`送中(CN)`**；而同批 **`JP日本01`–`10` 全部正常显示 `解锁(JP)`**，**`HK香港01`–`18` 全部正常显示 `解锁(HK)`**。
- **实证二（无忧链接 `2026-07-18 21:47:23 CST` 晚高峰实测 `wuyou-2.jpg`）**：在 50 节点御三家流媒体逐节点检测中，49 个节点正常解锁对应地区，但 **`香港HKG-01` 的 `INTL_youtube` 列明确显示 `送中(CN)`**（同时同批次 `wuyou-1.jpg` 测速图记录到新加坡 `SIN-02` 均速跌至 `17.59KB/s`）。
- **实证三（灵动云 `2026-07-20/21` 实测摘要）**：历史测试摘要同样明确记录了 **「新/台 YT 送中」**。

**遭遇 YouTube 送中或缓冲卡顿时的排查步骤**：首先在节点列表中切往同机场的日本节点（通常送中率低于新/台广播段）或未被标记的香港节点验证；其次在客户端中暂时关闭未妥善配置出口路由的 IPv6；最后可在 YouTube 播放器右键打开 **「详细统计信息（Stats for nerds）」** 查看实时连接速率与所调度的数据中心代码，若手机端持续异常，关闭 Google 相关 App 的精确位置权限并在无痕/新会话中重试。

| 流媒体/内容平台 | 风控与解锁核心难点 | 站内实测样本中观察到的典型现象 |
| :--- | :--- | :--- |
| **Disney+** | 对 IP 地域归属与非家用段检测较为严格，对跨区 DNS 解锁依赖强 | 光速云 `2026-08-19` 目录三网截图记录「台湾多节点 Disney+ 失败」；珠海联通 70 节点图中 `TW台湾01–10` 则识别为 **`解锁(GB)`**，`电信-` 前缀多节点显示 `请求失败` 或 `N/A` |

## 五、原生/住宅 IP vs 商宽/机房 IP：结合 `IPType` 与 `IPRisk` 字段科学解读

在机场宣传文案里，**「全原生 IP」「独享原生住宅 IP」「家宽落地」** 是最容易让人产生误解的词汇。在专业网络可观测性检测（如 Miaoko 进阶检测模板及各类 IP 质量脚本）中，评判一个出口 IP 的“含金量”不能听商家口头形容，而要看两个核心工程指标：

1. **`IPType`（IP 归属实体与路由类型）**：
   - **`ISP` / `Residential`（住宅/家庭宽带段）**：IP 广播与注册归属当地民用电信运营商，风控系统默认其背后是真实家庭用户。这类 IP 成本高、带宽通常远不如机房，多见于高价定制线路或独立住宅落地。
   - **`Business`（商业宽带段）**：企业办公宽带 IP，信誉度普遍优于普通机房但略低于纯住宅段。
   - **`Hosting` / `DataCenter`（数据中心/机房段）**：绝大部分常规机场节点均运行在云厂商或独立服务器机房内。只要该机房段没有被大量黑产、爬虫或注册机滥用，依然可以配合流媒体解锁策略正常使用，并不等于完全废掉。
2. **`IPRisk`（IP 历史滥用与风控分值）**：
   代表该 IP 近期在反欺诈库、代理黑名单、Cloudflare 拦截记录中的污点程度（常见划分为 Low / Medium / High / Very High 或百分比风险值）。**一个 `IPRisk` 处于极低风险的干净商业机房 IP，往往比一个被万人共享到烂的廉价所谓“原生广播段”更好用。**
3. **「原生 IP」与「DNS 解锁」的本质区别**：
   真正的 **「原生 IP（Native IP）」** 是指 IP 注册地（Whois）与服务器物理广播地一致，且被当地主流流媒体平台承认为本土用户；而 **「DNS 解锁 / 落地分流」** 则是服务器自身 IP 可能被屏蔽，但机场通过规则把流媒体请求转发到了另一台能解锁的机器上（这正是台湾节点却能看英国区 Netflix 的原因）。站内一翻云、微风网络、闪跃等品牌资料中均出现了「原生 IP / 原生住宅 IP」宣传字样，但在缺少独立 IP 质量检测截图前，本站一律严格标为 **`vendor`（品牌资料宣称）**。

## 六、五大热门地区节点横向对比：按需求选对国家/地区

选机场不是「只看香港延迟最低」就万事大吉。不同地区节点在物理延迟、AI 白名单支持率、流媒体片库与送中概率上存在天然分工，可参考下表快速决策（线路深度原理见 [香港节点分析](/routes/hong-kong/) 与 [日本节点落地](/routes/japan/)）：

| 节点地区 | 物理直连/专线延迟特征 | AI 平台（ChatGPT / Claude / Gemini）适配特点 | 流媒体（Netflix / YouTube / 本土内容）特点 | 典型风险与注意事项 |
| :--- | :--- | :--- | :--- | :--- |
| **香港（HK）** | 离华南最近，专线 RTT 最低（常见 `20–30ms`），日常网页秒开主力 | **默认不在 OpenAI / Anthropic / Google AI 白名单内**；除非机场在后端做分流转发（如光速云部分 HK 节点转成 `US`/`JP`），否则易出现网页拦截或 `仅APP(HK)` | 常规香港节点 YouTube 正常解锁（`解锁(HK)`），但仍有个别节点送中案例（如无忧链接 `HKG-01`）；TikTok 在港区多失败或受限 | 切勿只靠低延迟香港节点裸连跑 Claude 或 Gemini，必须配合客户端 AI 独立分流规则 |
| **台湾（TW）** | 延迟较低（常见 `37–45ms`），适合繁体中文与港澳台周边业务 | 部分支持区覆盖 OpenAI/Gemini，但受限于节点广播质量与送中联动 | 若为真本土解锁，可看台区独占繁中版权剧与动画；但跨区 DNS 解锁极易出现版权偏移（如识别为 `GB` 或 `ES`） | **YouTube 送中(CN) 高发区之一**（光速云、灵动云实测均观察到 TW 多节点送中） |
| **新加坡（SG）** | 华南出发延迟适中（常见 `42–48ms`），东南亚枢纽 | 属于 OpenAI、Claude 与 Gemini 的常规支持地区，常作为香港分流后的常用替补区 | 英语与东南亚片库丰富；部分节点在 TikTok 测试中呈现 `解锁(ALISG)` 等分流状态 | **同样属于 YouTube 送中(CN) 高发区**，选节点前需确认 YT 与 Gemini 未被 Google 误标为 CN |
| **日本（JP）** | 延迟适中（常见 `50–65ms`），亚太带宽大、IIJ/软银/NTT 线路多 | **亚太区 AI 综合可用率相对稳健的支持区**（尤其配合稳定单节点固定出口时） | 日区 Netflix（含海量日漫新番）、Abema（部分需本土解锁）、YouTube 在光速云 70 节点图中 **`JP01–10` 全部正常解锁(JP)** | 需注意部分软银/廉价机房晚高峰国际出口拥塞，以及个别节点可能出现 `0B`/`KB` 级异常或偏高 HTTPS 延迟 |
| **美国（US）** | 跨太平洋物理延迟较高（常见 `130–185ms`），不适合低延迟游戏 | **三大 AI 平台覆盖最全、新功能与模型灰度最先开放的核心地区** | 美区 Netflix 版权库最全，HBO Max 与各类北美学术/开发资源支持最完整 | 高密度共享美西机房极易成为 Claude 风控重灾区；远距离单线程吞吐可能大幅低于香港，且偶发单节点极端低速（如光速云 `美国02` 仅 `1.60KB/s`） |

## 七、DNS 解析与地区识别的关系：为什么 DNS 错位会毁掉解锁

许多排障小白经常疑惑：「我明明已经选了美国节点，为什么打开网站还是说我在香港或中国大陆？」这往往是 **「DNS 解析归属地」与「TCP 出口归属地」分裂** 造成的：

1. **本地 DNS 劫持或浏览器异步 DoH 绕过**：如果你在 Chrome/Edge 浏览器里开启了「使用安全 DNS」并指向了国内公共 DoH，或者客户端未正确接管 53 端口 DNS 请求，域名就会在本地直接解析出国内或污染 IP。轻则把 YouTube 调度到异常 CDN 节点导致卡顿，重则暴露真实地理特征引发平台风控。
2. **Redir-Host 模式下的域名与 IP 失配**：部分客户端在 Redir-Host 模式下，若 `nameserver` 与 `fallback` 分组配置错误，先用国内 DNS 查出了某个海外 CDN 的最近亚太节点 IP，然后再把这个 IP 交给美国代理节点去连接——目标服务器看到一个来自美国出口 IP 的连接请求，却在访问本地分配给香港/新加坡的入口，轻则绕远掉速，重则触发区域校验错误。
3. **服务端 DNS 流媒体解锁的工作原理**：反过来，机场服务商之所以能让一个普通的商业机房节点看全区 Netflix 或用上 ChatGPT，恰恰是在机场落地服务器的 `dnsmasq` / `sing-box` / `xray` 路由层，把特定流媒体或 AI 域名的 DNS 解析结果强行指向了具有解锁能力的反向代理或隧道出口。这就要求用户本地客户端必须开启 **「远端 DNS 解析（Fake-IP 或由节点侧解析域名）」**，不要在本地强制写死把 `openai.com` 或 `netflix.com` 解析成固定静态 IP。相关配置方法见 [分流规则配置](/guides/split-routing/) 与 [Fake-IP 198.18 冲突排查](/troubleshooting/articles/fake-ip-explained-fix)。

## 八、RegionRestrictionCheck 与 Miaoko 测试方法与报告阅读规范

无论是查看他人评测还是自己验证节点质量，目前社区最主流的检测工具分为两类，适用场景与阅读规范完全不同（完整图解见 [AI/流媒体兼容性测试解读](/ai-media/compatibility/)）：

### 1. RegionRestrictionCheck（单出口即时脚本检测）
`RegionRestrictionCheck` 是一套开源 Bash 检测脚本，特点是直接在当前网络出口环境下向数十个流媒体与 AI 接口发起即时探测，适合以下两类场景：
- 拥有自建落地 VPS 的用户，在服务器上直接运行查看原生 IP 的真实解锁能力；
- 本地终端已经连上某个特定机场节点后，在配置好代理终端环境（如 `HTTP_PROXY` / `ALL_PROXY` 或 TUN 全局接管）下只针对「当前这一条节点」核实其实时状态。

### 2. Miaoko 批量测试面板（多节点矩阵快照）
Miaoko（含喵速插件）则是目前机场评测中最常见的 **「全订阅批量并发探测面板」**，一次性对订阅内几十个节点同时拉起速度测试与流媒体/AI 检测，生成矩阵长图。阅读 Miaoko 报告时必须紧盯以下五个关键工程字段，切忌只看一片绿色就下结论：
1. **顶部测试环境与时间**：核对测速后端（如广西移动@2Gbps、长沙电信@2Gbps、河北联通@2Gbps 或珠海联通 9Gbps 单线程）、线程数以及底部是否印有具体测试年月日时间戳。
2. **协议列（`类型`）**：看清实际跑出来的节点协议是 `Shadowsocks`、`Vless` 还是 `AnyTLS`，并与商家文案对比是否存在偏差。
3. **`TLS RTT` vs `HTTPS 延迟`**：`TLS RTT` 仅代表单次 TLS 数据交换耗时（通常 `200–430ms`），而 **`HTTPS 延迟` 代表包含完整建连与网页请求的体验延迟**（部分节点在看似不算慢的情况下，HTTPS 延迟可能高达 `800–3000ms` 以上，这解释了为什么测速带宽很大但网页首屏打开却感觉发粘）。详见 [TLS RTT 与 Ping 延迟真相](/routes/low-latency/)。
4. **括号地区码与颜色标签**：
   - **`解锁(XX)`**（绿色）：可正常访问，且平台识别落地为括号内国家/地区（如 `解锁(US)`、`解锁(GB)`、`解锁(JP)`）；
   - **`本土解锁(XX)`** / **`解锁(ALISG)`**：针对 Abema、TikTok 等特定平台的细分识别状态；
   - **`送中(CN)`**（橙色）：仅常见于 YouTube 等 Google 定位，表示该节点出口被谷歌标回中国大陆；
   - **`仅APP(HK)`**（黄色/受限）：表明网页端已被拦截，仅客户端特定接口暂通；
   - **`失败` / `请求失败`**（红色）：探测请求被明确拦截或超时失败；
   - **`N/A`**（灰色）：**未测出、脚本跳过或未返回有效状态——绝对不能当成「解锁」或「可能支持」！**

> [!WARNING]
> **流量消耗警示**：运行 Miaoko 等批量测速与解锁探测会短时间下载大量测速文件，**正在使用「不限时一次性流量包」或小流量套餐的用户，绝对不要频繁执行全节点 32 线程跑分**，以免一次测试直接刷掉几十 GB 宝贵额度。详见 [不限时流量包使用边界](/pricing/non-expiring/)。

## 十一、AI 与流媒体无法访问的五步分层排查入口

当你选用了标注可用地区的节点，却仍然打不开 ChatGPT、Claude、Gemini 或看不了 Netflix 非自制剧时，请按以下从低风险到高精度的顺序逐层排查，切忌一上来就重装系统或关闭杀软：

1. **第一层：排除「节点地区选错」**
   确认当前在客户端策略组里选中的不是香港节点（或直连规则），手动切换至日本、美国或新加坡节点；若看 YouTube 遇到无广告或会员权限异常，优先换往日本节点排查是否为新/台节点送中。
2. **第二层：无痕窗口清理本地风控记忆**
   新建浏览器无痕/隐私窗口访问目标网站。若无痕窗口瞬间恢复正常，说明原普通窗口残留了先前受限 IP 种下的 Cookie 或 LocalStorage，清除目标站点网站数据即可。
3. **第三层：检查分流规则漏域与自动切点**
   核对客户端是否启用了 `url-test` 导致 AI 对话中途切国家出口，以及规则库是否遗漏了认证/API/静态资源域名（如 `oaistatic.com`、`anthropic.com`、`aistudio.google.com`、`generativelanguage.googleapis.com`）。操作指引见 [分流规则配置指南](/guides/split-routing/)。
4. **第四层：排查 DNS 泄漏与 IPv6 干扰**
   检查系统与浏览器是否开启了绕过代理的 DoH 安全 DNS，或尝试在客户端关闭 IPv6 出站测试（避免因机场落地未配好 IPv6 路由而触发地域判定异常或 YouTube CDN 绕远）。详见 [特定站点不可达排查](/troubleshooting/articles/specific-sites-unreachable) 与 [DNS 泄漏与污染修复](/troubleshooting/articles/dns-leak-hijack-fix)。
5. **第五层：对照账号区服与节点池限制**
   若同一机场内多个美/日节点在无痕窗口和正确规则下均提示同样的风控报错（或出现 `N/A` / `仅自制剧`），说明该批次节点出口 IP 本身已被目标平台限制或未配置流媒体分流。此时不要死磕刷新，应联系机场客服确认具体支持 AI/流媒体的分组节点编号，或在月付到期后更换具备透明实测记录的备选方案。

## 十二、常见问题（FAQ）

### 为什么代理已经连上且测速很快，ChatGPT、Claude 或 Gemini 却依然报错？
测速快只能证明从你本地设备到代理落地出口之间的链路带宽充足、延迟低，而 AI 平台是否放行取决于四大独立变量：出口 IP 所属国家是否在平台白名单内（香港默认不在 OpenAI、Anthropic 与 Google AI 常规支持区）、出口 IP 的 ASN 类型与历史滥用信誉（IPType 与 IPRisk）、本地 DNS 与分流规则是否漏域，以及浏览器残留的旧风控 Cookie。

### 某机场的节点实测支持 ChatGPT，能直接推导出它也一定支持 Claude 和 Gemini 吗？
绝对不能。OpenAI、Anthropic 与 Google 三家采用完全独立的服务区域白名单、ASN 风控黑名单和 GeoIP 地理位置修正库。即便在同一家机场的同一批实测中（例如光速云 2026-08-19 归档目录 Miaoko 截图），很多节点在 OpenAI 栏显示分流解锁(US)或(JP)，但同一批节点在 Gemini 栏却大量显示失败；而 Claude 在现有公开实测图中甚至没有单独的探测列，因此严禁横向推导。

### Miaoko 测试图里香港节点 OpenAI 显示「仅APP(HK)」是什么意思？能当主力使用吗？
「仅APP(HK)」指节点本身仍位于香港原生或未做网页分流出口，移动客户端部分 API 通道暂未拦截，但网页端（chatgpt.com）与桌面全功能处于地域封锁或高概率受限状态。在光速云 2026-08-19 归档目录的三网 Miaoko 测速图（62 节点 Shadowsocks）中，香港专线节点便普遍呈现仅APP(HK)。这种状态随时可能因平台收紧移动端校验而失效，不应作为主力生产力依赖。

### 为什么 31 家机场品牌资料中，绝大多数都把 Gemini 标注为「视节点而定」？
因为 Google 对自有 GeoIP 地理位置数据库更新极其频繁，且与 YouTube 定位信号高度联动。一旦某个新加坡或台湾共享节点的出口 IP 被大量带定位权限的移动设备上报中国大陆坐标而发生「送中」，或者香港节点未将 gemini.google.com、aistudio.google.com 单独分流到支持区落地，Gemini 就会立即提示所在地区不受支持，因此任何机场都很难保障全部节点长期稳定可用。

### 使用 Claude 时为什么很容易遇到 403 拦截或账号封禁？
Anthropic 对商业数据中心（IDC）机房 IP 段、并发自动化特征以及账号登录期间的 IP 国家高频漂移极其敏感。如果使用大量用户共用的低价机房 IP，或在 Clash 等客户端中开启 url-test 自动测速导致对话期间出口在美、日、新之间频繁跳动，极易触发安全风控并引发账号停用。

### 什么是 Netflix 的「仅自制剧」和「落地识别偏差（如台湾节点识别成 ES 或 GB）」？
当 Netflix 识别出出口 IP 属于普通商业机房代理时，会屏蔽第三方版权影片，只允许播放 Netflix 原创自制剧（Originals）。而为了提供全区版权库，许多机场会在后台通过 DNS 劫持或分流把流媒体流量统一送到少数专用落地机上，导致「节点名称所在国」与「实际识别版权国」不一致——例如灵动云 2026-07-20/21 实测记录中台湾落地被 NF/D+ 识别为西班牙（ES），光速云 2026-08-19 目录 Miaoko 图中 TW 台湾 01–10 的 Netflix 与 Disney+ 则显示解锁英国（GB）。

### 什么是 YouTube「送中(CN)」，为什么新加坡和台湾节点在实测中反而经常出现？
「YouTube 送中(CN)」指海外节点的出口 IP 被 Google 地理定位系统纠正为中国大陆（CN），症状包括看视频无广告、离线缓存/后台播放受限、家庭组或部分音乐/版权内容异常。成因通常是大量安卓/iOS 手机在连着代理时开启了 Google 应用位置授权，把国内 GPS 与 Wi-Fi 定位信息持续关联到该节点 IP 上。在光速云 70 节点 Miaoko 实测中 SG01–10 与 TW 多节点均出现送中(CN)，而无忧链接 2026-07-18 实测中也记录了香港 HKG-01 送中(CN)。

### 测速报告里的 IPType 与 IPRisk 字段怎么看？「原生住宅 IP」真的存在吗？
在 IP 质量检测与高阶测试面板中，IPType 用于区分出口 IP 归属的 ASN 类型（如 ISP 家庭宽带、Business 商业宽带、Hosting 数据中心机房），IPRisk 则反映该 IP 在欺诈库与滥用库中的风险评分。普通机房（Hosting）只要 IPRisk 够低且配合分流也能看流媒体，但面对 Claude 或 TikTok 等极严风控时，低风险 ISP/原生段更有优势；不过市面上少数商家宣称的「全节点原生住宅 IP」若无独立测试佐证，一律只能视为品牌宣传（vendor）。

### 2026-08-11 批次的 16 张机场测速截图和 2026-10-19 表格，能用来判断哪家解锁 AI 或 Netflix 吗？
完全不能。2026-08-11 批次的 16 张 MAI-TEST-BOT / MiaoSu PNG 截图只记录了节点延迟、下载速率与 UDP/NAT 类型，没有包含任何 AI 或流媒体解锁探测列；而 2026-10-19 附带的五地文本表格更是缺少工具与方法论披露。判断解锁兼容必须查看包含对应测试列的 Miaoko 报告，或先购买短周期月付套餐在本地实测。

### Miaoko 测试图里显示的「N/A」能算作基本支持或待解锁吗？
不能。测试表中的「N/A」通常代表该项探测脚本未执行、被前置条件跳过或通信超时未形成有效判定结果，它与明确标绿的「解锁(XX)」以及标红的「失败/请求失败」不同，绝对不能把 N/A 推定为可用。

### 切换到了标注解锁的美国或日本节点，为什么浏览器打开 ChatGPT 或 Gemini 仍然报错？
这通常是本地环境残留了「被拒绝的历史状态」或分流配置漏域。建议先打开浏览器的无痕/隐私窗口清除目标站点 Cookie 与 LocalStorage 重试；若无痕模式仍报错，检查 Clash/sing-box 分流规则是否漏掉了认证与静态资源域名（如 oaistatic.com、anthropic.com、aistudio.google.com），以及客户端是否泄漏了本地直连 DNS。

### 如果自己有可疑节点，应该如何用 RegionRestrictionCheck 或 Miaoko 自行验证？
如果你想检测当前本地客户端所连接的单条落地出口，可以在目标 VPS 或具备本地代理环境支持下运行开源的 RegionRestrictionCheck 脚本查看各大流媒体与 AI 返回码；如果是批量评测机场订阅里的几十个节点，则常借助 Miaoko 等支持多线程批量探测各平台与记录 TLS RTT、HTTPS 延迟的工具，同时务必先避开不限时流量包以免跑分消耗大量流量。
