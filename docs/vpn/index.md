faq:
  - q: 传统海外商业 VPN、代理订阅机场和游戏加速器，底层原理有什么不同？
    a: 传统商业 VPN 多基于 WireGuard、OpenVPN 或 IKEv2 在操作系统网卡层建立全局加密隧道；代理机场基于 VLESS、Trojan、Shadowsocks 或 Hysteria 2 等传输/应用层协议，核心优势是按域名与 IP 精细分流；游戏加速器则专注白名单游戏进程的 UDP 转发优化、丢包补偿与 NAT 穿透改善。
  - q: 用游戏加速器能访问普通海外网页或 ChatGPT 吗？
    a: 不能。正规合规游戏加速器仅对白名单游戏进程与指定游戏服务器 IP 段进行路由调度，不会代理浏览器常规网页流量或 AI 服务；反之，未开放完整 UDP 转发或 NAT 呈 Symmetric 状态的普通代理机场，在联机游戏里也容易触发语音断续与匹配失败。
  - q: 所谓“永久免费不限流量 VPN”靠什么盈利，存在哪些安全隐患？
    a: 带宽、机房与 IP 运维均存在刚性成本，缺乏付费订阅收入的免费 VPN 通常依赖五类变现模式：将用户设备转化为住宅出口代理节点、采集并出售 DNS 与访问画像、注入网页广告与劫持流量、采用弱加密或明文采集凭证，以及借免费限速诱饵转化高价年付。此类工具还高发 DNS 泄漏、IPv6 旁路泄漏与 WebRTC 真实 IP 暴露。
  - q: 为什么手机 VPN 锁屏几分钟后经常自动断连或收不到消息？
    a: Android 与 iOS 均在系统层施加了严格限制：Android 国产定制 ROM 会在锁屏后冻结后台进程并回收 VpnService 隧道，需关闭电池优化并开启后台自启与任务加锁；iOS 的 NetworkExtension 扩展则受约 50MB 内存硬上限约束，一旦加载过大的规则集或高频并发连接就会触发 OOM 强制终止。
  - q: 为什么不能在 Android 或 Windows 上同时开启两款 VPN 或游戏加速器？
    a: 操作系统在网络层对虚拟隧道存在排他性或路由竞争：Android 的 VpnService 同一时刻仅允许单个应用持有活跃槽位，启动第二个会直接顶掉前者；Windows 与 macOS 同时运行两套虚拟网卡（TUN 驱动、WireGuard 网卡或加速器驱动）则会引发默认路由表打架、DNS 环路与全局断网。
  - q: Android 端的分应用代理（Split Tunneling）和规则分流有什么区别？
    a: 分应用代理基于 Android VpnService 的应用 UID 黑白名单，直接决定某个 App 的全部流量是否进入隧道，最适合将国内网银、微信或本地政务 App 彻底排除在隧道之外；规则分流则在代理内核内部按域名与 GeoIP 判断流量去向，两者结合可兼顾兼容性与访问速度。
  - q: iOS 端获取手机 VPN 或代理客户端为什么会遇到区服与付费限制？
    a: iOS 端几乎所有合规工具均需通过 App Store 分发，而不同国家或地区商店的上架清单与定价差异极大（例如 Shadowrocket、Stash、Quantumult X、Surge 均为海外区服付费或内购应用）。用户必须使用本人可控账号在对应支持区服获取，切勿使用来路不明的共享 Apple ID 登录系统 iCloud，以免遭遇远程锁机与隐私泄露。
  - q: Windows VPN 内置客户端、商业 VPN 软件和代理客户端的 TUN 模式该怎么选？
    a: 企业内网接入若已下发标准 IKEv2 或 WireGuard 配置文件，可直接使用系统内置或官方开源客户端；海外商业 VPN 适合固定合规网络环境与整体加密需求；而需要国内外精细分流、同时兼容终端命令行与 UWP 应用时，使用 Clash Verge Rev 或 sing-box 开启 TUN 模式往往更灵活。
  - q: 联机游戏测速里的 FullCone、RestrictedCone 和 Symmetric NAT 代表什么？
    a: 这三种类型反映路由器或代理出口对外部 UDP 主动回包的放行严格度。FullCone（NAT1）放行最宽松，P2P 联机匹配池最广且组队语音最稳；RestrictedCone（NAT2/3）允许已通信主机的回包；Symmetric（NAT4）会为每个目标分配独立映射端口，极易导致联机匹配超时、无法加入好友房间或语音掉线。
  - q: 商业 VPN 宣传的“严格无日志（No-Logs）”声明该如何核验真伪？
    a: 口头宣称无日志不具备证明力，可信评估应核查四项客观依据：是否发布过独立第三方安全机构审计报告、服务器是否采用 RAM-Only 内存无盘架构、企业注册地司法管辖与透明披露报告是否公开，以及客户端是否开源可供社区审查。无公开审计背书的宣传一律按商家自称看待。
  - q: 在跨境复杂网络环境下，WireGuard、OpenVPN 为什么经常不如 VLESS 或 Trojan 稳定？
    a: WireGuard 与 OpenVPN 的设计初衷是通用加密组网而非对抗复杂链路干扰，其握手包结构与固定端口特征十分清晰，在跨境链路拥塞或严格 QoS 限速环境下容易出现握手超时或速率断崖下降；而 VLESS、Trojan 等协议多配合国内 BGP 中转或 TLS 伪装传输，在复杂跨境路由中连通率更具优势。
  - q: 商业 VPN、代理机场和游戏加速器，个人用户到底应该如何组合选购？
    a: 核心原则是按刚需拆解而非一刀切：访问企业内网或要求合规安全审计时使用单位指定的商业或自建 VPN；日常跨境学术、开源开发与多设备国内外精细分流优先选择规则代理方案；专注 PC 或主机外服联机降丢包则单独购买支持按时暂停的合规游戏加速器，并牢记切换前彻底退出上一款虚拟网卡工具。

# VPN 与加速器完整技术指南：商业 VPN、代理机场与游戏加速器深度对比

在日常交流中，人们习惯将所有涉及跨境加密或网络优化的工具统称为 **「VPN」** 或 **「加速器」**。但在计算机网络工程层面，**传统商业 VPN、基于规则分流的代理订阅服务（俗称机场）与合规游戏加速器**分别工作在截然不同的协议栈层级、路由接管模型与业务边界上。把三类工具混为一谈，不仅会导致选型花冤枉钱——例如买了游戏加速器却发现打不开学术网页，或者买了不支持 UDP 转发的普通代理却用来打竞技网游——更是引发双虚拟网卡冲突、国内应用全面卡顿与 DNS 泄漏的头号技术根源。

> [!WARNING] 合法网络运维与合规边界声明
> 虚拟专用网络（VPN）、应用层安全代理与网络路由加速属于标准互联网基础设施技术，广泛应用于**企业合规远程办公、跨国研发与开源协作、跨境学术文献检索、多区域 SaaS 灰度测试、公共 Wi-Fi 防窃听以及合规联机游戏减损**。本专题仅围绕网络协议原理、操作系统机制、隐私风控与连接排障展开客观技术解析，所有工具均须在所在司法辖区法律法规及工作单位、高校信息安全规范框架内合规使用，绝不鼓励任何未经授权的访问、侵权下载或绕过企业安全审计边界的行为。

## 一、VPN 与加速器的基本区别：别再被口语称呼误导

理解三类工具的本质差异，只需要抓住两个底层工程问题：**第一，它在操作系统的哪一层接管流量？第二，它默认把哪些流量送进隧道？**

- **传统商业 VPN（Virtual Private Network）**：工作在 **OSI 网络层（L3，IP 隧道）或数据链路层（L2）**。客户端会在操作系统中注册一块虚拟网卡（如 Windows 的 Wintun/TAP 网卡、macOS/iOS 的 `utun` 接口、Android 的 `tun0` 接口），修改系统默认路由表，将**整台设备的全部 IP 数据包**（包含浏览器、桌面软件、系统更新乃至局域网外的所有流量）加密打包送往远端 VPN 网关。它的设计目标是让远端设备“仿佛置身于目标局域网或海外出口机房之中”，强调**全链路加密一致性与合规隐私保护**。
- **规则代理订阅服务（机场 + 开源客户端）**：传统上工作在 **传输层与应用层（L4/L7，SOCKS5 / HTTP 代理端口）**，现代客户端（如 [Clash Verge Rev](/clients/clash-verge/)、[sing-box](/clients/sing-box/)、[Shadowrocket](/clients/shadowrocket/)）则可通过 [TUN 模式](/guides/tun-mode/) 向下兼容 L3 接管。它的核心基因不是“全局加密回源”，而是 **基于精细规则的智能分流（Split Routing）**：在本地维护一份包含数万条域名与 IP CIDR 的规则库（GeoSite / GeoIP），让国内银行、微信、视频网站和政务系统全部走本地宽带直连，仅将特定跨境目标域名通过多节点策略组转发。
- **合规游戏加速器**：工作在 **驱动层进程劫持（LSP / WFP / 虚拟网卡白名单路由）** 与 **专用 UDP 转发网络** 之间。它的目标既不是隐藏用户的浏览隐私，也不是代理常规网页，而是针对具体游戏客户端的进程名与已知游戏服务器集群 IP 段，构建低抖动、抗丢包、支持 NAT 类型优化的专用转发通道，同时让同一台电脑上的浏览器与聊天软件保持完全直连。

## 二、传统商业 VPN vs 代理订阅机场 vs 游戏加速器全景技术对比

下表从 9 个核心工程维度，直观呈现三类网络工具在架构、性能、兼容性与排障复杂度上的本质区别：

| 核心对比维度 | 传统海外商业 VPN（企业 / 隐私 VPN） | 代理订阅服务（机场 + Clash / Xray / sing-box） | 合规商业游戏加速器 |
|---|---|---|---|
| **典型底层协议栈** | WireGuard、OpenVPN（UDP/TCP）、IKEv2/IPsec | VLESS（XTLS/Reality）、Trojan、Shadowsocks、Hysteria 2 | 私有 UDP 加速隧道、双发冗余纠错（FEC）、定制游戏路由协议 |
| **系统流量接管方式** | 虚拟网卡全局接管（部分支持按应用 Split Tunnel） | 系统代理端口（HTTP/SOCKS5）或可选 TUN 虚拟网卡 | 白名单游戏进程 Hook、驱动过滤或游戏主机旁路路由接管 |
| **默认分流颗粒度** | 粗颗粒度：默认全部流量出国，国内访问易绕路变慢 | **极细颗粒度**：支持按域名后缀、关键词、GeoIP、进程名与 DNS 规则多级分流 | **严格业务白名单**：仅接管已收录游戏进程与指定区服端口，绝不代理常规网页 |
| **跨境复杂网络连通性** | 标准 OpenVPN/WireGuard 协议指纹明显，跨境直连易遇 QoS 限速或握手失败 | 普遍结合国内多线 BGP 中转、IEPL/IPLC 专线或 TLS 伪装，复杂环境下连通率更高 | 依托合规备案机房与游戏服务器就近专线接入，专注降低特定区服丢包与抖动 |
| **UDP 转发与联机 NAT 表现** | WireGuard 原生完整支持 UDP，但跨国公网直连路由抖动较大 | 高度依赖机场服务端配置与节点类型，需核验是否开放 UDP 且 NAT 为 `FullCone` | **专项优化强项**：主打 FullCone NAT 改善、跨区组队语音保活与防跳 Ping |
| **客户端透明度与可控度** | 多为闭源商业客户端（少数提供原生 WireGuard/OpenVPN 配置文件导出） | 开源通用客户端（Mihomo / Xray / sing-box）透明度极高；纯专属客户端机场则透明度低 | 完全闭源商业软件，节点与路由策略由厂商黑盒自动调度 |
| **跨平台与路由器适配** | 覆盖 Windows / macOS / Android / iOS / Linux 及主流企业路由器 | 开源生态极其丰富，全面覆盖桌面、移动端、Linux 终端及 OpenWrt 软路由 | 侧重 Windows PC、主流手游（Android/iOS）与主机加速盒/路由器插件，macOS 与 Linux 支持弱 |
| **典型计费与续费模式** | 按月高价（$10–$15/月）诱导 1–2 年大额预付与自动扣费 | 按月/年付流量包或一次性不限时流量包（¥15–¥25/月主流），支持多档灵活试错 | 按月包期（¥20–¥40/月）或 **按小时计费且支持随时暂停**，适合非每日游戏玩家 |
| **高频排障故障类型** | 全局接管拖慢国内应用、Kill Switch 死锁断网、跨境直连长期转圈 | 订阅拉取失败、YAML/JSON 格式报错、Fake-IP 冲突、TUN 与系统代理端口打架 | 本地杀软拦截驱动、路由器双重 NAT 致匹配失败、与 VPN/代理虚拟网卡冲突断网 |

## 三、常见合法使用场景与工具匹配矩阵

选型出错的根本原因，往往是“先看广告排行榜，再反推自己需不需要”。按照实际业务诉求反推工具形态，才能避免架构错配：

1. **企业远程办公与内网资源访问**：跨国企业员工、外派工程师访问公司内网 ERP、代码仓库、堡垒机或受 IP 白名单保护的云控制台时，应**严格使用企业 IT 部门统一部署的合规 VPN**（如 WireGuard、IPsec/IKEv2 或零信任客户端）。此类场景对身份认证（MFA）、审计留痕和内网网段路由有刚性要求，严禁将公司机密凭证暴露于来路不明的第三方共享代理节点。
2. **跨境学术文献检索与开源研发调试**：高校科研人员、独立开发者日常拉取 GitHub 仓库、Docker 镜像、npm/PyPI 依赖、阅读 IEEE/arXiv 论文或调用合规海外 API 接口时，核心痛点是 **「终端命令行（CLI）默认不走系统代理」** 以及 **「国内镜像源需要保持直连满速」**。此时，基于规则分流并开启 [TUN 模式](/guides/tun-mode/) 的开源代理架构（如 [Clash Verge Rev](/clients/clash-verge/) 或 [v2rayN](/clients/v2rayn/)）远比全局接管的传统商业 VPN 高效。
3. **跨国电商运营与多地区 SaaS 灰度测试**：出海产品经理与 QA 测试工程师需要验证不同国家/地区的落地页展示、支付网关回调或定价策略时，需要**稳定且可预测的出口地域 IP**。如果仅做网页级测试，带有清晰地域分组与原生落地测试记录的代理方案即可满足；如果涉及高风控广告账户或店铺登录，则应考虑合规独立静态住宅/企业专线或云主机固定出口，避免与成百上千用户共用脏 IP 池触发账号风控。
4. **外服 PC / 主机 / 手游联机加速**：游玩跨区服务器的多人竞技、合作射击或 MMORPG 游戏时，核心指标不是单线程下载几百兆带宽，而是 **持续 60 分钟内的丢包率（<0.5%）、延迟抖动（Jitter <5ms）与 NAT 穿透等级**。此类场景毫无疑问首选**合规商业游戏加速器**，且无需为高带宽流量包买单。
5. **差旅公共 Wi-Fi 传输层加密防窃听**：在机场、酒店、咖啡厅等开放无线热点中处理敏感业务邮件或财务操作时，若担心局域网 ARP 欺骗或明文嗅探，选择经独立安全审计的合规商业 VPN 或自建 WireGuard 回源至可信网关，能够对整机所有应用层外发流量（含部分未强制 HTTPS 的老旧协议）实施统一加密封装。

## 四、免费 VPN 的商业变现模式与安全 / DNS 泄漏风险拆解

搜索引擎里搜索 **「免费 VPN」** 时，充斥着大量标榜“永久免费、不限流量、一键极速”的应用与浏览器扩展。从基础网络经济学出发，**国际带宽采购、服务器租赁、IP 地址维护与客户端跨平台研发全部是持续消耗真金白银的刚性成本**。一家没有透明付费商业闭环的“免费 VPN”，必然通过隐蔽方式从用户身上回收成本。完整风控证据可进一步查阅[免费 VPN 风险剖析](/vpn/free/)。

### 4.1 免费 VPN 的 5 种真实商业变现路径

1. **把用户宽带劫持为商业住宅代理节点（P2P 带宽共享）**：这是近年来最具隐蔽性的变现模式。部分免费 VPN 客户端在安装协议的极小字号条款中夹带授权，一旦你保持软件后台运行，它就会将你的家庭宽带或手机移动网络作为 **「住宅出口 IP」** 转卖给外部爬虫、数据抓取甚至灰产团伙。表面上你免费用了它的出口，实际上陌生第三方正顶着你的实名宽带 IP 在互联网上发起未知请求，带来极高的法律与安全连带风险。
2. **采集与出售 DNS 查询及访问行为画像**：即便是加密的 HTTPS 网页，只要免费 VPN 接管了你的默认 DNS 解析器与出口网关，运营方就能完整记录你在什么时间访问了哪些域名（通过明文 DNS 请求与 TLS 握手中的 SNI 字段）、停留了多久、使用了哪类金融或购物应用。这些高价值行为数据会被打包出售给第三方数据经纪商或精准广告网络。
3. **广告注入、应用内弹窗与电商返利劫持**：大量免费手机 VPN 在连接前后强制播放高耗电全屏视频广告，部分恶意免费浏览器扩展甚至会在用户访问常规网页时静默注入追踪脚本、篡改搜索结果或劫持电商购物链接以窃取返利佣金。
4. **弱加密协议、明文凭证风险与恶意 SDK 捆绑**：为了压低服务器 CPU 加密开销，部分粗制滥造的免费工具停留在早已被淘汰的弱加密或无校验隧道配置上；更有甚者直接在非官方应用商店分发的安装包中植入恶意 SDK，过度索取通讯录、短信、剪贴板与无障碍权限。
5. **“免费诱饵”高价转化模式（Freemium 的合理与越界边界）**：需要客观区分的是，极少数具备清晰付费主体与公开审计报告的海外知名商业 VPN（如采用透明付费养免费模式的产品）会提供限节点、限速或限流量的免费体验档，本质属于获客营销成本。这类有限度的免费试用档与来路不明的“全免费不限速破解版”存在本质区别，但依然不应用于承载高敏感个人或企业数据。

### 4.2 三类高发隐私泄漏机制与自检方法

即使你正在使用付费 VPN 或代理工具，如果客户端底层配置不当，依然可能出现 **「表面已连接，真实位置已裸奔」** 的泄漏故障：

- **DNS 泄漏（DNS Leak）**：业务数据包走了加密隧道，但操作系统却把域名解析请求悄悄发给了本地运营商宽带的默认 DNS 服务器（例如 Windows 多网卡智能多宿主名称解析 SMHNR 机制触发并发查询）。结果是你的本地运营商依然能看到你解析的每一个海外域名，同时还可能因为拿到被污染的解析 IP 导致打不开目标站。排障方法请对照[DNS 泄漏与劫持修复指南](/troubleshooting/articles/dns-leak-hijack-fix)与[DNS 安全配置教程](/guides/dns-setup/)。
- **IPv6 旁路泄漏（IPv6 Bypass Leak）**：如今国内家庭宽带与 5G 移动网络已大面积普及 IPv6 双栈。如果一款老旧 VPN 或代理客户端只接管了 IPv4 默认路由，却没有同步屏蔽或接管 IPv6 流量，那么所有支持 IPv6 的海外站点就会绕开加密隧道直接通过你的本地真实 IPv6 地址建立连接，瞬间暴露真实网络归属。
- **WebRTC 真实 IP 暴露**：浏览器中的实时音视频通信接口 WebRTC 在执行 ICE/STUN 候选地址收集时，可能绕过应用层 HTTP/SOCKS5 代理直接探测本地网卡地址并上报给网页脚本。使用系统代理模式访问敏感站点时，需在浏览器设置中限制 WebRTC 仅使用代理路由或启用完整的系统级 TUN 隧道。

## 五、手机 VPN 选型方法与移动端核心约束

与插电且网络环境固定的桌面电脑不同，智能手机是 **高移动性、强电源管控、高频网络切换** 的受限终端。照搬电脑端标准去挑 **「手机 VPN」**，往往会陷入“刚连上很快，塞进兜里走两条街就彻底失联”的窘境。选型移动端工具时，必须优先考察以下 5 项硬指标（深入分析见[手机 VPN 后台机制](/vpn/mobile/)）：

1. **Wi-Fi 与 4G/5G 蜂窝网络切换的平滑度（Roam 容错）**：当你走出家门从 Wi-Fi 切入 5G 基站时，设备出口 IP 瞬间变更。支持无状态连接迁移或快速重连的协议（如 WireGuard、IKEv2 MOBIKE、Hysteria 2 或优化心跳检测的 VLESS/Trojan 客户端）能在 1–2 秒内无感恢复；而依赖僵化 TCP 长连接的劣质工具则会假死卡住 30–60 秒，必须手动开关飞行模式或重连。
2. **分应用代理与国内外规则分流能力**：手机上高频运行着微信、支付宝、高德地图、外卖与银行类 App。如果手机 VPN 只能全局接管而不支持精细分流或应用排除，轻则导致扫码支付转圈、定位漂移、推送延迟，重则触发银行风控弹窗冻结账户。
3. **电池能耗与后台内存占用控制**：持续加密计算与高频保活心跳会直接拉高移动 SoC 功耗。优先选用轻量化现代协议（如基于 ChaCha20-Poly1305 的移动友好型加密算法，在无 AES-NI 硬件加速的中低端手机上比传统 AES 更省电），并精简动辄十万行的冗余分流规则集。
4. **锁屏后台存活机制适配**：必须确认所选工具在当前手机系统版本下是否支持持久前台通知保活（Android）或按需连接 On-Demand（iOS），否则锁屏几分钟后即被系统休眠机制强杀。
5. **安装包来源可核验性**：手机端承载着支付密码、短信验证码与生物识别入口，**安全红线高于一切**。切勿从陌生贴吧网盘、第三方聚合站或所谓“绿色破解版”下载安装手机 VPN。

## 六、Android vs iOS 系统级隧道架构差异深潜

同样是移动端，**安卓 VPN** 与 **iOS VPN** 在底层操作系统 API、资源限额与分发政策上几乎是两个世界。理解这两套系统级边界，能直接解决 80% 以上的移动端掉线与选型困惑。

### 6.1 Android 端：`VpnService` 单槽位机制、国产 ROM 保活与安全预警

Android 操作系统通过标准 API `android.net.VpnService` 向用户态应用开放虚拟网络隧道能力，完整实操可参见[安卓 VPN 与 VpnService 指南](/vpn/android/)：

- **单槽位排他抢占原则**：Android 系统内核规定，**同一时刻只能有一个应用持有活跃的 `VpnService` 隧道接口**。一旦你打开第二款 VPN、规则代理或手游加速器并点击连接，系统会强制撤销第一款应用的 `VpnService` 授权并触发 `onRevoke()` 回调使其立即断开。这也是为什么无法在安卓手机上同时运行代理软件与某类基于本地 VPN 接口的广告拦截器或抓包工具。
- **防环路 `protect()` 与分应用代理（Per-App Proxy）**：正规安卓客户端必须把发往远端服务器的底层 Socket 显式调用 `VpnService.protect()` 移出虚拟隧道，防止流量陷入无限死循环；同时利用 `addDisallowedApplication()` 或 `addAllowedApplication()` 实现精准的**应用级白名单/黑名单分流**——把国产网银、微信、政务与本地打车 App 直接放进绕过列表，彻底消除分流规则漏判引发的兼容性故障。
- **国产定制 ROM 的后台查杀与保活三件套**：小米（HyperOS）、华为（HarmonyOS）、OPPO（ColorOS）、vivo（OriginOS）等深度定制系统为了延长续航，会在锁屏数分钟后冻结非白名单后台进程或切断后台网络。使用 [FlClash](/clients/mihomo/)、[Clash Meta for Android](/clients/clash-meta/) 或 [v2rayNG](/clients/clash-meta/) 等安卓客户端时，必须完成“电池优化设为无限制 + 允许后台自启/关联启动 + 多任务视图锁定卡片”三步配置，常见断连排障可查[安卓断连与保活排障](/troubleshooting/articles/android-v2rayng-clash-disconnect)。
- **安卓端重要分发安全警示**：根据本站 `data/clients.json` 审计留存记录，**NekoBox for Android** 官方项目已明确提示维护资源有限，且特别发出安全警告：**切勿使用其名称下已被第三方控制的 Google Play 商店版本**，务必仅从经过核验的官方开源发布渠道验证签名后再安装。

### 6.2 iOS / iPadOS 端：`NetworkExtension` 内存红线与 App Store 区服限制

与安卓的相对开放相反，Apple 在 iOS 端对网络隧道施加了极为严苛的沙盒与分发管控：

- **`NEPacketTunnelProvider` 约 50MB 内存硬上限**：iOS 代理与 VPN 应用的核心网络转发逻辑并非运行在主 App 进程中，而是运行在独立的系统扩展进程 `NetworkExtension`（Packet Tunnel Provider）内。iOS 系统对该扩展进程实施 **约 50MB 的严格内存上限（历史版本甚至低至 15MB）**。一旦用户导入了过于庞大的 GeoSite/GeoIP 数据库、开启过多并发连接或加载复杂 JS 重写脚本，扩展进程瞬间触及上限即被系统直接 OOM 强杀，表现为“主界面没关但顶部 VPN 图标突然消失，所有网页断网”。解决之道是精简规则集、避免在 iOS 上启用极重型全量 IP 库，并开启 `On-Demand` 按需自动拉起。
- **App Store 区服上架与付费软件生态**：iOS 不允许普通用户自由侧载未签名安装包，所有主流工具均依赖 App Store 分发。正如本站客户端数据库所载，iOS 端生态以**海外区服付费或内购应用**为主力——包括 [Shadowrocket（小火箭）](/clients/shadowrocket/)、[Stash](/clients/shadowrocket/)（兼容 Clash YAML 与覆写）、[Quantumult X（圈 X）](/clients/shadowrocket/)（支持脚本与请求重写）、[Surge 5](/clients/shadowrocket/)（专业级流量分析与抓包调试）以及跨平台 [Karing](/clients/sing-box/)、[Hiddify](/clients/sing-box/)、[Clash Mi](/clients/mihomo/)、[Streisand](/clients/shadowrocket/) 等。具体上架状态与售价以用户所属 App Store 地区为准。
- **严禁使用共享 Apple ID 登录系统 iCloud**：为了下载海外区服工具而借用或购买网络上廉价“共享 Apple ID”是 iOS 用户最惨痛的安全雷区。一旦在「设置 → iCloud」中登录陌生账号，对方即可通过“查找我的 iPhone”远程抹除数据并激活锁机勒索。如需切换商店地区下载合规应用，务必仅使用本人完全可控的账号，且仅在 App Store 媒体与购买项目内操作，绝对不要触碰系统级 iCloud 登录。

| 对比维度 | Android (`VpnService`) | iOS / iPadOS (`NetworkExtension`) |
|---|---|---|
| **后台内存上限** | 宽松（取决于整机 RAM 与 ROM 调度） | **严苛**（扩展进程约 50MB 硬顶，大规则集易 OOM 闪退） |
| **系统级分应用代理** | 原生支持按应用 UID 黑白名单绕过 | 消费级 App Store 应用不支持标准按应用排除，强依赖域名与 IP 规则分流 |
| **锁屏保活核心难点** | 国产 ROM 省电冻结与后台自启限制 | 扩展进程内存溢出与低电量模式休眠 |
| **客户端分发与成本** | GitHub 开源 APK 免费生态丰富（需严防仿冒与被接管的 Play 版本） | 强依赖 App Store 对应区服，主力成熟工具多为一次性付费或内购 |

## 七、Windows 与 macOS 桌面端选择及“单虚拟网卡铁律”

桌面端承载着开发编译、大文件传输、多标签浏览与专业音视频生产，对 **「Windows VPN」** 与 **「macOS 网络代理」** 的要求不仅在于“能连通”，更在于**不破坏本地局域网打印、不干扰企业内网软件、不与虚拟机/Docker 路由冲突**。

### 7.1 Windows 桌面端三种接入机制对比

1. **系统内置 VPN（IKEv2 / L2TP / SSTP）与商业软件客户端**：适合标准企业网关与海外商业 VPN 场景。优点是全局生效、无需逐个软件配代理；缺点是缺乏精细的国内外域名分流，开启后访问国内企业微信、钉钉或网盘速度容易骤降，且部分自带“断网保护（Kill Switch）”的商业 VPN 在异常崩溃后可能锁死 Windows 防火墙出站规则导致重启后依然无网。
2. **开源代理客户端的系统代理模式（WinINET HTTP/SOCKS5）**：例如 [v2rayN](/clients/v2rayn/) 或 [Clash Verge Rev](/clients/clash-verge/) 默认通过修改 Windows 注册表中的系统代理地址（如 `127.0.0.1:7897`）接管浏览器流量。优点是轻量、不安装虚拟网卡驱动、极少引发系统级路由故障；缺点是**终端命令行（Git/PowerShell/Python）、Steam/游戏客户端、UWP 微软商店应用以及大量独立桌面程序不会遵循系统代理设置**，具体差异见[TUN 模式与系统代理深度对比](/troubleshooting/articles/tun-vs-system-proxy)。
3. **开源代理客户端的 TUN 虚拟网卡模式（Wintun / Service Mode）**：通过安装 Wintun 驱动并配合管理员权限系统服务接管全部 TCP/UDP 流量，同时保留 Mihomo / sing-box 的精细分流规则。它完美解决了 CLI 命令行与桌面应用不走代理的痛点，但需注意 Windows Defender 或第三方安全软件可能误报拦截核心文件（如 `mihomo.exe`、`xray.exe`），引发[Clash Verge 启动失败](/troubleshooting/articles/clash-verge-startup-fail)或[TUN 模式不生效](/troubleshooting/articles/tun-not-working)。此外，在 Windows 上切勿盲目选择维护状态存疑的历史工具（本站 `clients.json` 明确提示 **Mihomo Party** 需单独关注项目维护状态，不宜未经核实列为持续更新首选）。

### 7.2 macOS 桌面端特有的工程注意点

- **芯片架构严格区分**：macOS 客户端（如 Clash Verge Rev、FlClash、Hiddify）在下载安装包时必须严格区分 **Apple Silicon（ARM64 / M1–M4 芯片）** 与 **Intel（x86_64）** 版本，混装转译版容易造成代理核心高占用或系统扩展加载失败。
- **System Extension 授权与 `utun` 路由**：现代 macOS 开启 TUN 模式或安装商业 VPN 时，需要在「系统设置 → 隐私与安全性」中手动批准网络扩展授权。若在 macOS 上同时使用 Parallels / OrbStack / Docker Desktop 等虚拟化工具，开启 TUN 后务必检查虚拟网段是否被误纳入代理路由或 Fake-IP 冲突池。

### 7.3 桌面与移动通用的黄金排障铁律：严禁同时运行两套虚拟网卡

无论是海外商业 VPN、代理客户端的 [TUN 模式](/guides/tun-mode/)、企业 ZeroTrust 客户端还是合规游戏加速器，它们都会向操作系统写入高优先级默认路由与专属 DNS 解析器。**在同一台设备上同时开启任意两款此类工具，会立刻引发路由表互相覆盖、DNS 查询环路或网卡抢占断连**。每次从远程办公切换至日常分流或联机游戏前，请先确认前一款工具已**彻底退出后台托盘进程并释放虚拟网卡**，再启动下一款工具。

## 八、游戏加速器原理与 UDP FullCone / RestrictedCone / Symmetric NAT 诊断

为什么很多用户买了一条下载能跑满 500Mbps 的高端专线代理，打外服联机游戏时却依然频繁丢包、无法加入好友大厅、或者语音麦断断续续？答案藏在 **UDP 传输特性与 NAT（网络地址转换）行为类型** 中，详细诊断步骤可延伸阅读[游戏加速器与 UDP NAT 诊断](/vpn/gaming/)与[UDP 与 NAT 防火墙阻断排障](/troubleshooting/articles/udp-nat-firewall-blocks)。

### 8.1 联机游戏为何对“抖动、丢包与 UDP”极度敏感

网页浏览和 4K 视频播放基于 TCP 或带大缓冲区的流传输——就算中间丢了 2% 的数据包，浏览器重传几百毫秒或者播放器吃掉 5 秒本地缓存，人眼几乎毫无察觉。但实时竞技与动作联机游戏每秒钟都在高频双向收发极小的状态同步帧（通常走 **UDP 协议**，不做 TCP 队头阻塞重传）。只要跨境链路上出现 1%–3% 的随机丢包或 30ms 以上的瞬时延迟抖动，玩家屏幕上就会立刻表现为人物瞬移、技能吞指令、判定延迟甚至直接掉线退房。

合规商业游戏加速器解决该问题的工程手段包含三层：第一，**白名单进程与区服精准识别**，剥离其他后台下载对游戏小包的抢占；第二，**多路径冗余发包（双发/多倍发包与前向纠错 FEC）**，宁可多耗一点微不足道的带宽，也要确保关键状态帧首包直达不丢；第三，**专门优化出口节点的 NAT 映射策略**，扫清 P2P 联机与主机语音壁垒。

### 8.2 看懂测速图里的四种 NAT 类型（STUN 行为模型）

在代理测速截图（如 Miaoko 测速图）或主机网络检测（PlayStation NAT Type 1/2/3、Switch NAT A/B/C/D/F）中，经常出现 `FullCone`、`RestrictedCone`、`PortRestrictedCone`、`Symmetric` 与 `Unknown` 等标识，它们直接决定联机体验上限：

| NAT 行为类型 | 主机等效大致对应 | 外部入站 UDP 回包放行规则 | 对外服联机游戏与语音开黑的真实影响 |
|---|---|---|---|
| **FullCone NAT（完全圆锥型）** | NAT Type A / 宽松（Open） | 只要内网端口建立过对外映射，**任何外部 IP 与端口**发往该映射公网端口的 UDP 包均无条件放行 | **联机最理想状态**：P2P 匹配池覆盖面最大，可顺利担任房主，与任何类型玩家互联及游戏内语音均最稳定 |
| **RestrictedCone NAT（地址限制圆锥型）** | NAT Type B / 中等（Moderate） | 仅放行内网主机**曾经主动发包通信过的外部 IP** 发回的 UDP 包（不限制对方源端口） | **常规服务器模式表现良好**：主流官方专用服务器游戏基本无碍，但遇到严格 NAT 玩家做 P2P 房主时偶发连不上 |
| **PortRestrictedCone NAT（端口限制圆锥型）** | NAT Type B–C / 中等偏严 | 必须严格匹配内网曾经通信过的**外部 IP 且外部源端口完全一致**才放行 | 绝大多数家用宽带光猫+路由器默认状态；官方服可玩，但跨区 P2P 联机与部分语音服务易出现单边听不见 |
| **Symmetric NAT（对称型）** | NAT Type D / 严格（Strict） | 内网访问**每一个不同的外部目标 IP/端口**时，都会被分配一个全新的随机公网映射端口，STUN 打洞极难成功 | **联机重灾区**：高频触发“无法加入好友小队”、匹配耗时极长、主机语音报错或刚进局即踢出 |
| **`Unknown`（未知/UDP 阻断）** | NAT Type F / 失败 | 节点未开启 UDP 转发、被中间防火墙丢弃 UDP 或 STUN 探测超时 | **完全不适合联机游戏**：只能走 TCP 网页流量，强行用于 UDP 联机游戏会直接断连或提示无法连接服务器 |

需要特别提醒：即使你的代理节点本身在测速图上标着 `FullCone`（例如微风网络、宇宙云部分香港节点），如果你本地家庭网络处于 **「运营商大内网 CGNAT + 光猫路由模式 + 二级无线路由器」** 的多层 NAT 嵌套下，或者本地客户端未开启 `udp: true` 转发，实际联机时依然可能被拖回严格 NAT。遇到该现象应先排查本地是否开启 UPnP 或改光猫为桥接模式，再核验隧道端 UDP 支持。

## 九、隐私安全、日志边界与可审计性评估

谈论 VPN 或代理工具的“安全性”时，最容易陷入两个极端：要么盲信广告语“军工级加密绝对匿名”，要么认为所有第三方工具都必然窃密。客观的工程评估应当严格区分 **「链路传输加密」** 与 **「端到端匿名性」**，并在四个可核验维度上划清日志边界（完整框架见[隐私与日志安全边界](/security/privacy/)）：

1. **传输加密只防中间窃听，不等于对服务商隐身**：无论是商业 VPN 还是代理机场，加密隧道保护的是“你本地设备到代理/VPN 出口服务器”这一段链路不被本地 Wi-Fi 运营商或中间节点窥探。然而，**出口服务器本身天然知晓你的入口源 IP、连接时间、流量大小以及目标服务器域名/IP**（尽管 HTTPS 网页正文内容受端到端 TLS 保护，代理服务器看不到你输入的密码和正文，但依然能看到你访问了哪个域名）。因此，你对工具的信任本质上是对运营方治理水平与合规底线的信任。
2. **如何辨别“无日志（No-Logs）”声明的含金量**：商业 VPN 行业几乎家家宣称“零日志”，但只有同时满足以下客观条件的声明才具备较高可信度——**经过独立第三方安全审计机构（如四大会计师事务所或知名渗透审计机构）多轮公开审计并出具完整报告；服务器全面采用无硬盘内存运行模式（RAM-Only），断电即销毁运行态数据；定期发布透明报告披露司法协查响应原则；且未发生过隐瞒数据泄露的负面历史**。对于缺乏任何独立审计背书的普通代理服务商，所有口头“不记录日志”均只能视作 `vendor` 宣称，切忌通过共享节点传输明文未加密的企业机密或敏感金融凭证。
3. **开源通用客户端 vs 闭源专属客户端的审计鸿沟**：使用 [Clash Verge Rev](/clients/clash-verge/)、[v2rayN](/clients/v2rayn/)、[FlClash](/clients/mihomo/)、[sing-box](/clients/sing-box/) 等主流开源客户端时，核心源码与构建产物接受全球开发者社区监督，是否夹带异常数据回传或过度权限索取相对透明；而部分强制要求安装闭源专属客户端的工具，其内部集成了哪些第三方 SDK、是否在后台静默上传设备指纹，普通用户几乎无法核验。这也是本站始终强调优先保留通用订阅兼容性的安全底层原因。
4. **独立账号隔离与支付隐私习惯**：无论使用商业 VPN 还是代理服务，都应遵守最小暴露原则——使用独立邮箱与密码管理器生成的专属高强度密码注册（绝不复用主力银行、工作邮箱或社交账号密码），避免在不可信终端保持长期自动登录，详细清单参见[账号安全防护指南](/security/account-security/)。

## 十一、核心协议栈与跨平台兼容性深度比较

为什么同样是“连上加密服务器”，换一种底层协议就会让延迟、耗电和晚高峰流畅度判若两人？理解主流 VPN 协议与代理协议的底层工程取舍，有助于你在[VPN 与代理协议架构对比](/vpn/comparisons/)与日常排障中迅速定位瓶颈：

| 协议名称 | 所属阵营与传输层 | 加密开销与握手延迟 | 跨境复杂链路与弱网表现 | 跨平台客户端兼容性 |
|---|---|---|---|---|
| **WireGuard** | 现代商业/自建 VPN（纯 UDP） | **极低开销、极快握手**：代码极简（约 4000 行内核态实现），采用 ChaCha20-Poly1305，移动端极省电且切网瞬时恢复 | 静态握手包与 UDP 特征高度清晰；在无干扰直连或内网穿透中性能称王，但在跨境严控或 UDP QoS 限速环境下易遭遇断流 | Windows / macOS / Linux / Android / iOS / OpenWrt 全面原生支持 |
| **OpenVPN** | 传统商业/企业 VPN（UDP 或 TCP） | 中高开销：运行在用户态，数据需在内核态与用户态间多次拷贝，高带宽吞吐明显劣于 WireGuard；TCP 模式易引发“TCP over TCP”熔断雪崩 | 灵活性强，支持 443 端口 TCP 穿透严格企业防火墙，但在复杂跨境检测下原生 TLS 特征易被识别限速 | 历史最悠久，几乎所有企业防火墙与操作系统均内置或原生兼容 |
| **IKEv2 / IPsec** | 商业与企业移动 VPN（UDP 500/4500） | 低开销、支持 **MOBIKE** 无缝网络漫游（Wi-Fi 切 5G 不掉线） | 原生深度集成在 iOS、macOS 与 Windows 系统中无需装第三方客户端，但同样易受固定 UDP 端口策略阻断 | 系统内置兼容度最高，适合企业合规出差与轻量直连 |
| **VLESS（+ TLS / XTLS / Reality）** | 现代代理订阅协议（TCP / UDP over TCP/gRPC/WS） | 极轻协议头（无冗余二次加密），配合 XTLS-Vision 或 Reality 消除嵌套 TLS 指纹特征，延迟低、吞吐极高 | 在复杂跨境环境下适应能力最强的现代主流协议之一，配合国内中转或专线表现尤为稳健 | 需较新内核支持（Xray-core、Mihomo、sing-box、Shadowrocket、Karing、Hiddify）；老旧客户端（如停更的旧版 Clash、Potatso）不兼容 |
| **Trojan** | 经典代理订阅协议（TCP + 标准 TLS） | 依赖标准 HTTPS/TLS 加密层，握手与正常网页访问高度相似，资源开销适中 | 抗探测能力成熟稳健，适合配合专线与多线中转稳定运行 | 跨平台兼容面极广，几乎全部现代桌面、移动与软路由客户端均原生支持 |
| **Shadowsocks（AEAD / SS-2022）** | 轻量化代理协议（TCP + UDP） | 协议极简、加密计算开销低，搭配专线或 BGP 入口时吞吐表现非常出色 | 纯公网直连环境下旧版抗识别能力较弱，因此现代机场通常将其部署在 **IEPL/IPLC 专线或国内加密隧道中转** 后端（正如本站 08-11 实测包大量节点所示） | 兼容性最广，全平台几乎零门槛支持 |
| **Hysteria 2** | 新一代 QUIC 代理协议（基于 UDP / QUIC） | 握手极快，内置针对高丢包弱网设计的 **Brutal 激进拥塞控制算法** | 在高丢包跨境公网直连环境下可强行拉起吞吐，但若本地运营商对大流量 UDP 实施限速（UDP QoS），速率会出现明显波动或掉线 | 需现代内核支持（Mihomo、sing-box、v2rayN、Shadowrocket、Hiddify、Streisand），老旧客户端不支持 |

## 十三、VPN 与加速器常见连接故障与排障入口

无论你使用的是商业 VPN、规则代理还是游戏加速器，90% 以上的“连不上、网速慢、能连上但打不开网页”问题，最终都能归因到 **本地驱动冲突、DNS 污染/泄漏、系统时间偏差、分流规则误判或上游节点波动** 这五类工程根因。遇到异常时切忌盲目卸载重装或反复重买套餐，请直接按下方症状对照进入对应排障手册：

1. **同时开着 VPN、TUN 模式或加速器后全机彻底断网**：立刻检查任务管理器与网络适配器列表，彻底退出其中一款工具并重置系统代理；若关闭后依然无法上网，查阅[连接成功但无网络排障](/troubleshooting/articles/connected-no-internet)与[TUN 模式无法工作修复](/troubleshooting/articles/tun-not-working)。
2. **国内微信、银行 App、淘宝极慢或提示网络异常**：典型由商业 VPN 全局接管或代理分流规则失效（含 Fake-IP 冲突）导致。Android 用户可将国内 App 加入 `VpnService` 绕过名单；桌面端用户请检查[规则分流配置指南](/guides/split-routing/)与[Fake-IP 冲突原理与修复](/troubleshooting/articles/fake-ip-explained-fix)。
3. **显示已连接但特定海外站点打不开或频繁跳验证码**：优先排查本地是否存在 DNS 泄漏、运营商劫持或系统时钟偏差超过 90 秒导致 TLS/VLESS 握手被拒。对应查阅[DNS 异常与污染诊断](/troubleshooting/dns-error/)、[特定网站无法访问排查](/troubleshooting/articles/specific-sites-unreachable)及[系统时间同步与 TLS 证书报错修复](/troubleshooting/articles/time-sync-tls-cert-error)。
4. **所有节点全部超时或订阅链接拉取失败**：先排查订阅链接是否返回 `HTTP 401/403/404/503`、本地 DNS 是否无法解析订阅域，或套餐流量是否耗尽/已到期。直达[订阅拉取失败排障](/troubleshooting/subscription-failure/)、[HTTP 状态码排查](/troubleshooting/articles/sub-http-401-403-404-503)与[全节点超时诊断](/troubleshooting/articles/nodes-all-timeout)。
5. **手机端锁屏几分钟自动断开，亮屏后必须重连**：Android 检查电池无限制、自启白名单与任务加锁；iOS 检查是否因规则过大触发 `NetworkExtension` 50MB 内存上限崩溃。详见[安卓断连专项排障](/troubleshooting/articles/android-v2rayng-clash-disconnect)。
6. **晚高峰卡顿丢包或游戏联机 NAT 始终呈 Strict / Symmetric**：区分本地宽带波动、路由器双重 NAT 与服务端晚高峰拥塞，对照[晚高峰高延迟与丢包排障](/troubleshooting/articles/high-latency-packet-loss-peak)与[UDP 及 NAT 防火墙阻断修复](/troubleshooting/articles/udp-nat-firewall-blocks)。

如需系统化按故障树逐层定位，请访问本站核心工具入口[代理故障诊断总控台](/troubleshooting/)。

## 十四、商业 VPN 与代理订阅机场的深度取舍框架

在众多咨询中，最高频的纠结是 **「我到底该买海外知名商业 VPN，还是该买支持规则分流的代理订阅机场？」** 两者并不存在绝对的上下级替代关系，而是各自在特定边界内不可替代：

- **选择合规商业 VPN 的 4 个充分理由**：第一，你处于**海外本地或无复杂干扰的直连网络环境**，核心诉求是在咖啡厅公共 Wi-Fi 防窃听、跨区访问合规流媒体库或保护本地宽带隐私；第二，你的单位或客户要求**可出具独立第三方安全审计报告与正规商业发票**的合规服务商；第三，你极度排斥学习任何订阅格式与分流规则，希望跨设备一键全局加密；第四，你的主要需求是固定国家出口的全局 IP 隐藏，且几乎不需要高频访问对延迟敏感的中国内地本地服务。
- **选择规则代理订阅服务的 4 个充分理由**：第一，你日常处于**跨境复杂网络环境且同时高频使用国内外服务**，必须依赖精细的域名与 GeoIP 分流（国内直连不减速、跨境按需分流）；第二，你需要使用 **Linux 命令行、OpenWrt 家庭软路由透明代理或自定义覆写脚本**，追求开源客户端的完全可控性与排障透明度；第三，你对**晚高峰跨境连通稳定性与低延迟**有较高要求，而标准 WireGuard/OpenVPN 直连在你的本地宽带环境下频繁受限；第四，你希望通过**灵活月付（¥15–¥25/月）或小额流量包**控制试错成本，并建立多品牌异构备用机制，而不愿一次性预付数百美元长约。

一句话总结取舍逻辑：**要全局合规隐私审计与公网热点防护，选经审计的商业 VPN；要国内外精细分流、开源高度可控与复杂跨境连通率，选规则代理；要外服低抖动联机与 FullCone NAT，单独配一台合规游戏加速器**。

## 十六、VPN 与加速器常见问题

### 传统海外商业 VPN、代理订阅机场和游戏加速器，底层原理有什么不同？

传统商业 VPN 多基于 WireGuard、OpenVPN 或 IKEv2 在操作系统网卡层建立全局加密隧道；代理机场基于 VLESS、Trojan、Shadowsocks 或 Hysteria 2 等传输/应用层协议，核心优势是按域名与 IP 精细分流；游戏加速器则专注白名单游戏进程的 UDP 转发优化、丢包补偿与 NAT 穿透改善。

### 用游戏加速器能访问普通海外网页或 ChatGPT 吗？

不能。正规合规游戏加速器仅对白名单游戏进程与指定游戏服务器 IP 段进行路由调度，不会代理浏览器常规网页流量或 AI 服务；反之，未开放完整 UDP 转发或 NAT 呈 Symmetric 状态的普通代理机场，在联机游戏里也容易触发语音断续与匹配失败。

### 所谓“永久免费不限流量 VPN”靠什么盈利，存在哪些安全隐患？

带宽、机房与 IP 运维均存在刚性成本，缺乏付费订阅收入的免费 VPN 通常依赖五类变现模式：将用户设备转化为住宅出口代理节点、采集并出售 DNS 与访问画像、注入网页广告与劫持流量、采用弱加密或明文采集凭证，以及借免费限速诱饵转化高价年付。此类工具还高发 DNS 泄漏、IPv6 旁路泄漏与 WebRTC 真实 IP 暴露。

### 为什么手机 VPN 锁屏几分钟后经常自动断连或收不到消息？

Android 与 iOS 均在系统层施加了严格限制：Android 国产定制 ROM 会在锁屏后冻结后台进程并回收 `VpnService` 隧道，需关闭电池优化并开启后台自启与任务加锁；iOS 的 `NetworkExtension` 扩展则受约 50MB 内存硬上限约束，一旦加载过大的规则集或高频并发连接就会触发 OOM 强制终止。

### 为什么不能在 Android 或 Windows 上同时开启两款 VPN 或游戏加速器？

操作系统在网络层对虚拟隧道存在排他性或路由竞争：Android 的 `VpnService` 同一时刻仅允许单个应用持有活跃槽位，启动第二个会直接顶掉前者；Windows 与 macOS 同时运行两套虚拟网卡（TUN 驱动、WireGuard 网卡或加速器驱动）则会引发默认路由表打架、DNS 环路与全局断网。

### Android 端的分应用代理（Split Tunneling）和规则分流有什么区别？

分应用代理基于 Android `VpnService` 的应用 UID 黑白名单，直接决定某个 App 的全部流量是否进入隧道，最适合将国内网银、微信或本地政务 App 彻底排除在隧道之外；规则分流则在代理内核内部按域名与 GeoIP 判断流量去向，两者结合可兼顾兼容性与访问速度。

### iOS 端获取手机 VPN 或代理客户端为什么会遇到区服与付费限制？

iOS 端几乎所有合规工具均需通过 App Store 分发，而不同国家或地区商店的上架清单与定价差异极大（例如 Shadowrocket、Stash、Quantumult X、Surge 均为海外区服付费或内购应用）。用户必须使用本人可控账号在对应支持区服获取，切勿使用来路不明的共享 Apple ID 登录系统 iCloud，以免遭遇远程锁机与隐私泄露。

### Windows VPN 内置客户端、商业 VPN 软件和代理客户端的 TUN 模式该怎么选？

企业内网接入若已下发标准 IKEv2 或 WireGuard 配置文件，可直接使用系统内置或官方开源客户端；海外商业 VPN 适合固定合规网络环境与整体加密需求；而需要国内外精细分流、同时兼容终端命令行与 UWP 应用时，使用 Clash Verge Rev 或 sing-box 开启 TUN 模式往往更灵活。

### 联机游戏测速里的 FullCone、RestrictedCone 和 Symmetric NAT 代表什么？

这三种类型反映路由器或代理出口对外部 UDP 主动回包的放行严格度。FullCone（NAT1）放行最宽松，P2P 联机匹配池最广且组队语音最稳；RestrictedCone（NAT2/3）允许已通信主机的回包；Symmetric（NAT4）会为每个目标分配独立映射端口，极易导致联机匹配超时、无法加入好友房间或语音掉线。

### 商业 VPN 宣传的“严格无日志（No-Logs）”声明该如何核验真伪？

口头宣称无日志不具备证明力，可信评估应核查四项客观依据：是否发布过独立第三方安全机构审计报告、服务器是否采用 RAM-Only 内存无盘架构、企业注册地司法管辖与透明披露报告是否公开，以及客户端是否开源可供社区审查。无公开审计背书的宣传一律按商家自称看待。

### 在跨境复杂网络环境下，WireGuard、OpenVPN 为什么经常不如 VLESS 或 Trojan 稳定？

WireGuard 与 OpenVPN 的设计初衷是通用加密组网而非对抗复杂链路干扰，其握手包结构与固定端口特征十分清晰，在跨境链路拥塞或严格 QoS 限速环境下容易出现握手超时或速率断崖下降；而 VLESS、Trojan 等协议多配合国内 BGP 中转或 TLS 伪装传输，在复杂跨境路由中连通率更具优势。

### 商业 VPN、代理机场和游戏加速器，个人用户到底应该如何组合选购？

核心原则是按刚需拆解而非一刀切：访问企业内网或要求合规安全审计时使用单位指定的商业或自建 VPN；日常跨境学术、开源开发与多设备国内外精细分流优先选择规则代理方案；专注 PC 或主机外服联机降丢包则单独购买支持按时暂停的合规游戏加速器，并牢记切换前彻底退出上一款虚拟网卡工具。
