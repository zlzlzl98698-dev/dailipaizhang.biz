# 手机 VPN 为什么会自动断开：Android VpnService 杀后台与 iOS NetworkExtension 内存限制

## 核心结论（Answer-First）

**手机 VPN 熄屏自动断开，九成源于系统对后台资源的硬限制而非节点故障。** Android 端主因是厂商定制省电机制强杀持有 `VpnService` 的后台进程；iOS 端主因则是 `NetworkExtension` 独立内存上限极窄，巨型规则库或 MitM 解密极易触发 OOM 秒杀隧道。此外，Wi-Fi 与 5G 切换造成的死链也会诱发假断连。

## 一、快速区分「系统杀隧道」「网络切换死链」还是「远端节点断流」

动手调设置之前，先花 30 秒观察手机状态栏和客户端日志，把三类截然不同的断连现象分清楚：

| 故障表现 | 状态栏 VPN 图标变化 | 切换回国内 App 表现 | 真实根因归属 |
| :--- | :--- | :--- | :--- |
| **现象 A：锁屏几分钟后彻底断连** | VPN 图标直接消失 | 国内 App 恢复直连可正常打开 | **操作系统杀后台或扩展 OOM 崩溃**（Android 省电策略 / iOS 内存超限） |
| **现象 B：出门 Wi-Fi 切 5G 后卡死** | VPN 图标仍在，但所有网页转圈 | 国内外 App 可能同时转圈或极慢 | **底层网卡切换导致长连接半开假死**，或 DNS 缓存未随新网络刷新 |
| **现象 C：玩游戏或刷视频中途断流** | VPN 图标稳稳挂着，重切节点立刻恢复 | 国内直连 App 完全正常 | **远端代理节点本身超时、晚高峰丢包或协议被 QoS**（详见 [晚高峰高延迟与丢包排查](/troubleshooting/articles/high-latency-packet-loss-peak)） |
| **现象 D：打开特定软件瞬间挤掉 VPN** | VPN 图标瞬间闪灭或换成一个新图标 | 另一个安全/办公 App 接管了通道 | **移动端单 VPN 槽位被其他软件抢占**（如企业 VPN、本地去广告工具，参见 [VPN 与代理能否同时运行](/vpn/articles/vpn-and-proxy-coexistence)） |

关于移动端整体网络优化策略与省电平衡，也可延伸参考二级专题 [手机 VPN 与移动端优化指南](/vpn/mobile/) 以及 [Android VPN 专项适配](/vpn/android/)。

## 二、Android 端深度剖析：为什么 `VpnService` 总是被后台悄悄干掉

Android 原生系统（AOSP）从 Android 6.0 引入 Doze（打盹模式）与 App Standby（应用待机），到了国产深度定制 ROM（如 HyperOS / MIUI、ColorOS、OriginOS、MagicOS、HarmonyOS）中，为了追求续航跑分，系统内置了多层后台查杀引擎（俗称“墓碑机制”与“神隐模式”）。

当你把 FlClash、Clash Meta for Android、v2rayNG、Hiddify 或 Karing 切到后台并息屏后，如果该应用没有获得系统级白名单豁免，通常会依次经历三个阶段：
1. **网络冻结阶段**：息屏 3–5 分钟后，系统限制后台应用的网络套接字活动，代理核心与远端节点的心跳保活包发不出去，连接进入假死。
2. **进程冷冻/回收阶段**：当你打开拍照、大型游戏或电商 App 占用大量内存时，系统的 LMKD（低内存查杀守护进程）会把处于后台的代理 App 判定为普通高耗电/高内存后台进程直接清退。
3. **`VpnService` 隧道回收**：一旦宿主 App 进程死亡，内核立即销毁对应的 `tun0` 虚拟网卡，状态栏 VPN 图标瞬间消失。

### Android 端五步保活实操（零 Root 通用方案）

下面五项设置需要 **组合生效**，只做其中一步往往治标不治本（更细化的分机型保活说明也可对照阅读 [Android 端 v2rayNG 与 Clash 断连保活排查](/troubleshooting/articles/android-v2rayng-clash-disconnect)）：

1. **解除系统电池优化（核心）**：进入手机「设置 → 应用管理 → 找到代理客户端 → 耗电管理 / 电池」，将策略明确改为 **「无限制」**（切忌留在“智能限制”或“省电优化”），并同步打开「允许后台高耗电」「允许完全后台行为」。
2. **开启允许自启动与关联启动**：在应用权限中打开「自启动」，确保系统在极端低内存重启核心后能自动拉起隧道，而不是彻底静默退出。
3. **多任务卡片手动加锁**：上滑打开最近任务列表，下拉或点击代理 App 卡片右上角菜单选择 **「锁定」**，避免点击“一键清理后台”时顺手把代理核心误杀。
4. **保留前台常驻通知栏**：Android 系统判断一个后台服务是否属于「用户正在使用的前台服务（Foreground Service）」，直接依赖它是否在通知栏展示了常驻通知。切勿为了图清净在系统设置里彻底关掉代理客户端的通知权限，否则系统会大幅降低其进程优先级，秒杀概率暴增。
5. **在系统 VPN 设置中谨慎配置「始终开启的 VPN」**：前往「设置 → 网络和互联网 / 更多连接 → VPN → 点击代理客户端右侧齿轮」，开启 **「始终开启的 VPN」**。但请注意：**除非你确定节点 100% 稳定且无需连校园网认证，否则不要顺手勾选「阻止不使用 VPN 的连接」**，不然一旦代理进程崩溃或节点失效，整部手机会彻底断网连国内救急通信都发不出去。

## 三、iOS / iPadOS 端深度剖析：`NetworkExtension` 内存红线与 OOM 闪断

很多从 Android 换到 iPhone 的用户困惑：iOS 根本没有“国产杀后台”，为什么用 Shadowrocket（小火箭）、Stash、Quantumult X（圈 X）、Surge 或 sing-box 官方版（SFI）时，看视频或切 App 同样会遇到隧道突然断开重启，甚至整个配置加载不起来？

答案藏在苹果严格的多进程沙盒架构里。iOS 的代理软件分为两个完全独立的进程：
- **主 App 进程（UI 界面）**：你点开软件选节点、看测速时运行的是它，系统给它的内存空间非常宽裕（几百 MB 甚至超过 1 GB）。
- **网络扩展进程（`NEPacketTunnelProvider`）**：真正维持虚拟网卡、加载分流规则、解析 DNS 和加解密流量的是这个隐藏在后台的系统扩展。为了防止网络扩展拖垮整机内存，苹果对 `NEPacketTunnelProvider` 设定了 **极其苛刻的硬性内存上限**（早期仅 15MB，近年新版 iOS 放宽至约 50MB 左右，但依然远低于主 App）。

只要这个网络扩展进程的常驻内存（RSS）在瞬间突破红线，iOS 的 Jetsam 内存监控机制就会 **零警告直接发送 SIGKILL 强杀扩展进程（OOM Crash）**。用户看到的现象就是：VPN 图标闪一下消失、几秒后尝试重连，或者彻底断网。

### 触发 iOS 扩展进程爆内存（OOM）的五大元凶

| 高危诱因 | 为什么会瞬间撑爆 50MB 内存红线 | 优化瘦身方法 |
| :--- | :--- | :--- |
| **1. 巨型分流规则与广告清单** | 加载包含 10 万–30 万条域名的完整去广告/全量分流文本，规则树常驻内存直接吃掉 30MB+ | 精简规则集，改用主流轻量化精简规则，或使用二进制编译格式（如 `.mrs` / `.srs` 替代纯文本大清单） |
| **2. 全量 GeoIP / GeoSite 数据库** | 导入包含全球全部国家细粒度记录的超大数据库，加载与索引瞬间拉高内存峰值 | 优先选用精简版国内 GeoIP（仅含 CN 段）与按需规则集，避免多套重叠规则同时启用 |
| **3. 开启 HTTPS 解密（MitM）与大量重写脚本** | 对大量主机名开启 TLS 中间人解密与 JS 脚本注入，并发缓冲区和证书缓存急剧膨胀 | 日常仅做分流上网时关闭 MitM 与非必要去广告脚本，仅保留确需使用的极简条目 |
| **4. 节点并发测速与多路下载同时爆发** | 几十上百条并发连接叠加测速缓冲区，瞬间把活跃连接表推过内存临界点 | 避免在高速下载或刷 4K 流媒体时点击全节点并发测速；减少单份订阅中冗余的数百个无效节点 |
| **5. 长期开启全量请求体日志记录** | 开启详细抓包与请求历史落盘缓存，在持续重度使用后内存缓慢泄漏直至触顶 | 排障完成后立即关闭详细抓包和请求体录制，仅保留基础连接摘要 |

### iOS 端「按需连接（Connect On Demand）」的正确用法

在 Shadowrocket、Stash、Quantumult X 或 Surge 的设置中，通常都内置了 **「按需连接（On Demand）」** 选项。它的底层原理是把触发规则登记进 iOS 系统级配置，当扩展进程因 OOM 崩溃或网络从蜂窝切回 Wi-Fi 导致隧道断开时，系统一旦检测到新的出站请求就会自动重新拉起隧道。

开启建议与避坑：
- 日常建议开启「按需连接」，并配置好 **Wi-Fi 白名单豁免**（例如家里的软路由已经透明代理，把家庭 Wi-Fi SSID 填入豁免列表，回家自动停用手机代理，出门切 5G 自动无感连上）。
- 切忌在刚遇到「配置本身一启就 OOM 崩溃」的情况下硬开按需连接，否则系统会陷入「启动 → 2 秒爆内存崩溃 → 再次拉起 → 手机发烫掉电」的恶性循环。先精简规则确保隧道稳态运行，再开启按需连接。关于小火箭规则导入与精简步骤，可参见 [Shadowrocket 规则导入指南](/troubleshooting/articles/shadowrocket-import-rules)。

## 四、跨平台通用诱因：Wi-Fi / 5G 切换假死与协议保活排查

排除了系统杀后台和内存爆仓后，如果手机在「进电梯信号弱」「走出家门 Wi-Fi 切 5G」或「长待机唤醒」时依然频繁掉线，应重点排查以下三项网络与客户端细节：

1. **协议对弱网与网络切换的耐受度差异**：传统长连接 TCP 协议在移动网络基站切换或 NAT 映射表过期时，需要等待长达数十秒的 TCP 超时才能察觉断链；而具备连接迁移特性的现代协议（或在客户端开启较短间隔的 TCP Keep-Alive / UDP 空闲超时回收）能更快感知旧链路失效并重连。
2. **客户端「网络变更自动重置连接」选项**：部分移动端客户端支持监听系统网络接口切换，在检测到 Wi-Fi 与蜂窝网切换时主动掐断旧连接并刷新本地 DNS 缓存。如果遇到“图标还在但刷不出网页”，在客户端里手动开关一次隧道即可验证是否属于接口切换遗留的死链。
3. **安全下载与伪冒客户端风险提醒**：手机端遇到频繁异常闪退，也要确认客户端来源是否正规。根据站内 [客户端资料审计](/clients/) 的安全警示：Android 端的 `NekoBox for Android` 官方已明确警告 **不要使用其名称下已被第三方控制的 Google Play 版本**，且 `v2rayNG`、`FlClash`、`Clash Meta for Android` 等开源工具均应核验作者发布页来源（站内统一标为项目地址待核实，请以作者发布页为准）；iOS 端的 `Shadowrocket`、`Stash`、`Quantumult X`、`Surge` 属于海外 App Store 付费应用，切勿使用来路不明的共享 Apple ID 登录系统 iCloud，以免触发锁机风险。

## 五、常见问题

### 为什么安卓手机一锁屏过几分钟，状态栏里的 VPN 图标就自己消失断网了？

绝大多数情况不是节点坏了，而是国产定制 Android 系统（如 MIUI/HyperOS、ColorOS、OriginOS、HarmonyOS）的激进省电策略在锁屏后冻结甚至强杀了后台进程。一旦承载 VpnService 的代理 App 被清理，系统就会同步销毁虚拟网卡接口，表现为 VPN 图标突然消失且海外应用断连。

### 为什么 iPhone 用 Shadowrocket、Stash 或 Quantumult X 时，明明后台还在却突然断连或重启隧道？

这通常触发了 iOS NetworkExtension（NEPacketTunnelProvider）极其严格的独立内存上限（iOS 现代版本中常在 50MB 左右，早期更紧）。当配置文件加载了过于庞大的 GeoIP/GeoSite 规则库、数十万条去广告域名、或同时开启 MitM 解密与高并发下载时，扩展进程内存瞬间越界就会被系统直接 OOM 杀掉。

### Wi-Fi 和 5G 蜂窝网络来回切换时，为什么手机 VPN 经常“图标还在但完全没网”？

当手机走出家门从 Wi-Fi 切到 5G 时，底层物理网卡的本地 IP 地址发生变化，原先建立在旧网络接口上的 TCP/UDP 长连接实际已变为半开死链。若客户端未及时监听网络变更事件重建底层套接字，或开启了仅按旧 IP 绑定的连接复用，就会出现状态栏仍挂着 VPN 图标却刷不出任何内容的“假连接”状态。

### 在安卓手机上把代理软件设为“始终开启的 VPN”，就能彻底防止杀后台吗？

不能单靠这一个开关。系统「始终开启的 VPN（Always-on VPN）」能在进程被杀死后尝试重新拉起隧道，但如果未同步关闭该 App 的电池优化、未允许后台高耗电与自启动，系统仍会反复杀进程再重启，导致网络每隔几分钟卡顿断流一次。必须把电池无限制、后台锁定与系统常驻通知一起配齐。

### 在 iOS 上怎么精简配置，才能显著减少 NetworkExtension 内存爆仓断连？

重点做四项减法：第一，删除重复或动辄数十万行的巨型广告拦截与域名清单，改用轻量化规则集；第二，非必要时关闭全局 MitM（HTTPS 解密）与复杂重写脚本；第三，限制订阅中冗余的过期节点与超高并发测速；第四，关闭长期开启的全量流量抓包日志记录，降低内存峰值。
